# CL-908: Add a host-neutral preview skeleton for PRs

## Goal

A project gets a preview deploy for each PR, and deletes it when the PR closes, from one host-neutral skeleton that kickoff fills in.

## Context

From CL-605. Neighborhood's `ci.yml` has a `preview` job after `validate`, and `preview-cleanup.yml` runs on close. Both call `tools/preview.ts deploy|delete pr-<n>`, which is Cloudflare-specific, with its own database and storage prefix for each PR. Clutch has only `docs/contributing/setup/previews.md`, with kickoff slots.

## Steps

1. Add a `preview` job and a `preview-cleanup.yml` that call `bun tools/preview.ts deploy|delete pr-<n>`, behind a kickoff slot for the host.
2. Ship `tools/preview.ts` as a stub that refuses any name outside `pr-<n>`: the name guard from `previews.md`.

## Acceptance criteria

- A project that fills the slot gets a preview URL comment on each PR, and the preview is gone after close.
