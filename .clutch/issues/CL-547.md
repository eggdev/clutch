# CL-547: Keep the count of the contract check, and name a check that wrote no findings

## Goal

The contract check prints the count that it printed before CL-534, and `validate --json` shows a check that stopped before the end.

## Context

CL-534 merged when its checks passed, before its review ended. The review found three problems, and none of them loses a rule.

- The contract check counted one finding of several lines as one. Its first line said `Contract check failed (1).` where it said `(3)` before.
- A check that stopped before the end wrote no findings file, so `validate --json` showed nothing for it. Only the exit code told a reader that a check failed.
- A findings file that did not parse stopped `validate --json` with a stack trace and no document.

## Steps

1. Branch `clutch/cl-547-findings-follow-up`.
2. Count the lines of the problems in the contract check, and pin the count in a test.
3. Add `missing` to the document of `validate --json`. It names each check of `findingChecks` in `tools/findings.ts` that wrote no file, or a file that does not parse.
4. Add a test that holds `findingChecks` to the checks that write findings.
5. Describe `missing` in `docs/contributing/setup/checks.md`.

## Files

- `tools/check-contract.ts`, `tools/findings.ts`, `tools/validate.ts` and their tests
- `docs/contributing/setup/checks.md`

## Acceptance criteria

- One unnamed one-way change prints `Contract check failed (3).`
- `validate --json` names a check that wrote no findings under `missing`.
- A findings file that does not parse does not stop `validate --json`.

```sh
mise exec -- bun run validate
```
