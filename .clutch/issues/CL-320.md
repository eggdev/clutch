# CL-320: Add the Planning and Design phases

## Goal

A ticket that needs the owner's judgment gets a planning conversation, and a ticket that changes what a user sees gets a prototype that the owner approves before the build starts.

## Context

After CL-319, Triage holds each ticket that needs Planning or Design. This issue adds both phases and removes that hold.

### Planning

- Planning runs in its own thread, with `thread: own`, in the main checkout. It changes no code.
- It uses the `grilling` skill: one question at a time, each with a recommended answer. It asks only about the requirements that Triage left empty.
- The skill is in the owner's skills repository and is not installed on the machine. Install it with `equip`. `tickets phases --check` (CL-318) fails until it is installed.
- It writes the answers with `tickets edit`. It can add or remove `design` on the route.
- `advance: owner`. The phase is done when the 4 requirements are set and the owner confirms.

### Design

- Design is the first phase in the work thread when it is on the route.
- It uses the `emil-prototype` skill: 2 or 3 directions behind a live picker, on the real components of the project.
- It works alone. It enters `in_review` when the directions are ready. The status prompt asks the owner to pick one direction or to give feedback.
- `advance: owner`. On approval, the agent:
  1. removes the directions that the owner did not pick,
  2. commits the approved prototype on the ticket branch,
  3. saves screenshots at 390 and 1024 pixels wide to `~/.local/state/clutch/<project>/tickets/<id>/prototype/`,
  4. links the commit and the folder with `tickets link --kind prototype`.
- The approved prototype is the finish line of the ticket. Build then makes it real in the same worktree.

## Steps

1. Branch `clutch/cl-320-planning-design`.
2. Install the `grilling` skill and record how in the setup docs.
3. Write the `planning` and `design` entries of the default `.clutch/phases.yaml`, with the prompts for the phase and for `in_review` and `blocked`.
4. Remove the hold from the Triage prompt.
5. Hand test: one ticket that needs both phases.

## Files

- `.clutch/phases.yaml`
- `docs/contributing/setup/` (the page that lists the skills to install)

## Acceptance criteria

- A vague ticket starts a Planning thread whose first message is one question with a recommendation.
- `tickets phase <id> planning done` exits 1 while a requirement is empty.
- A ticket with `design` on its route starts no Build before the owner approves.
- After approval, the ticket has a `prototype` link, and the folder holds a screenshot at each of the 2 widths.

## Verify

- `mise exec -- bun run clutch tickets phases --check`
- `mise exec -- bun run validate`
- The hand test in step 5.
