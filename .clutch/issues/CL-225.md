# CL-225: Create the revert label in every project

## Goal

Every project has the `revert` label, so the manual revert lever and auto-revert
both work from the first merge.

## Context

A revert drill in Neighborhood (PR #48) failed at the first step:
`gh pr edit 48 --add-label revert` said `'revert' not found`. Clutch has the
label only because someone created it by hand. Nothing in the template creates
it. `tools/github/auto-revert.ts` adds it with the same command, so auto-revert
fails in every project too. The revert, tighten and auto-revert links point to
`rollback.md` anchors that a project's copy of the doc may not have.

## Steps

1. Create `revert` in the Labels workflow's label set, next to `one-way-door`
   in `apps/cli/src/labels/compute.ts`.
2. Run `gh label create revert --force` in `tools/github/auto-revert.ts` before
   the add, as `revert.ts` does for `risk-tighten`.
3. Link the revert docs by URL to Clutch's `rollback.md`, so they resolve in any
   project.

## Files

- `apps/cli/src/labels/compute.ts` and its test
- `tools/github/auto-revert.ts` and its test
- `tools/github/revert.ts` (the tighten issue text)
- `.github/workflows/revert.yml` and `auto-revert.yml` (header comments only)

## Acceptance criteria

- `clutch labels` defines `revert` with a description and a color.
- Auto-revert runs `gh label create revert --force` before it adds the label.
- No link in the revert code or workflows points at a `rollback.md` anchor of
  the project's own copy.
- No workflow permission, trigger, environment or secret line changes.

## Verify

- `mise exec -- bun test apps/cli/src/labels tools/github`
- `mise exec -- bun run clutch risk` reports `low` or `medium`.
- `mise exec -- bun run validate`
