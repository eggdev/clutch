# CL-007: Define the clutch.yaml schema and loader

## Goal

Each repository declares its Clutch adoption in one root file, `clutch.yaml`. Each capability is `adopted`, `waived` with a reason, or `n/a` with a reason. The file pins the template commit.

## Schema (schemaVersion 1)

```yaml
schemaVersion: 1
project: clutch # short name, used in doctor output
template:
  repo: eggdev/clutch # source of truth (eggdev/project-template until CL-006)
  commit: 384c9c39f729f9a5630eccea5806bb3b641348bf # pin; clutch sync moves it
  mode: sync # sync: clutch sync manages files; doctor: checks only (Bar Savvy)
capabilities: # key = registry id
  root_agents_md: adopted # short form
  codeql_sast:
    status: waived # adopted | waived | n/a
    reason: Lands in CL-102. # required for waived and n/a
    issue: CL-102 # optional; when the issue is done, the waiver expires
    until: 2027-01-31 # optional; an expired date fails doctor --check
worktree: # used by clutch worktree (P2)
  root: ../clutch.worktrees
  copy: [.env.local]
  setup: ['mise exec -- bun install']
```

## Steps

1. Branch `clutch/cl-007-clutch-yaml`.
2. Add `apps/cli/src/clutch-config/schema.ts`. Use a hand-written validator (no new dependency). It returns typed config plus errors with a YAML path. Reject unknown top-level keys. Require `reason` for `waived` and `n/a`. Check that `issue` matches `CL-\d{3}`, `until` is ISO, and `template.commit` is 40 hex characters.
3. Add `apps/cli/src/clutch-config/load.ts`: `loadClutchConfig(root)` reads `clutch.yaml` with the `yaml` package. A missing file gives a typed "not adopted" result, not a throw.
4. Add root `clutch.yaml` for the template itself. Pin `template.repo` to its own repo and `template.commit` to the merge base. Set `mode: sync` and leave `capabilities: {}`. CL-011 fills it.
5. Add `clutch.yaml` to `tools/guardrail-files.json` `patterns` and to `.github/CODEOWNERS` as `/clutch.yaml @eggdev`. `check-agent-hooks` keeps the two in step.
6. Tests: a valid file, each error kind, the short form and the long form.
7. Document the schema in `apps/cli/README.md` under "clutch.yaml".

## Files

- add `apps/cli/src/clutch-config/{schema,load}.ts` plus tests, `clutch.yaml`
- edit `tools/guardrail-files.json`, `.github/CODEOWNERS`, `apps/cli/README.md`

## Acceptance criteria

- `loadClutchConfig` returns typed config for the committed `clutch.yaml`.
- Each invalid case names the YAML path in its error.
- `check-guardrail-coverage` and `check-agent-hooks` pass.
