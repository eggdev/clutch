# CL-465: Fail a draft journey and a journey that asserts nothing

## Goal

A journey proves something, or the check says that it does not. A draft journey and a journey with no assertion do not count as proof.

## Context

- The feature generator writes a journey with `State: draft`, which proves only that the screen renders. `tools/check-journeys.ts` reads `Contract`, `Entry` and `Isolation and cleanup`, and it never reads `State`. So the draft passes the check for good.
- `journey()` in `packages/journeys/testing/journey.ts` takes any step list. The Maestro compiler refuses a flow with no `see`, `gone` or `outcome` step, and the web run does not.
- `assert-behavior` in `tools/lint/test-policy.mjs` counts a call of any helper named `expect…` or `assert…` as an assertion, also when the helper asserts nothing.

## Steps

1. Branch `clutch/cl-465-journeys-prove`.
2. Write the failing tests first, in `tools/check-journeys.test.ts` and in the tests of the journeys package.
3. In `check-journeys`, a journey with `State: draft` does not count as the journey of a feature that an app ships.
4. Hold one rule for both platforms: a journey with no `see`, `gone`, `outcome` or `serverHolds` step is refused where it is declared.
5. In `assert-behavior`, count a helper only when the test file or a `testing/` module defines it with an `expect` inside.
6. Say in the generator's journey template what the developer must replace before the feature merges.

## Files

- `tools/check-journeys.ts`, `packages/journeys/testing/journey.ts`, `tools/journeys/maestro.ts`
- `tools/lint/test-policy.mjs`
- `tools/generators/feature/files/journeys/`, `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- A feature with a screen and only a draft journey fails `check-journeys`, with a sentence that names the fix.
- A journey with no assertion step fails on the web and on a device with the same sentence.
- A test whose only assertion is an empty helper fails the lint.

## Verify

- `mise exec -- bun test tools/check-journeys.test.ts tools/journeys tools/lint packages/journeys`
- `mise exec -- bun run validate`
