# CL-596: Run the native journeys in local CI on a pool device

## Goal

The local CI service runs the native journeys of a pull request that reaches native, on one device of the shared pool, with no T3 Code tools.

## Context

The owner asked for this on 2026-11-21, after CL-497 removed the GitHub Actions native jobs. A CI job has no `device_open`, so it takes its own lease from Simlock, the pool's leasing daemon. The pool's address and its token are settings of the machine, as the build machine is. The same `AGENT_DEVICE` contract serves both callers. CI must not starve agents: the pool runs 3 devices.

## Steps

1. Read `simlock instructions` and the Simlock docs. Write the lease calls from them.
2. Add a `native` job that local CI runs. It leases one device, puts the bound command in `AGENT_DEVICE`, runs `native:build --install` and `journey --native ios`, and always ends the lease.
3. Run it only when `tools/journeys/reach.ts` says that the change reaches native.
4. Limit CI to 1 device at a time.

## Files

- `.github/workflows/ci.yml`
- `tools/native/`
- `apps/local-ci/README.md`
- `docs/contributing/setup/native.md`

## Acceptance criteria

- C1: A pull request that reaches native gets a `native` status from local CI, from a run on a pool device.
- C2: A pull request that does not reach native starts no lease.
- C3: A job that fails or is cancelled ends its lease.
- C4: Two native jobs never hold two devices at once.

## Verify

Read the `native` status and its log on a pull request that changes `apps/app`.
