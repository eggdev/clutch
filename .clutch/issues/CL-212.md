# CL-212: Make the hard core hold without trusting the agent

## Goal

The main ruleset gives no repository role a bypass, so an agent that runs with the owner's admin login cannot merge a one-way-door PR past the code owner's approval. The agent review workflow reads the base branch's `CLAUDE.md`, `AGENTS.md` and `.claude/`, so a PR cannot change the instructions or hooks of its own reviewer. The review rules page stays read from the PR checkout. See Notes.

## Context

- `.github/rulesets/main.json` gave the `RepositoryRole` actor 5 (the repository admin) a `pull_request` bypass. Agents run with the owner's admin credentials, so only the client-side refusal in `pr merge` stopped them. Agent PRs are opened by the release bot, so the owner can approve them as code owner without the bypass.
- `.github/workflows/agent-review.yml` checks out the PR head and runs Claude Code there. Claude Code loads the checkout's `CLAUDE.md` and `AGENTS.md`, which are `medium` risk, so a PR could change the instructions of its own reviewer.

## Steps

1. Remove the `RepositoryRole` bypass from `.github/rulesets/main.json`. Keep the `Integration` (release bot) bypass. Update the test that asserts the bypass list, and add one that fails if a repository role gets a bypass.
2. In `agent-review.yml`, sparse-check out `CLAUDE.md` and `AGENTS.md` from the base commit with `clutch.yaml`. After the PR-head checkout, copy each base file over the PR's copy, or delete it when the base has none.
3. Update the docs that describe the admin bypass: the capability page for the protected default branch, the approval and merge sections of the PR reference, the release bot section, and the escape hatch table. Note in `review.md` that agent review runs with the base branch's instructions.
4. Ship the change as a one-way-door PR. The owner approves it on GitHub, then runs `clutch ruleset --apply` so GitHub matches the file.

## Acceptance criteria

- `.github/rulesets/main.json` lists only the `Integration` bypass. A test fails when a repository role appears in it.
- `agent-review.yml` sparse-checks out `CLAUDE.md` and `AGENTS.md` from the base, and a step named "Use the base branch's agent instructions" replaces or removes each file in the PR checkout before the review runs. Its permissions, environment, secrets and triggers are unchanged.
- The docs no longer say that the admin role bypasses the ruleset, and say that the owner approves a one-way-door PR on GitHub.
- `mise exec -- bun run validate` passes.
