# CL-208: Route a weakened check to the owner

## Goal

Check scripts, lint config and workflows auto-merge like product code (CL-209).
So the guard against a weaker check moves from paths to agent review: a change
that weakens a check, a lint rule, a budget or a test goes to Brendan.

## Context

Agent review had two levels. A `blocking` finding fails the required check,
so even the owner cannot merge until the author changes the PR. A weaker check
needs a third outcome: the owner decides.

## Steps

1. Add the `owner` level to `docs/contributing/review.md`. A weaker check,
   lint rule, budget or test is `owner`, whatever the path.
2. Agent review returns each `owner` finding. The job passes and writes an
   "Owner review needed" annotation on its own run.
3. Auto-merge reads those annotations on the head and leaves the PR for the
   owner. An agent cannot remove an annotation, as it could a label.

## Files

- `docs/contributing/review.md`, `.github/workflows/agent-review.yml`
- `tools/github/auto-merge.ts`, `auto-merge-rules.ts` and the test
- `.agents/skills/deliver/references/pull-requests.md`

## Acceptance criteria

- An `owner` finding blocks auto-merge at every step, on a PR that is
  otherwise green.
- Agent review passes with an owner finding, so the owner can merge.

## Verify

`mise exec -- bun run validate`. Auto-merge runs the default branch's code,
so the first live owner finding takes effect after merge.
