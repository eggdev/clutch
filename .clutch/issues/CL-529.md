# CL-529: Check each written record at the event log, and hold each table to its record

## Goal

No record reaches a client unless it fits the fields that its contract declares.

## Context

A package declares each record once, in its contract. Its database table is private storage, written by hand in `repo/schema.ts`, as Exact writes its own storage by hand. The rule is at the boundary: each record that leaves the server fits its declaration.

Built:

- `eventLog(contracts)` in `packages/sync/service/event-log.ts` checks each change as the log commits it. A model that no contract declares, or a record that does not fit, stops the commit, and the error names the fields. No log exists without the contracts.
- `settle` in `packages/sync/service/settle.ts` ends such a change as `failed`, which is final, so the client drops the write.
- `upsertChange` in `packages/sync/contract/change.ts` makes the same check earlier, where the change is built.

Not doing: a test that compares the columns of a table with the fields of its record. The table is storage, not a second declaration of the wire shape, and the check at the log holds what leaves it.

## Steps

1. Land the check with the contract work.

## Files

- `packages/sync/service/event-log.ts`, `packages/sync/service/settle.ts`
- `packages/sync/contract/change.ts`, `packages/sync/contract/fields.ts`
- `apps/api/src/server.ts`

## Acceptance criteria

- A server change that builds a change by hand with a wrong field fails its commit, and the test names the field. `packages/sync/service/event-log.test.ts` and `packages/sync/runtime/tools.server.test.ts` prove it.
