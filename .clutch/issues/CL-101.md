# CL-101: Add gitleaks secret scanning to hooks and CI, plus SECURITY.md

## Goal

Stop secrets before they reach GitHub, and publish a disclosure policy.

## Steps

1. Branch `clutch/cl-101-gitleaks`.
2. Pin gitleaks in `mise.toml` (`gitleaks = "<latest 8.x>"`). `mise.toml` is a guardrail file.
3. Add `.gitleaks.toml`. Start from Bar Savvy's `.gitleaks.toml` (CL-704 upstreams it) and extend the default rules.
4. Pre-commit: run `gitleaks git --staged --redact --no-banner` from `tools/hooks/` (follow the existing pre-commit structure in `.githooks/pre-commit`).
5. CI: add a `secrets` step to the `validate` job, or a separate job with `permissions: contents: read` that runs `gitleaks git --redact --log-opts="$CHECK_BASE..HEAD"`.
6. Add `SECURITY.md` at the root: how to report, response time, and supported branch. Link it from `docs/contributing/security.md` if that page exists.
7. Set `secret_scanning` (local part) and `security_policy` to adopted in `clutch.yaml` and raise the doctor baseline.

## Acceptance criteria

- Committing a fake AWS key in a scratch branch fails pre-commit, and the CI job fails on it.
- `clutch doctor` shows `secret_scanning` partial (local present, remote probe pending CL-106).

## Verify

```bash
mise exec -- gitleaks version
mise exec -- bun run clutch doctor --category Trust
mise exec -- bun run validate
```
