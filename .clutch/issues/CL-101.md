# CL-101: Add gitleaks secret scanning to hooks and CI, plus SECURITY.md

## Goal

Stop secrets before they reach GitHub, and publish a disclosure policy.

## Context

`.githooks/pre-commit` runs `hooks:pre-commit`. That script is `lint-staged` with the commands that `stagedCommands` returns in `tools/hooks/paths.mjs`. The gitleaks command goes there.

## Steps

1. Branch `clutch/cl-101-gitleaks`.
2. Pin gitleaks in `mise.toml` (`gitleaks = "<latest 8.x>"`). `mise.toml` is a guardrail file.
3. Add `.gitleaks.toml` at the root. It extends gitleaks' default rules (`[extend] useDefault = true`). Add an allowlist entry only for a false positive that a reviewer has approved. Also:
   - add `.gitleaks.toml` to `tools/guardrail-files.json`,
   - add a line for it to `.github/CODEOWNERS`,
   - add a `managed` entry with `capability: secret_scanning` for it in `clutch.files.yaml`.
4. Pre-commit: add `gitleaks git --staged --redact --no-banner` to `stagedCommands` in `tools/hooks/paths.mjs`, with a case in `tools/hooks/hooks.test.ts`. The expected lists in that test change too.
5. CI: add a `secrets` step to the `validate` job in `.github/workflows/ci.yml`, or a separate job with `permissions: contents: read` that runs `gitleaks git --redact --log-opts="$CHECK_BASE..HEAD"`. `CHECK_BASE` is already set in `ci.yml`.
6. Add `SECURITY.md` at the root: how to report, response time, and supported branch. Link it from `docs/contributing/security.md`, which exists. Add `SECURITY.md` to `clutch.files.yaml` as a `seed` entry. Brendan picks the response time and the supported branch. Ask him in the PR.
7. Add a row for the gitleaks pre-commit command to the Git hooks table in `docs/contributing/setup/checks.md`.
8. In `clutch.yaml`, replace the `secret_scanning` waiver with `secret_scanning: { status: waived, reason: 'Local gitleaks adopted in CL-101. Push protection pending the owner in CL-106.', issue: CL-106 }`. Do not adopt it yet. Detection is partial without `--remote`, and an adopted capability that is only partial fails `clutch doctor --check`. Delete the `security_policy` idea: it is not a registry capability.
9. Run `mise exec -- bun run clutch doctor --write-baseline`. The improvement exits 2 until the baseline is written.

## Acceptance criteria

- Committing a fake AWS key in a scratch branch fails pre-commit, and the CI job fails on it.
- `clutch doctor --category Trust` shows `secret_scanning` partial (local present, remote probe pending CL-106).
- `clutch doctor --check` passes.

## Verify

```bash
mise exec -- gitleaks version
mise exec -- bun run clutch doctor --category Trust
mise exec -- bun run clutch doctor --check
mise exec -- bun run validate
```
