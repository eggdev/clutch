# CL-555: The nightly hunt proves the contract claims with a new seed

## Goal

Prove the contract claims with a new seed each night, so the proof meets new inputs.

## Context

`proveClaims` uses the fixed seed 532 and 40 runs. Each PR and each run on `main` tries the same inputs. The owner asked for a property test that meets new inputs. A PR must still fail only for its own change.

## Steps

1. Let `proveClaims` read `CLAIMS_RUNS`, as it reads `CLAIMS_SEED`. Refuse a value that is not a whole number above zero.
2. Add `tools/claims-hunt.ts`. It picks a new seed and runs each proof file with that seed and many runs.
3. Add a `claims` job to `flake-hunt.yml`. A broken claim fails it.
4. Extend the docs of the claims and of the flake hunt.

## Files

- `packages/sync/testing/claims.ts`, `claims.test.ts`
- `tools/contract-claims.ts`, `contract-claims.test.ts`
- `tools/claims-hunt.ts`, `claims-hunt.test.ts`
- `.github/workflows/flake-hunt.yml`
- `docs/contributing/architecture/contract.md`, `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- `CLAIMS_SEED=7 CLAIMS_RUNS=400` runs 400 inputs for each command with seed 7. A test proves it.
- With no variable set, the proof is the same as before.
- A broken claim fails the nightly job. The output names the seed and the line to run it again.
- The blocking runs keep seed 532 and 40 runs.

## Verify

- `mise exec -- bun test packages/sync/testing/claims.test.ts tools/claims-hunt.test.ts tools/contract-claims.test.ts`
- `mise exec -- bun tools/claims-hunt.ts --seed 7 --runs 400`
- `mise exec -- bun run validate`
