# CL-483: Close two accepted gaps in the deterministic checks

## Goal

Each accepted gap has a test and a fix. If the owner keeps a gap, the issue states a written reason.

## Context

- `tools/github/weaker-journeys.ts` compares only the `run:` lines of the CI journeys job.
- So `if: false` or `continue-on-error: true` on that step is not caught.
- `tools/check-scope.ts` skips the `goal:` rule while `KICKOFF.md` exists in the checkout.
- So a pull request that deletes `KICKOFF.md` skips the rule.
- The owner accepted both gaps when he approved the pull requests on 2026-11-12.

## Steps

1. Branch `clutch/cl-483-close-accepted-gaps`.
2. Find out first: whether the owner still wants each gap closed.
3. For the CI step gap, add a test. The test fails on `if: false` and on `continue-on-error: true` in the journeys step. Then fix `tools/github/weaker-journeys.ts`.
4. For the `KICKOFF.md` gap, add a test. The test shows that a pull request that deletes `KICKOFF.md` still runs the `goal:` rule. Then fix `tools/check-scope.ts`. Find out first: how the check sees the deletion.
5. If the owner keeps a gap, write the reason in this issue instead of a fix.

## Files

- `tools/github/weaker-journeys.ts`
- `tools/check-scope.ts`
- `.github/workflows/ci.yml`
- `KICKOFF.md`
- Test files for both tools. Find out first: their names.

## Acceptance criteria

- A journeys step with `if: false` fails the check.
- A journeys step with `continue-on-error: true` fails the check.
- A pull request that deletes `KICKOFF.md` still runs the `goal:` rule.
- Or each kept gap has a written reason in this issue.
