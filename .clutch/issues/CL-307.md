# CL-307: Add nested AGENTS.md files for the CLI, tools and runtime

## Goal

Scoped agent rules near the code, each 20 lines or fewer.

## Context

- `tools/check-file-size.ts` has `fixed: { 'AGENTS.md': 20 }`. It is an exact-path map, so it caps only the root file. A `**/AGENTS.md` cap needs a glob match in the check loop.
- `checkFileSize(root)` checks the fixed files before it reads `tools/file-size-budgets.json`, and `ignoredByGit` returns an empty set outside a repository. So a test can call it on a temporary folder with no budgets file and no Git.
- `tools/check-file-size.test.ts` does not exist yet. The 2 file-size tests are in `tools/docs-checks.test.ts` and use the `inRepo` helper.
- A root `CLAUDE.md` exists. It holds one line, `@AGENTS.md`, and `clutch.files.yaml` ships it as `managed`. The nested `CLAUDE.md` files use the same include.
- `clutch.files.yaml` ships `tools/` as `managed`. So `tools/AGENTS.md` and `tools/CLAUDE.md` go to each project, and their text must be true in a project. `apps/cli/` and `packages/runtime/` do not ship.
- `tools/docs-files.ts` `listDocs` lists only the root `AGENTS.md`. The docs checks (file references, terms, sentences) do not read nested `AGENTS.md` files until `listDocs` lists them.
- `clutch.yaml` waives `nested_agent_rules` until this issue. `.clutch/doctor-baseline.json` records it as `missing`. Doctor detects it with `*/**/AGENTS.md` in git-tracked files, excluding `.agents/**` and `node_modules/**`.
- A repository-wide `Bun.Glob('**/AGENTS.md')` scan takes about 30 ms in this checkout.

## Notes

- Owner decision, default picked (easy to undo): `tools/AGENTS.md` and `tools/CLAUDE.md` ship to projects, because `clutch.files.yaml` manages all of `tools/`. Recommended: ship them. Their text stays project-neutral, and each project then gets `nested_agent_rules` as present. To stop it, add both paths to `exclude` in `clutch.files.yaml`.
- Default picked (easy to undo): a `CLAUDE.md` file with `@AGENTS.md`, not a symlink. It matches the root file and works on Windows checkouts.
- Default picked (easy to undo): the cap covers every git-tracked `AGENTS.md` in the repository, not only the 3 folders. This matches the doctor detection rule.
- A root `CLAUDE.md` already exists, so the earlier separate decision about it is closed.

- Found in implement: `check-structure` allows only listed files at the top of a package, so it rejected `packages/runtime/AGENTS.md` and `packages/runtime/CLAUDE.md`. Once `check-structure` names `CLAUDE.md`, `check-guardrail-coverage` asks for an exempt entry. `check-test-integrity` counts per file, so the moved tests need an allow entry.
