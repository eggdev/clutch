# CL-609: Pass a Neighborhood check in a new worktree and post a verify screenshot

## Goal

Prove layer 02 in Neighborhood: a lane passes its check in a new worktree, and the `verify` agent posts a screenshot on a Neighborhood PR.

## Context

- CL-312 adds `clutch worktree new --runner spark --check`. CL-313 adds the `verify` agent and `clutch verify post`.
- The work happens in `~/dev/neighborhood`, under its `AGENTS.md`. Use a real Neighborhood PR from the week's work. Do not make a PR only for this proof.
- Neighborhood's alpha (Fri 2026-11-06) wins over this issue when they compete for a lane.

## Steps

1. Sync Neighborhood to the release that carries CL-312 and CL-313, by its rules. Add `worktree.check` to its `clutch.yaml` when its check is not the default.
2. Run `clutch worktree new <slug> --runner spark --check` in Neighborhood. Record the time and the result.
3. Run the `verify` agent on a real Neighborhood PR that changes a screen, and let it post the screenshot.

## Acceptance criteria

- A Neighborhood worktree that `clutch worktree new --check` made passes its check.
- One Neighborhood PR has a `clutch-verify` comment with a screenshot that shows on the PR page.
