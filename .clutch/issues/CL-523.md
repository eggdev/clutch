# CL-523: Hold each local database adapter and the object pool to one conformance suite

## Goal

Each adapter of a seam passes one shared suite before the app uses it, and the object pool is held to a small reference model.

## Context

The client page tells a person to run the memory fake's tests against a new local database adapter by hand. Exact admits a host by a shared corpus and names each known deviation in a file with its reason. The pool's rebase is a pure function of the confirmed records and the pending transactions, so a reference reducer with generated traces can check it without a proof.

## Steps

1. Branch `clutch/cl-523-conformance`.
2. Add `packages/sync/testing/local-database-conformance.ts`: one function that runs the same cases against any `LocalDatabase`.
3. Run it against the memory fake in a `bun test`, and against the IndexedDB adapter in a browser test.
4. Add a reference reducer for the pool in `packages/sync/testing/`, and a test that feeds both the same generated runs, deltas and outcomes and compares what each shows.
5. Keep known deviations in one file with a reason for each, and fail on a deviation that the file does not name.

## Files

- `packages/sync/testing/local-database-conformance.ts`, `packages/sync/testing/reference-pool.ts`
- `packages/sync/runtime/pool-conformance.test.ts`
- `docs/contributing/architecture/client.md`

## Acceptance criteria

- The memory fake and the IndexedDB adapter pass the same suite.
- A change that breaks rebase order fails the reference test with the trace that shows it.
- The client page names the suite in place of the manual step.

## Verify

```sh
mise exec -- bun run validate
```
