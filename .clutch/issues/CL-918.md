# CL-918: Deliver live deltas across more than one server process

## Goal

A client gets each live delta, whichever server process committed it.

## Context

`eventLog` in `packages/sync/service/event-log.ts` publishes each delta to a `PubSub` in the memory of its process. `SessionsLive` in `packages/sync/service/sessions.ts` holds the sockets of its process. With two API processes, a client on one gets no live delta of a commit on the other until it connects again, and `Sessions.end` closes only the sockets of its own process. The same holds for a job runner in its own process. A council review on 2026-11-20 found this. Linear's server sends each change to each client that may see it.

The publish also runs after the commit, outside the lock. Behind a shared bus, two commits can arrive out of order, and `onDelta` in `packages/sync/service/feed.ts` then drops the older one.

Trigger: the first project that runs a second API process, or a job runner apart from the API.

## Steps

1. Branch `clutch/cl-918-deliver-across-processes`.
2. State the one-process limit in `docs/contributing/architecture/server.md` until this lands.
3. Wake each process on a commit, for example with Postgres `LISTEN` and `NOTIFY`. Each connection then reads the log after its watermark, so order comes from the log.
4. End the sockets of a user in each process.

## Files

- `packages/sync/service/event-log.ts`, `packages/sync/service/feed.ts`, `packages/sync/service/sessions.ts`
- `docs/contributing/architecture/server.md`

## Acceptance criteria

- A client on one process gets the live delta of a commit on another process.
- Deltas reach a client in sync ID order, with none dropped.
- A sign-out closes the sockets of the user in each process.

## Verify

```sh
mise exec -- bun run validate
```
