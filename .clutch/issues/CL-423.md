# CL-423: Compute labels and the risk tier in one workflow

## Goal

One labels run on each PR event in place of two, with the same labels.

## Context

Each job bills at least one minute in a private repository. On 2026-11-02 and
03, Neighborhood ran Labels (2 jobs) 49 times and Risk (1 job) 50 times on the
same PR events. Both check out the PR and install the dependencies.

## Steps

1. Move the tier into the Labels `compute` job. It still runs the base
   branch's CLI and rules, so a PR cannot lower its own tier.
2. Let the `apply` job set `risk/<tier>` with the other labels, and remove a
   stale `risk/` label.
3. Delete `.github/workflows/risk.yml`. Sync removes it from projects, since
   `.github/workflows/` is managed.

## Files

- `.github/workflows/labels.yml`, `.github/workflows/risk.yml`
- `docs/contributing/review.md`, `docs/contributing/setup/checks.md`
- `apps/cli/README.md`, `apps/cli/src/init-command.ts`

## Acceptance criteria

- A PR gets its `risk/<tier>` label from the Labels workflow, from the base's rules.
- The PR's code still never runs with a write token.

## Verify

- `mise exec -- bun run validate`
- This PR's own labels.
