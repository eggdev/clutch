# CL-496: A workflow that pushes a branch does not install the local push hook

## Goal

The weekly gardening job and the nightly flake hunt can push their branch, also when the branch changes code.

## Context

The gardening job on `main` failed on 2026-11-09 and on 2026-11-16, at the step that opens its pull request. So no gardening pull request came for two weeks.

The cause is the install step. `bun install` runs the root `prepare` script, and that script points Git at the hooks in `.githooks/`. The job then pushes its branch. When the branch changes code, the `pre-push` hook runs the journeys. The job has no browser, so each journey fails and Git refuses the push. A docs-only branch runs only the fast checks, so the run of 2026-11-02 passed.

The `hunt` job of the flake hunt has the same install step and the same push. It fails in the same way when it quarantines a test, because that branch changes a test file.

The other workflows that push a branch install with `--ignore-scripts`: release, security, Clutch sync and revert. The comment in `release.yml` gives the reason. The hook is for a push from a machine of a person or an agent. A branch that a workflow pushes gets the same checks from CI on its pull request.

## Steps

1. Branch `clutch/cl-496-bot-push-no-hook`.
2. In `.github/workflows/gardening.yml`, install with `--ignore-scripts`. Give the reason in a comment.
3. Do the same in the `hunt` job of `.github/workflows/flake-hunt.yml`.
4. After the merge, start the gardening workflow by hand one time. Confirm that the step that opens the pull request passes.

## Files

- `.github/workflows/gardening.yml`
- `.github/workflows/flake-hunt.yml`

## Acceptance criteria

- Each workflow that pushes a branch installs with `--ignore-scripts`.
- A gardening run that changes code opens its pull request.
- No rule for a push from a machine changes: the `pre-push` hook and its targets stay as they are.
