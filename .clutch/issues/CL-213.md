# CL-213: Run Linear issues in parallel lanes that auto-merge

## Goal

A Linear Todo can run beside other Todos in the same repository, each in its
own checkout, and the PR it opens merges through Auto-merge when its risk tier
allows, with no hand merge.

## Context

`deliver-linear` serialized each repository to one active worker, through a
unique index on `runs(route)`. It told the worker never to create a worktree,
and it stopped at a PR, with the merge left to the owner. Auto-merge judges
only PRs that the release bot opens, so the Linear route opens its PRs with
`bun run pr open`.

## Steps

1. `intake.py`: replace the `one_repository` index with a per-route
   `maxLanes` limit (default 3). Drop the index in `connect`, so existing
   databases migrate. Count the route's reserved and working runs inside the
   reserve transaction, and return `busy` at the limit.
2. `test_intake.py`: cover the default, `maxLanes: 2`, `maxLanes: 1`, invalid
   values and migration of an old database.
3. `SKILL.md` "Run one issue" and the statuses section: each issue gets its own
   checkout, the task branch is `clutch/cl-<key>-<slug>`, the worker opens the
   PR with `pr open`, and Done means the merge is observed.
4. `references/setup.md`: document `maxLanes`.
5. `deliver/SKILL.md`: a Todo grants a PR, and the merge follows auto-merge.

## Acceptance criteria

- With `maxLanes: 2`, two issues reserve and a third stays queued with status
  `busy`. The default is 3. `maxLanes: 1` keeps one run per repository.
- An existing database loses the `one_repository` index on its next command.
- An invalid `maxLanes` (0, negative, fractional, a string or a boolean) fails
  route registration.
- `one_issue` still allows one active run per issue.
