# CL-531: Show the check that holds each principle, and name the principles that only review holds

## Goal

A reader of the principles index sees the check that holds each principle, or sees that only review holds it.

## Context

Bend keeps each rule in one file, a checker holds each rule, and its README lists what the checker does not cover. Clutch has 22 principle pages, and no page maps a principle to its check. Six principles have no check: fail loudly, fix the root bottleneck, keyboard first, mobile first, no invasive test-only code and single-page app. An agent that reads one of those pages cannot tell that nothing stops a change that breaks it. `tools/check-docs-claims.ts` already fails a doc sentence that names a check that does not exist.

## Steps

1. Branch `clutch/cl-531-principle-checks`.
2. Add a `Held by` column to the table in `docs/principles/index.md`. Each cell names the check, the lint rule or the journey that holds the principle, or says `Review only`.
3. Extend `tools/check-docs-claims.ts`. It fails on a principle page with no row, on an empty `Held by` cell, and on a cell that names a check or a lint rule that does not exist.
4. Add the rule of each `Review only` principle to `docs/contributing/review.md`, which holds the rules that no check enforces yet.
5. File one issue for each `Review only` principle that a check can hold.

## Files

- `docs/principles/index.md`, `docs/contributing/review.md`
- `tools/check-docs-claims.ts`, `tools/check-docs-claims.test.ts`

## Acceptance criteria

- Each principle has a `Held by` cell.
- A new principle page with no row fails `validate`, and the message names the page.
- A cell that names a check that does not exist fails `validate`.
