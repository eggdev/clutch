# CL-447: Record competitor runs of each core journey for the council

## Goal

The council compares each core journey with 2 to 4 competitors from recorded runs. A model's memory of a competitor's UI is never evidence.

## Context

- Brendan, 2026-11-06, wants each feature scored on "how well our feature stacks up against our competitors".
- CL-446 metric 10 needs this data. The research method, from NN/g competitive usability evaluations:
  - The owner names the competitors.
  - An agent drives each live flow with the same script.
  - Tools compute the deltas, and models compare screens in blind pairs.
  - Every claim cites a record.
- Pitfalls:
  - An agent's own failure gets logged as competitor friction.
  - Regional A/B tests show a different flow.
  - A CAPTCHA or the site's terms block the run. Never bypass it.
  - Counting features rewards bloat.

## Steps

1. Give project intent a competitor list for each core journey, 2 to 4 per journey. Kickoff asks the owner for it in a T3 thread.
2. Add a recorder that runs each competitor's flow with Playwright. It uses the journey's task script, the same widths and a new account. For each step it records the action, a screenshot, the inputs with their `required` flags, the elapsed time and web-vitals. Store each run at `competitors/<journey>/<vendor>/<date>/`, with its locale and plan. Log agent failures in their own field.
3. For a flow behind a paywall, a KYC check or a bot wall, take dated screens from a flow library, mark them `library`, and treat their timing as an estimate.
4. Compute the delta table for metrics 2, 3 and 9 for the council. Give the pairs to the models blind, judge each pair in both orders, and call a flipped verdict a tie.
5. Run the recorder again each month from a T3 schedule (CL-438). A record older than 90 days stops gating the merge.
