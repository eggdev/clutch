# CL-495: Revert an auto-merged change when its production proof fails

## Goal

When production fails its core journeys after a deploy, the change that auto-merge merged is reverted with no person. The owner is asked only when no revert is possible.

## Context

- The council review of 2026-11-13 found this gap at head `8563977b`. The owner approved the fix on 2026-11-14.
- `tools/deploy.ts prove` runs the core journeys on production. After two failed runs it opens a question for the owner: revert, or fix forward. The failure stays live until he answers.
- `tools/github/auto-revert.ts` already reverts an auto-merged pull request that turns CI on the default branch red. A revert can be paid back, so the owner does not need to choose it.
- The template names no deploy, so `prove` prints "Nothing to prove" here. The tests use the fake runs of `tools/github`.
- CL-443 keeps the rest of the production work, such as the list of pull requests in each deploy.
- A change to a workflow trigger or grant is in the tier `one-way-door`. So the pull request waits for the owner's approval.

## Steps

1. Branch `clutch/cl-495-revert-on-production-failure`.
2. Find out first: how `auto-revert.ts` finds the pull request of a commit, how it knows that auto-merge merged it, and how it starts the revert.
3. When `prove` fails twice, start the same revert for the deployed commit. Use the smallest change: a call from the Deploy job, or the Deploy workflow as one more trigger of Auto-revert.
4. Ask the owner, as today, in three cases: a person merged the commit, the commit is a revert, or the revert cannot start.
5. Make sure that the revert deploys and that production is proven again.
6. Update `docs/principles/proof-gates-code.md`, the deploy docs and the rollback docs.

## Acceptance criteria

- A test: two failed production runs after an auto-merged commit start the revert of its pull request, and open no question.
- A test: two failed runs after a commit that a person merged open the question, and start no revert.
- A test: two failed runs after a revert commit open the question, and start no second revert.
- A test: one failed run and one passed run start nothing.
- The docs say what happens in each case.
