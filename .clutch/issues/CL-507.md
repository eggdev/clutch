# CL-507: Write the Clutch deprecation policy and warn before a removal

## Goal

Anything a project depends on gets one release of warning before it goes away.

## Context

In the 2026-10-30 research over 58 repositories (see `.clutch/PLAN.md`), 26% of top repositories have a written deprecation policy, against 0% of the rest. It is what lets a fast trunk move without breaking the repositories that follow it.

## Steps

1. Branch `clutch/cl-507-deprecation`.
2. Write `docs/contributing/deprecation.md`: what counts as public (the CL-506 surface), the `Deprecated:` changeset line, and the one-release window.
3. `clutch sync --check` and `doctor` print each deprecation that affects the project, with the release that removes it.

## Files

- `docs/contributing/deprecation.md`
- `apps/cli/src/sync/`
- `tools/release/changeset.ts`

## Acceptance criteria

- A deprecated item shows in `sync --check` of a project that uses it.
