# CL-464: Hold a pull request whose contract snapshot names a break

## Goal

A PR whose `contract.json` names a break waits for the owner, by a rule of the merge judge.

## Context

- `tools/check-contract.ts` passes a one-way change when the snapshot names it under `breaks`. The flag `--accept-breaks` writes the name, and any agent can run it.
- `docs/contributing/architecture/contract.md` says that the owner agrees to a break. No check holds that sentence.
- A non-empty `breaks` is a fact that the judge can read with no language model.

## Steps

1. Branch `clutch/cl-464-hold-contract-breaks`.
2. Write the failing tests first, in the tests of `tools/github/auto-merge-rules.ts`: a PR whose head has a non-empty `breaks` is held for the owner, and one with an empty list is not.
3. Read `contract.json` at the head of the PR in the judge, and hold a non-empty `breaks` as the tier `one-way-door` is held.
4. Give `pr status` and `pr merge` the same verdict, with a sentence that names the breaks.
5. Say it in `docs/contributing/architecture/contract.md` and `docs/contributing/review.md`.

## Files

- `tools/github/auto-merge-rules.ts`, `tools/github/auto-merge.ts`, `tools/github/merge.ts`, `tools/github/status.ts`
- `docs/contributing/architecture/contract.md`, `docs/contributing/review.md`

## Acceptance criteria

- Auto-merge leaves a PR with a named break for the owner, and its verdict names each break.
- The owner's approval of the head lifts the hold, as it lifts the tier.
- A PR that only adds a record or a command is not held by this rule.
