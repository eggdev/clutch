# CL-024: Make pull requests and stacks a repeatable rule for every project

## Goal

Every project that comes from Clutch opens pull requests the same way: ready for review, and in a linear GitHub stack when a PR builds on another open PR. One committed command does the GitHub steps, so no agent types them by hand (decision by Brendan, 2026-10-29).

## Context

- Agents ran `gh` and `gh api` by hand: create, mark ready, change the base, link a stack, edit a body and merge. Each session did it a little differently.
- The Ubuntu `gh` on the Spark is 2.45. Its `gh pr edit` fails on the retired Projects (classic) API.
- GitHub stacks come from the `github/gh-stack` extension. A stack is linear. `gh stack link` reuses open PRs, fixes their bases and adds to an existing stack.
- The full install copies `tools/`, `mise.toml`, `docs/` and `.agents/skills/` into a project. Review install copies the deliver skill.

## Steps

1. Pin `gh` in `mise.toml`, so every machine and CI run the same version.
2. Add `tools/github/pr.ts` with `doctor [--fix]`, `open`, `body` and `merge`. `doctor --fix` installs the pinned `gh-stack` version.
3. `open` pushes the branch, opens the PR ready for review and links it into the stack of its base branch.
4. Add the `pr` script to `package.json`.
5. Add `.agents/skills/deliver/references/pull-requests.md` with the rules, and link it from the deliver skill and `docs/contributing/delivery.md`.
6. Point `.clutch/README.md` at the command.

## Acceptance criteria

- `mise exec -- bun run pr doctor` passes on the Spark.
- Unit tests cover the stack chain, the version check and the argument errors.
- validate passes.
