# CL-424: Find the pull request inside the auto-merge decide job

## Goal

One auto-merge job on each run in place of two, with the same decisions.

## Context

Each job bills at least one minute in a private repository. On 2026-11-02 and
03, Neighborhood ran Auto-merge 139 times. Each run had a `find` job of a few
seconds, then `decide`. Dropping the `pull_request` trigger would save more,
but the hourly sweep matches runs to a PR's head through those runs, so it
would dispatch every PR every hour. This change keeps every trigger.

## Steps

1. Move the Find step into `decide`. The checkout and the rules run only
   when it found a PR that the run may judge.
2. Let the sweep count a decide job only when its Decide step ran, so a run
   that found no PR is not taken as a decision.
3. Queue decisions by PR number, since no job output is known before the job.
   A `workflow_run` that names no PR falls back to its head commit.

## Files

- `.github/workflows/auto-merge.yml`
- `tools/github/auto-merge-sweep.ts`, `tools/github/auto-merge-sweep.test.ts`
- `.agents/skills/deliver/references/pull-requests.md`

## Acceptance criteria

- The same verdicts and merges, from one `decide` job. The sweep still reads
  the job named `decide`.
