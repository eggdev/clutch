# CL-105: Audit CI credentials and adopt OIDC or waive it

## Goal

Each long-lived CI secret either moves to OIDC or has a recorded waiver.

## Context

Two workflows use long-lived secrets: `agent-review.yml` and `gardening.yml`. Both use `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`. `ci.yml` uses none. Both workflows grant `id-token: write`, but no workflow logs in to a cloud provider. CL-022 removed the Nx cache tokens and the Cloudflare token.

## Steps

1. Branch `clutch/cl-105-oidc`.
2. List the secrets used in workflows: `rg -n 'secrets\.' .github/workflows`. Expect `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`.
3. For each one, record in the PR body: the provider, whether it supports GitHub OIDC, and the scope.
4. Do not change any secret. Credential changes are a human gate.
5. Verify the waiver claim before you write it: `rg -n 'role-to-assume|workload_identity_provider|azure/login' .github/workflows` must print nothing.
6. In `clutch.yaml`, replace the `oidc_ci` waiver with `oidc_ci: { status: waived, reason: 'CI deploys to no cloud provider. The only secrets are Anthropic credentials.' }`. It has no `issue`, so it does not expire when this issue is done.
7. Write `docs/contributing/setup/ci-credentials.md` describing each secret's scope. Follow the doc rules. Add a line for it to `docs/contributing/setup/index.md`, after the Checks line.
8. In the PR body, add this checklist for Brendan: "- [ ] Delete the old Cloudflare and Nx secrets from the repository settings. CL-022 removed their use."

## Acceptance criteria

- `clutch.yaml` has an `oidc_ci` decision with a reason and no `issue`.
- `ci-credentials.md` lists `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`, and the index links to it.

## Verify

rg -o 'secrets\.[A-Z_]+' -N .github/workflows | sort -u
