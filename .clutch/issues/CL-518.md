# CL-518: Let the sync bot rule accept a seed file that sync adds

## Goal

Auto-merge takes a Clutch sync PR that adds a new seed file, at the step `bots`, as it takes a sync PR that changes only managed files.

## Context

- CL-515 added `add_on_sync` to a seed entry in `clutch.files.yaml`. Sync adds each file under it that the project lacks, once, and lists it in `seeded` in `.clutch/lineage.json` (`apps/cli/src/sync/seed-adds.ts`). The factory tree at `factory/` uses it.
- `syncProblems` in `tools/github/bot-rule.ts` accepts only the managed files in the PR's lineage and a short list of extras. A sync PR that adds `factory/agents/implement/agent.md` gets "is not a file that clutch sync writes", so a person must merge it.
- The rule must accept only a file that the PR adds, under an `add_on_sync` entry, with the content of Clutch's copy at the PR's release. It must still reject a change to a seed file that the project already has.

## Steps

1. Branch `clutch/cl-518-sync-bot-seeds`.
2. Give the bot rule the paths that sync added. One option: the rule reads `seeded` from the PR's lineage, as it reads the managed files, and accepts a listed path that the PR adds. Pick the option that a forged PR cannot use to add a file that Clutch did not ship.
3. Accept those paths in `syncProblems` only when the PR adds the file.
4. Add the test cases to `tools/github/bot-rule.test.ts`.

## Files

- `tools/github/bot-rule.ts`, `tools/github/auto-merge.ts`, their tests
- `apps/cli/src/sync/` when the lineage records the added paths

## Acceptance criteria

- A sync PR that adds the factory tree passes the bot rule.
- A sync PR that changes a seed file that the project has fails the bot rule.
- `mise exec -- bun run validate` passes.

## Verify

```bash
mise exec -- bun test tools/github/bot-rule.test.ts
mise exec -- bun run validate
```
