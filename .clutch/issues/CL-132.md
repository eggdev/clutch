# CL-132: Support auto-merge steps, the bot rule and a main-red guard

## Goal

Auto-merge can be turned on one step at a time, merges as the release bot, and never merges onto a red `main`. Then CL-405 only flips `clutch.yaml`.

## Context

CL-404 shipped the dry-run for low-risk agent PRs. CL-405 turns auto-merge on in three steps: bot PRs, then `risk/low`, then `risk/medium` with a clean agent review. Two prerequisites from CL-112 are in CL-405's steps: the decide job needs `contents: write`, and the merge needs the release bot token, so the release and CI run after it.

## Steps

1. Branch `clutch/cl-132-automerge-steps`.
2. Add `automerge.step` (`bots`, `low` or `medium`) to the `clutch.yaml` schema.
3. Judge bot PRs. A `renovate/` or `gardening/` branch needs a bot author and a diff that passes the bot rule. Renovate may change only versions, lockfiles and changesets. Gardening must be `risk/low`.
4. Refuse every merge while a required check is red on the default branch's latest commit.
5. In `on` mode, run `gh pr merge --auto --merge` with the release bot token, and give the decide job `contents: write`. Comment once that the merge is queued.
6. Keep the dry-run verdict on agent PRs: at the step in `dry-run`, and at the next step in `on`.

## Files

- `tools/github/auto-merge.ts`, `tools/github/bot-rule.ts`, `.github/workflows/auto-merge.yml`, `apps/cli/src/clutch-config/schema.ts`, `.agents/skills/deliver/references/pull-requests.md`.

## Acceptance criteria

- At `step: bots`, a version-only Renovate PR is queued, and a low-risk agent PR is not.
- No PR is queued while a required check is red on `main`.
