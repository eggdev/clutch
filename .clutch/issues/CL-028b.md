# CL-028b: Run init, sync and doctor from the clutch release binary

## Goal

A project runs `clutch sync`, `clutch doctor` and `clutch init` through the release binary that mise installs, with no Clutch clone.

## Context

- CL-025 made the binary run the tracker commands. `install`, `init`, `sync` and `doctor` read Clutch's files from a clone, so the binary refuses them.
- A project's `check-clutch` target runs `bun tools/clutch.ts doctor --check`. In a project that runs the binary, so the target fails today.
- CL-028 made sync and init follow the newest `vX.Y.Z` tag of the clone. They read Clutch through git (`loadClutchSource`), so a bare clone works as the source.

## Steps

1. Doctor: build the registry into the binary, so `doctor` reads the registry of the release that runs. Check the doc pages only in a clone.
2. Sync and init: keep a bare clone of `template.repo` in the user cache folder. Fetch its tags before each run, and read the latest release from it.
3. Keep `install` from a clone, or move it too. Decide in the PR.
4. Remove the `clone` guard from each command that works.

## Acceptance criteria

- In a project made by `clutch install`, `mise exec -- bun run clutch doctor --check` and `mise exec -- bun run clutch sync --check` run through the binary.
- validate passes.
