# CL-012: Extract the sync engine from review install with no behavior change

## Goal

Move the planning and apply logic of `apps/cli/src/review-install.ts` into a generic engine, so `clutch sync` reuses tested code.

## Context

`review-install.ts` does these things today:

- It compares hashes of the template's committed files (`review-source.ts`, which uses `git ls-tree` and `git show`) against the target's `.review/tooling.json` `{schemaVersion, templateCommit, files}` and `review-baseline.json`.
- A conflict means the local hash matches neither.
- It removes paths listed in `retired`.
- Its writes are symlink-safe: a temp file, then a rename.
- It requires managed paths to be clean, and it checks the preflight again before it changes anything.

## Steps

1. Branch `clutch/cl-012-sync-engine`.
2. Add `apps/cli/src/sync/engine.ts` with `plan({source, target, record, baseline, retired})` and `apply(plan)`. The source is `Map<path, {mode, content, hash}>` and the record is `{templateCommit, files}`. Copy the logic. Do not rewrite it.
3. Make `review-install.ts` call the engine. Keep its public behavior, output and exit codes.
4. Keep every existing `review-install.test.ts` and `review-command.test.ts` test unchanged. `check-test-integrity` blocks removed tests. Add engine unit tests.
5. Keep every file under 400 lines.

## Files

- add `apps/cli/src/sync/engine.ts` plus test
- edit `apps/cli/src/review-install.ts`

## Acceptance criteria

- `git diff origin/main -- 'apps/cli/src/*review*.test.ts'` is empty.
- All CLI tests pass.
