# CL-562: The gardening job pushes with the Git hooks off

## Goal

The weekly gardening job can push its branch after it ran `validate`.

## Context

CL-496 made the gardening job install with `--ignore-scripts`, so the Git hooks stay off and the push does not run the journeys in a job with no browser. CL-554 then added a step that runs `validate` before the commit.

`validate` has the target `check-lockfile`, which runs `bun install --frozen-lockfile`. That install runs the root `prepare` script, and the script turns the Git hooks on again. So the push ran the `pre-push` hook, the journeys failed with no browser, and Git refused the push. The run of 2026-11-17 on `main` failed in this way: each step passed, and the step that opens the pull request failed.

## Steps

1. Branch `clutch/cl-562-gardening-hooks-off`.
2. In the step that opens the pull request, turn the Git hooks off before the commit and the push.
3. After the merge, start the gardening workflow by hand one time, and confirm that the step that opens the pull request passes.

## Files

- `.github/workflows/gardening.yml`

## Acceptance criteria

- A gardening run that changes code passes `validate` and then opens its pull request.
- The `pre-push` hook and its targets stay as they are for a push from a machine.

## Verify

```sh
mise exec -- bun run validate
```
