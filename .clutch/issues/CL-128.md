# CL-128: Keep the check-db schema test inside its timeout

## Goal

`tools/check-db.test.ts` "a schema change with no migration fails, and passes once drizzle-kit writes one" passes inside its timeout on a loaded CI runner, so it leaves the quarantine.

## Context

The test runs `drizzle-kit` for real several times. On 2026-10-31 it timed out at 5 s in CI (run 41198473156, PR #109), and it passed on the rerun. CL-029 measured the whole file at 1.3 s on an idle machine. CL-304 quarantined it in `tools/flaky-tests.json` until 2026-11-28.

## Steps

1. Branch `clutch/cl-128-check-db-timeout`.
2. Measure each `drizzle-kit` call in the test under `CI=1` with the other test targets running.
3. Cut the calls the test does not need, or give this test an explicit timeout with the measured reason in a comment. Never skip it.
4. Remove its entry from `tools/flaky-tests.json`.

## Files

- `tools/check-db.test.ts`
- `tools/flaky-tests.json`

## Acceptance criteria

- The test passes 20 times in a row under `CI=1` while `validate` runs beside it.
- `tools/flaky-tests.json` has no entry for it, and `check-flaky-tests` passes.

## Verify

```bash
mise exec -- bun test tools/check-db.test.ts --rerun-each 20
mise exec -- bun nx run check-flaky-tests
```
