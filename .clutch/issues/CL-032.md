# CL-032: Release Clutch on every merge: changesets, a stored changelog and GitHub releases

## Goal

Each merge to `main` is a semver release. It bumps the version, adds its entries to `CHANGELOG.md` in the repository, tags `vX.Y.Z` and publishes a GitHub release with the `clutch` binaries (decision by Brendan, 2026-10-30). npm comes later.

## Design

- Each PR carries a changeset in `.changeset/` with its bump and summary. `bun run pr open` writes it from the conventional PR title: `fix` is a patch, `feat` is a minor, and `!` is a major. Changesets are separate files, so stacked PRs never conflict on a version.
- A check fails a PR that changes distributed files without a changeset.
- On a push to `main`, a release workflow:
  - runs `changeset version`, which bumps the version and writes `CHANGELOG.md`;
  - commits that to `main`;
  - tags `vX.Y.Z`;
  - builds `clutch` with `bun build --compile` for Linux and macOS, x64 and arm64;
  - publishes the GitHub release with the changelog entry and the binaries.
- A stack merged in one go is one release.
- When `main` gets protection (CL-106), the release workflow needs a bypass to push its version commit. That is a repository setting for Brendan.

## Acceptance criteria

- A merge with a changeset produces a tag, a GitHub release with binaries, and a `CHANGELOG.md` entry on `main`.
- A PR without a changeset fails its check.
- validate passes.
