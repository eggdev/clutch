# CL-534: Give each check finding a stable id, and print the findings as JSON

## Goal

An agent reads the findings of `validate` as data: an id that does not change, a file, a line, the problem and the fix.

## Context

Exact's compiler gives each diagnostic a stable id and a source range, and prints JSON for tools. Clutch has the rule in `docs/contributing/setup/checks.md`: "A failure message names the file, the problem and the fix." The checks follow it, but each check prints free text. Only `tools/audit-prod.ts` has `--json`. No finding has an id, and only some findings name a line. An agent parses prose to find what to fix, and a reworded message breaks that.

Move the checks one at a time. This issue adds the shape and moves two checks. A second issue moves the other checks in batches.

## Steps

1. Branch `clutch/cl-534-check-findings`.
2. Add one finding type to a shared module in `tools/`: `id`, `file`, `line`, `problem` and `fix`. One printer writes the text form.
3. Add `--json` to `tools/validate.ts`. It prints the findings of each moved check as one JSON document. A check gets no flag of its own.
4. Move `tools/check-file-size.ts` and `tools/check-contract.ts` to the type. Pin each id in the test of its check.
5. Add the rule to `docs/contributing/setup/checks.md`: a new check starts on the type.
6. File one issue that moves the other checks to the type in batches.

## Files

- A shared module in `tools/`, and `tools/validate.ts`
- `tools/check-file-size.ts`, `tools/check-contract.ts` and their tests
- `docs/contributing/setup/checks.md`

## Acceptance criteria

- `mise exec -- bun run validate --json` prints one JSON document that holds each finding of the two moved checks.
- Each of those findings has an id, and a test pins it.
- The text output of each check still names the file, the problem and the fix.

## Verify

```sh
mise exec -- bun run validate
```
