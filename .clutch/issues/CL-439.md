# CL-439: Gate on core journeys and product decisions, not code paths

## Goal

The owner gates the product, and proof gates code. One principle page says so, and no doc tells an agent to ask the owner about a diff.

## Context

- Brendan, 2026-11-06: "I'm expecting 1-2 stops a day." And: "my gates should shift from being on the sensitive side of the software to the sensitive decisions for the product journeys." He approved held Neighborhood PRs to meet a deadline, without a real review.
- Brendan, 2026-11-06: "There should realistically be no 'decisions' in this project. They should all be funnelled to critically important core documents." So the rule is a principle page, and CL-444 folds the decision records into core docs.
- On Neighborhood from 2026-10-28 to 2026-11-07, the one-way-door tier held 19 bot PRs and none caused a bug. Seven journeys broke on `risk/medium` PRs with every check green. The fix for the broken production sign-in, eggdev/neighborhood#94, waited for the owner because it touched `packages/identity/**`.
- The path tiers stay until CL-441 gives each held path its journeys. This issue changes docs, not `risk.yaml` rules.

## Steps

1. Branch `clutch/cl-439-journey-gates`.
2. Add `docs/principles/proof-gates-code.md`: what the owner decides, what proof decides, the core journeys, and the rule that a gate with no proof fails. List it in `docs/principles/index.md`.
3. Rewrite "One-way changes need the owner" in `docs/principles/two-way-doors.md` as "One-way changes need proof".
4. Rewrite "Hard invariants" and the agent rule in `docs/contributing/project-intent.md`: the owner decides what an invariant says, and a journey proves each change keeps it.
5. Link the principle from the ask rule in `.agents/skills/deliver/SKILL.md`, and from the `.clutch/risk.yaml` header comment.
