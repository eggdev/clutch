# CL-492: Fail a write that returns no row

## Goal

A repository function returns the row that the database holds, or it fails. It never returns its input as if the database stored it.

## Context

- The council review of 2026-11-13 found this gap at head `8563977b`. The owner approved the fix on 2026-11-14.
- Four functions end with `rows[0] ?? row`: `packages/notes/repo/notes.ts`, `packages/notes/repo/space-note-count.ts`, `packages/access/repo/space.ts` and `packages/access/repo/membership.ts`.
- When the statement returns no row, the caller gets the input row. The caller cannot see that nothing was written, or that the stored row is different.
- This breaks `docs/principles/fail-loudly.md`.
- `packages/access/**` is a path that the owner holds until its journeys exist. So the pull request waits for the owner's approval.

## Steps

1. Branch `clutch/cl-492-no-made-up-rows`.
2. Find out first: when each statement returns no row. An insert that does nothing on a conflict is one case.
3. For each function, return the row that the database holds. When no row exists, fail with the typed error that the repositories of this project use. Find out first: its name.
4. Add a test for each function that shows the failure, or the stored row.
5. Stop the pattern from coming back: add a lint rule or a ratchet at zero for `?? row` in `packages/*/repo`. Use the smaller of the two.

## Files

- `packages/notes/repo/notes.ts`
- `packages/notes/repo/space-note-count.ts`
- `packages/access/repo/space.ts`
- `packages/access/repo/membership.ts`
- The test file of each one.
- `.clutch/ratchets.json`, or the lint rule and its test.

## Acceptance criteria

- No file under `packages/*/repo` contains `?? row`.
- For each of the four functions, a test shows the stored row or a typed failure when the statement returns no row.
- A new `?? row` in a repository file fails `validate`.
- The journey `notes-sync` still passes.

## Verify

- `mise exec -- bun test packages/notes packages/access`
- `mise exec -- bun run validate`
