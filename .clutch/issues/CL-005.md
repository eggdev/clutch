# CL-005: Add clutch notify for the Bix webhook

## Goal

`clutch notify <kind> "<message>"` posts a status to Bix, so the agent reports milestones and questions without a chat window.

## Context

- `apps/cli/src/notify.ts` already exists. It is a desktop notifier (terminal bell, osascript, notify-send) that the install flow uses. Do not change its behavior. Put the webhook in a new module.
- Env contract, decided by Brendan:
  - `BIX_WEBHOOK_URL` (required)
  - `BIX_WEBHOOK_AUTH_HEADER`: the full header value, sent verbatim
  - `BIX_WEBHOOK_AUTH_HEADER_NAME`: the header name, default `Authorization`
  - `BIX_WEBHOOK_KEY`: used verbatim as the header value only when `BIX_WEBHOOK_AUTH_HEADER` is unset
  - Do not prefix `Bearer` or any scheme in code.
- Body: `{from, repo, branch, pr_url, kind, message}`. `kind` is one of `status|question|done|blocked|handoff`.

## Steps

1. Branch `clutch/cl-005-notify`.
2. Add `apps/cli/src/notify/bix.ts`:
   - `buildPayload({kind, message, pr, from, cwd})` fills:
     - `repo` from `git remote get-url origin`, as `owner/name`
     - `branch` from `git rev-parse --abbrev-ref HEAD`
     - `pr_url` from `--pr`, else `gh pr view --json url -q .url` when `gh` exists and succeeds, else `null`
     - `from` from `--from`, else `CLUTCH_AGENT_NAME`, else `agent@<hostname>`
   - `send(payload, env)` posts JSON with a 10 s timeout. It never logs the auth value.
3. Add `apps/cli/src/notify-command.ts`:
   - Usage: `clutch notify <kind> <message> [--pr URL] [--from NAME] [--dry-run] [--json]`.
   - Exit codes:
     - 0 on a 2xx response
     - 1 on a bad kind, an empty message, a non-2xx response or a network error, printing the status code and the first 200 bytes of the body
     - 3 when `BIX_WEBHOOK_URL` is unset, printing the payload so a log keeps it
   - Limit the message to 2000 characters.
   - `--dry-run` prints the payload and the header name, never the value.
4. Register `notify` in `commands.ts`.
5. Tests start a local `Bun.serve` on port 0 and assert method, headers, body, timeout and exit codes. Test that the auth value never appears in stdout or stderr.
6. Document the env vars in `apps/cli/README.md`. Add them to `.env.example` if one exists at the root; otherwise only the README.
7. Validate, commit "Add clutch notify for status webhooks", draft PR, then send `clutch notify status "CL-005 in review"` as the first real use.

## Files

- add `apps/cli/src/notify/bix.ts` plus test, `apps/cli/src/notify-command.ts` plus test
- edit `apps/cli/src/commands.ts`, `apps/cli/README.md`

## Acceptance criteria

- With the env set, `clutch notify status "hello"` returns 0 and Bix receives the body above.
- With no env, the command exits 3 and prints the payload.
- No test or log prints the auth value.
