# CL-211: Judge agent PRs by author, and auto-merge reverts

## Goal

Auto-merge judges an agent's PR by its author, not only by its `clutch/cl-` branch. A revert PR that undoes an auto-merged PR can merge while main is red. The last step of `automerge.step` posts no dry-run comment.

## Context

- Auto-merge judged only PRs whose head branch starts with `clutch/cl-`. Other projects name branches differently (Neighborhood uses `feature/`, `fix/` and `clutch/sync-v0.39`), so their decide job was skipped on every PR. The release bot opens agent PRs through `open-pr.yml`, so a bot author is the reliable signal.
- The Revert workflow opens a `revert/<n>` PR. Nothing auto-merged it, and `blockers()` refused every merge while main was red. One bad auto-merge therefore stopped all merging until a person merged the revert.
- At the last step, `medium`, `nextStep` returns `medium`. `on` mode still posted a dry-run "react 👍/👎" comment on each blocked PR, although there was no next step to calibrate.

## Steps

1. In `tools/github/bot-rule.ts`, make `botKind` return `revert` for `revert/` branches. Add `revertedPr`, which reads the number from `revert/<number>`.
2. In `tools/github/auto-merge-rules.ts`, add `isAgentPr`: no bot kind, and a `clutch/cl-` branch or a bot author. `kindProblem` keeps the bot-author rule for a bot branch. Any other PR gets the reason to open it with `bun run pr open`. Use `isAgentPr` wherever the branch prefix was tested.
3. In `tools/github/auto-merge-rules.ts`, skip the red-main reasons for a revert PR. Other reasons still apply.
4. In `tools/github/auto-merge.ts`, judge a revert PR in `runAutoMerge`. It may merge only when `autoMerged()` finds the reverted PR auto-merged and its own risk tier is `low` or `medium`. Otherwise the reasons go in `botProblems`.
5. In `tools/github/auto-merge.ts`, when `mode` is `on` and `nextStep(step) === step`, log that the step is the last and return before any dry-run comment.
6. In `.github/workflows/auto-merge.yml`, the decide job's `if:` accepts any PR from this repository, not a fork, and no branch prefix. The script decides. Triggers, `permissions:` and `environment:` are unchanged.
7. In `tools/github/revert.ts`, the revert PR body says when auto-merge takes it.
8. Update the tests in `tools/github/auto-merge.test.ts`, `bot-rule.test.ts` and `revert.test.ts`.
9. Update `.agents/skills/deliver/references/pull-requests.md#auto-merge`, `docs/contributing/operations/rollback.md`, `docs/contributing/setup/checks.md` and `docs/contributing/capabilities/risk-tier-automerge.md`.

## Acceptance criteria

- A bot-authored PR on `feature/x` is judged as an agent PR.
- A person-authored PR on `feature/x` is refused with the new reason, and gets no comment.
- A `clutch/cl-` branch still works.
- A revert PR of an auto-merged PR may merge while main is red.
- A revert PR of a person-merged PR may not merge.
- `on` at the step `medium` posts no dry-run comment.
- `.clutch/risk.yaml`, rulesets and `agent-review.yml` are unchanged.
