# CL-568: Let a project differ from Clutch on purpose, and keep that across syncs

## Goal

A project maintainer can keep a small, deliberate difference from Clutch's copy of a synced file. The difference has a reason, `clutch doctor` lists it, and no later sync undoes it.

## Context

The owner asked for a sync that is more forgiving. A project must be able to keep its own behavior or text without a fight on each sync.

A **project difference** is one place where a project differs on purpose from Clutch's copy of a file that sync delivers. Each one has a reason, as each entry of `tools/accepted-advisories.yaml` and `tools/dependency-overrides.yaml` has. There are three kinds:

- An edit to a managed file, which sync carries forward with a three-way merge. CL-569 adds it.
- A removal from a merge file: a key, a list item or a line that the project does not want. CL-570 adds it.
- A notes block at the end of a managed Markdown page, for facts of one project. CL-571 adds it.

Sync today has no such idea:

- `clutch.files.yaml` gives each file one rule: `managed`, `merge` or `seed`.
- A managed file that the project edited is a conflict in `planDesired` (`apps/cli/src/sync/engine.ts`, line 101). It is a conflict even when Clutch did not change the file.
- `settle` in `apps/cli/src/sync/run.ts` records a kept file in `kept` of `.clutch/lineage.json`, with the hash of Clutch's copy. The whole file is the unit. Sync asks again each time Clutch changes that file.
- Sync stores only hashes. It never merges three ways. `readLineage` in `apps/cli/src/sync/lineage.ts` does not read `templateCommit` back.
- `mergePackageJson` (`apps/cli/src/merge-package-json.ts`) adds back each key that the project deleted, and joins lists. `mergeLines` (`apps/cli/src/install-template.ts`) adds each missing line. So a project cannot remove an item that Clutch adds.
- No record holds the reason for a kept file or a kept value.

Neighborhood synced from v0.62.0 to v1.13.1 in the week of 2026-11-16:

- 14 managed files needed a three-way merge by hand to keep small project changes. Most were one line, such as one `nosemgrep` line in `.github/workflows/deploy.yml`.
- `check-deploy` came back in the `checks` list of `package.json` on each sync, because sync joins lists.
- One sentence in `docs/principles/fast-first-load.md` needed a kept copy of the whole page. Agent review then flagged that page as the owner of the behavior on each head.
- Two projects kept a managed file only to change one number, or to say that their own pipeline deploys.

### Order

1. This issue: the term, the record of reasons in `clutch.yaml`, and the list in `clutch doctor`.
2. CL-569: carry an edit to a managed file with a three-way merge.
3. CL-571 and CL-572, which use the merge of CL-569: the notes block, and the review rule for managed pages.
4. CL-570 and CL-573 do not need CL-569: the removal from a merge file, and a setting in place of a kept file.

### Where the reasons live

A reason goes in `differences:` in `clutch.yaml`, and not in `.clutch/lineage.json`. Sync writes the lineage, and a reason is the owner's words. `clutch.yaml` already holds each waiver with its reason. `tools/guardrail-files.json` lists `clutch.yaml`, so a new difference gets the same review as a new waiver. The hashes that sync compares stay in the lineage.

## Steps

1. Branch `clutch/cl-568-project-differences`.
2. Add `differences:` to the schema in `apps/cli/src/clutch-config/schema.ts`. It is a list. Each entry has `path`, `kind` and `reason`, and each one is required.
   - `kind: edit` names a managed file, such as `tools/check-bundle.ts`.
   - `kind: value` names a merge value that the project keeps, such as `package.json#scripts.validate`. Sync has this kind already, as `kept` in the lineage.
   - `kind: removal` names a merge item that the project removed. CL-570 gives its form.
3. Reject an entry with an empty `reason`, an unknown `kind`, or a `path` that appears twice. Extend `apps/cli/src/clutch-config/schema.test.ts`.
4. Make `clutch doctor` list each project difference: its kind, path and reason. List each entry of `kept` in the lineage that has no `differences:` entry as a warning, with the words "no reason recorded". After CL-571, list each notes block too.
5. Add "Project difference" to the Clutch table of `docs/contributing/glossary.md`, with the meaning above.
6. Add a short "Project differences" part to the "Sync" section of `apps/cli/README.md`. Name the three kinds, the record in `clutch.yaml`, and the issues that add each kind.

## Acceptance criteria

- `clutch.yaml` accepts `differences:` with the three kinds. A missing reason, an unknown kind or a repeated path is a config error.
- `clutch doctor` prints each project difference with its kind, path and reason.
- `clutch doctor` warns about each kept file or kept value that has no `differences:` entry.
- The glossary defines "Project difference", and the "Sync" section of `apps/cli/README.md` links each kind to its issue.
- `mise exec -- bun run validate` passes.
