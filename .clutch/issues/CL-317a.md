# CL-317a: Add the ticket store and its rules

## Goal

The store of CL-317 exists as code, with its rules, so the commands of CL-317 only parse arguments and print JSON.

## Context

CL-317 does not fit one pull request under the size limit, so it splits in two. This part adds the store and its rules. CL-317 adds the `clutch tickets` commands on top of it. The design is in [CL-317](./CL-317.md).

## Steps

1. Branch `clutch/cl-317a-ticket-store-module`.
2. Add `apps/cli/src/tickets/store.ts`: open the file in the git common directory, make the tables, and run each write in an immediate transaction that also writes the event.
3. Add `apps/cli/src/tickets/change.ts`: one function for each write of CL-317, with its rules.

## Files

- `apps/cli/src/tickets/store.ts`, `apps/cli/src/tickets/change.ts` (new)
- `apps/cli/src/tickets/store.test.ts`, `apps/cli/src/tickets/change.test.ts` (new)

## Acceptance criteria

- A new ticket takes the next id from 1000, and has one `triage` phase. The phase is `not_ready` when the ticket is held, and release makes it `ready`.
- A route with no `planning` phase fails and names each missing requirement. With the 4 requirements set, it passes.
- `done` makes the next phase `ready`. A phase that goes back to `ready` sets each later phase to `not_ready`.
- A claim of a phase that is not `ready` fails.
- Each write adds exactly one event with `deliveryId`, `type`, `action`, `data` and `updatedFrom`.
- Each worktree of a project opens the same store file. Two projects open two files.
