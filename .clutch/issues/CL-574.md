# CL-574: Pull again after a socket drop, and save again after a failed save

## Goal

A client gets live changes again after its socket drops, and it saves again after one save fails.

## Context

A council review on 2026-11-20 compared the sync engine with a study of Linear's client. It found two bugs in the client, and a test with a real socket confirmed the first one.

- `engine` in `packages/sync/runtime/transport.ts` started `Pull` once. When the socket dropped, the RPC client failed the open `Pull`, and the socket opened again. Nothing sent a new `Pull`. The client still sent its writes, but it got no change of another client until the page loaded again. A `Load` that failed was not sent again either.
- `save` in `packages/sync/runtime/boot.ts` set `writing` and did not clear it when `database.write` failed. Each later change then returned without a write, so a reload lost each change after the failure.

## Steps

1. Branch `clutch/sync-recovery`.
2. Write the failing tests first, in `packages/sync/runtime/transport.test.ts` and `packages/sync/runtime/boot.test.ts`.
3. Pull again after each pull that ends. Stop the whole engine after an ended session. Name the last sync ID and the loaded groups that the pool holds then. Send the load requests that are not loaded yet with each pull.
4. Report a failed save once, and write again on the next change.
5. State both rules in `docs/contributing/architecture/local-first-sync.md`.

## Files

- `packages/sync/runtime/transport.ts`, `packages/sync/runtime/transport.test.ts`
- `packages/sync/runtime/boot.ts`, `packages/sync/runtime/boot.test.ts`
- `docs/contributing/architecture/local-first-sync.md`

## Acceptance criteria

- After a pull ends, the engine pulls again from the last sync ID of the pool, with its loaded groups.
- A group that a gate asked for, and that is not loaded, is asked for again by the next pull.
- An ended session stops the engine, by the 4401 close or by `SessionEnded`, and `onSessionEnded` runs once.
- A `Load` that the server could not run does not end its pull.
- After a save that fails, the person gets one sentence, and the next change saves the newest state.
