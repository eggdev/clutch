# CL-102: Add the CodeQL workflow

## Goal

Static analysis on every PR and on main.

## Context

CL-103 makes `check-workflows` reject an unpinned `uses:`. This workflow lands pinned from the start. There is no merge queue yet, so the workflow does not list `merge_group`. CL-402 adds it later.

## Steps

1. Branch `clutch/cl-102-codeql`.
2. Add `.github/workflows/codeql.yml`:
   - `on:` a push to main, `pull_request`, and a weekly `schedule`
   - top-level `permissions: { contents: read }`, and job `permissions: { security-events: write, actions: read, contents: read }`
   - languages `javascript-typescript` and `actions`, plus `python` because `tools/verification/verify.py` exists
3. Use `github/codeql-action/init` and `analyze` at their current major. Pin each to a full commit SHA, with the tag in a comment, as CL-103 requires.
4. In `clutch.yaml`, replace the `codeql_sast` waiver with `codeql_sast: adopted`. Then run `mise exec -- bun run clutch doctor --write-baseline`.

## Acceptance criteria

- The CodeQL run on the PR is green.
- `check-workflows` passes.
- `clutch doctor --check` passes with `codeql_sast` adopted.

## Verify

```bash
mise exec -- bun nx run check-workflows
mise exec -- bun run clutch doctor --check
gh pr checks --watch
```
