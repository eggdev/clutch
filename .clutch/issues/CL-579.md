# CL-579: Split the object pool into the confirmed records and the pool

## Goal

The object pool has room to grow under the file-size limit, so the local database work (CL-575, CL-578, CL-576) lands with no file-size exception.

## Context

`packages/sync/runtime/pool.ts` is 400 lines on `main`, which is the limit of `tools/check-file-size.ts`. The lane A stack adds about 50 lines to it. The owner chose a split over an exception on 2026-11-20. The design already has a seam: the confirmed records come only from the server, and the pool puts the waiting transactions on top of them. The owner agreed that the first-screen module budget of `tools/check-bundle.ts` may go from 390 to 391 for the new module.

## Steps

1. Branch `clutch/cl-579-split-pool`.
2. Move the confirmed records to `packages/sync/runtime/confirmed.ts`: the confirmed tables, the `meta` of each record, the loaded groups, the last sync ID, the build that left a record out, `applyChange`, `purge`, and the load and snapshot of those parts.
3. Keep in `pool.ts` the waiting transactions, `recompute` and the visible tables, the watchers, the group waits, and the public `Pool` type and `createPool`.
4. Change no behaviour and no test.
5. Raise the module budget to 391 only if the build needs it. Update the docs that name the files of the pool.

## Files
