# CL-112: Make every auto-merge dry-run verdict countable

## Goal

Brendan can agree or disagree with every dry-run verdict, including a hold-back, and `clutch metrics` counts it.

## Context

P1 ends when Brendan agrees with the auto-merge dry-run verdict on 20 PRs in a row. CL-404 comments only on a PR that would auto-merge, so a wrong hold-back cannot be counted.

## Steps

1. Branch `clutch/cl-112-countable-verdicts`.
2. In `tools/github/auto-merge.ts`, comment the verdict on each open, ready PR from a `clutch/cl-` branch: "would auto-merge", or "would not auto-merge" with the reasons. Both end with the 👍/👎 line. Keep one comment for each head commit, with the `<!-- automerge-dry-run:<sha> -->` marker.
3. Post no verdict while a required check has not finished. Otherwise a pending check would decide the head's one verdict.
4. Add `dryRunAgreement` to `clutch metrics`: verdicts, agreed, disagreed, unanswered, and the streak of agreements since the latest 👎.
5. Write the two CL-405 prerequisites into `.clutch/issues/CL-405.md`: the job needs `contents: write`, and the merge uses the release bot token.

## Acceptance criteria

- A medium PR from a `clutch/cl-` branch gets a "would not auto-merge" comment that names its reasons.
- `clutch metrics --json` fills `dryRunAgreement`.

## Verify

```bash
mise exec -- bun run clutch metrics --since 30d --json | jq .dryRunAgreement
```
