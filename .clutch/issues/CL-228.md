# CL-228: Fix three sync breaks found by the Neighborhood sync

## Goal

Neighborhood's sync to Clutch v0.44.0 (`clutch/cl-217-sync-latest`, commit `108d48c`) fails `validate`. A sync PR that auto-merges must pass `validate` in a project, so each break that a project hits is fixed here.

## Context

- `tools/check-managed-links.ts` (from PR #162) reads `clutch.files.yaml`, which sync does not deliver. In a project the check crashed on every run.
- `tools/journeys/web-app.test.ts` (from PR #167) expected Clutch's web-app dev name `app.shop`. Neighborhood's `tools/dev.ts` names its web app with the bare project name, so the expectation failed there.
- `.agents/skills/deliver/references/pull-requests.md` (managed) and `docs/contributing/harness-engineering.md` (managed) linked `docs/contributing/decisions/000x` by repo path. Projects have their own decision records.
- The Neighborhood file `docs/principles/stable-layout.md` links `.agents/skills/verify/SKILL.md`. It exists only in Neighborhood, so Clutch's check never sees it. Clutch's check does scan `docs/principles/`, and Neighborhood generates its own verify skill, so the link resolves there.

## Steps

1. `check-managed-links`: without `clutch.files.yaml`, print one notice line and exit 0. The real check runs in Clutch before each release. A test runs the script in a folder with no manifest.
2. `check-managed-links` tests: a principles page that links the verify skill fails, so the check's coverage of `docs/principles/` is pinned.
3. `web-app.test.ts`: read the expected dev name from `devApps`, the naming function in `tools/dev.ts`, so the test checks which app is chosen in each project.
4. Decision links: link `decision 0001` and `decision 0002` in the managed files by GitHub URL.

## Files

- `tools/check-managed-links.ts`, `tools/check-managed-links.test.ts`
- `tools/journeys/web-app.test.ts`
- `.agents/skills/deliver/references/pull-requests.md`, `docs/contributing/harness-engineering.md`
- `.changeset/cl-228.md`, `.clutch/issues/CL-228.md`

## Acceptance criteria

- In a project without `clutch.files.yaml`, `check-managed-links` exits 0 and prints one notice line.
- A principles page that links `.agents/skills/verify/SKILL.md` fails `check-managed-links` in Clutch.
- `web-app.test.ts` passes whatever dev names `tools/dev.ts` gives, and still checks the web app is selected.
- No managed Markdown file links a `docs/contributing/decisions/0…` file by repo path.

## Verify

- `mise exec -- bun test tools/check-managed-links.test.ts tools/journeys/web-app.test.ts`
- `mise exec -- bun run validate`
