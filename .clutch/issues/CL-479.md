# CL-479: Stop the app when a native journey run ends

## Goal

The native journey runner stops the app that it launched. It does this on success and on failure.

## Context

- On 2026-11-12 a native journey run left the Clutch app running in the iOS simulator.
- After the dev server stopped, the app used about 90% of a processor core for five hours.
- Two `diagnosticd` processes stayed at the same level.
- The CLI test suite then took 72 seconds against its 60 second budget. So `validate` and the pre-push hook failed.
- The runner is in `tools/journeys/native.ts`. The native tools are in `tools/native/`.

## Steps

1. Branch `clutch/cl-479-stop-app-after-journey`.
2. Find out first: which function in `tools/journeys/native.ts` or `tools/native/` launches the app.
3. Stop the launched app when the run ends. Do this on success and on failure.
4. Stop only the app that the runner launched. Do not stop other apps.
5. Add tests for a passing run and for a failing run.
6. Do not raise the 60 second budget. Do not use a timer as a wait.

## Files

- `tools/journeys/native.ts`, `tools/journeys/native.test.ts`
- `tools/native/`

## Acceptance criteria

- After a failing native run, the launched app is not running.
- After a passing native run, the launched app is not running.
- The runner stops no app that it did not launch.

## Verify

- `mise exec -- bun test tools/journeys`
- `mise exec -- bun run validate`
- Only the owner boots a device. Ask the owner to check one native run on a device.
