# CL-236: Let a pure Clutch sync merge past owner findings the owner approved upstream

## Goal

A Clutch sync PR in a project merges at the step `bots` even when agent review leaves it an `owner` finding that the owner already approved in Clutch. Every other PR keeps its owner findings.

## Context

- Each Clutch release that changes a gate reaches each project as a sync PR. Agent review in the project raises the change again as an `owner` finding, which holds the PR, so each gate change costs one owner approval per project. Neighborhood #53 had 5 such findings, all already approved in Clutch.
- Decision 0003 records the rule. It amends 0002 for projects.
- `clutch / doctor` is not in `.github/rulesets/main.json`, and projects get that ruleset as a managed file, so no ruleset requires it. The rule reads its conclusion itself.

## Steps

1. `tools/github/auto-merge-rules.ts`: `approvedUpstream` is true for a `clutch-sync` PR whose author is a bot, whose `botProblems` is empty and whose `doctor` is `success`. `blockers` skips the owner findings when it is true, and `verdictText` lists them under "Owner findings, approved upstream in Clutch:".
2. `tools/github/auto-merge.ts`: read the `clutch / doctor` conclusion on the head with the other check runs, and keep it out of `checks`, so it never becomes a required check.
3. `tools/github/auto-merge-checks.ts` (new): `checkConclusions` and `actionsApp` moved here unchanged, to keep `auto-merge.ts` within its line budget. It joins the one-way-door tier, and `.github/CODEOWNERS` is regenerated.
4. `tools/github/auto-merge-sync.test.ts` (new): the cases in the PR body.
5. Docs: decision 0003, the steering list and the status of 0002, `pull-requests.md#auto-merge`, and the sync rule's header in `bot-rule.ts`.

## Acceptance criteria

- A pure sync (release bot, `clutch-sync/` branch, sync rule passes, `clutch / doctor` succeeded on the head) with an owner finding merges at the step `bots`, and its verdict lists the finding under the upstream heading.
- The same sync with the doctor check missing, pending or failed is held by its owner finding.
- A sync with a file that `clutch sync` does not write is held by its owner finding, with doctor success.
- An agent PR, or a Renovate or gardening PR, with an owner finding is held as before.
- A failed required check still holds a pure sync.
- The auto-merge files stay within the 400-line budget.
