# CL-222: Mark the issue done in the PR head, before auto-merge

## Goal

`pr open` marks the branch's issue `done` in the PR head before it pushes, so
the merged default branch says `done` even when auto-merge merges on the first
green head.

## Context

The flow ran `pr ready` after the first green push. With auto-merge at step
`medium`, GitHub can merge on that first green head, before `pr ready` pushes.
PR #164 merged at `74e0b32`, and its `done` commit `9ac45c6` never reached
`main`, so `main` still said CL-221 was `in_progress`. The rule must not depend
on timing. A PR that closes unmerged leaves its issue at `done` until the next
session sets it back to `todo`.

## Steps

1. `pr open` finds the issue from the branch prefix (`pr.branchPrefix`) and,
   when it is not `done` with the PR link, commits only its issue file as
   `chore(tracker): mark <id> done` before the push.
2. `pr ready` adds the PR link, or re-marks the issue. It makes no commit when
   the issue already says `done` with that link.
3. The deliver docs and `.clutch/README.md` describe the new order.

## Acceptance criteria

- `open` on `clutch/cl-123-x` with an `in_progress` issue commits the done
  change before its push.
- `open` on an issue that is already `done` with the PR link makes no commit.
- `open` on a branch with no issue id makes no tracker call and no commit.
- `ready` on an issue already `done` with the link makes no commit and no push.
- CL-221 on `main` is `done` with its PR link.
