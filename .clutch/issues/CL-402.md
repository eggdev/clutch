# CL-402: Add merge_group triggers to required workflows

## Goal

The required workflows run in a merge queue.

## Steps

1. Branch `clutch/cl-402-merge-group`.
2. Add `merge_group:` to `on:` in `ci.yml` and `agent-review.yml`. CL-102 adds it to `codeql.yml`, so this issue does not touch that file.
3. In `agent-review.yml`:
   - The job condition `github.event.pull_request.draft == false` is false on `merge_group`, because there is no PR. Change it to `github.event_name == 'pull_request' && github.event.pull_request.draft == false`.
   - Add a `merge_group` path that exits 0 with a notice, so the required name `agent-review` still reports. The review already ran on the PR.
   - The concurrency group uses `github.event.pull_request.number`, which is empty on `merge_group`. Every queue entry would then share one group with `cancel-in-progress: true`, and each run would cancel the others. Key the group on `github.event.merge_group.head_sha` for queue runs.
4. Add `required_checks` (a list of job names) to the `clutch.yaml` schema. `check-workflows` runs offline, so it cannot read the ruleset probe in `apps/cli/src/doctor/remote.ts`, which needs `--remote`.
5. Add a `check-workflows` rule: a workflow whose job name is in `required_checks` must have `merge_group`.

## Acceptance criteria

- `check-workflows` passes and fails on a fixture without `merge_group`.
- A `merge_group` run of agent review exits 0 and does not cancel another queue entry.

## Verify

```bash
rg -n "merge_group" .github/workflows
mise exec -- bun nx run check-workflows
```
