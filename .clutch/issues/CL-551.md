# CL-551: Fail a window or a matchMedia that a wrapper hides from the layout rule

## Goal

A type cast, a non-null mark or `.bind` does not hide a window or a `matchMedia` from the rule `repo-layout/no-viewport-reads`.

## Context

CL-550 made the rule fail a `matchMedia` or a window under a local name, and it merged when its checks passed. Agent review then found that a wrapper hides the name. `const view = window as Window` passes, and so do `window.matchMedia as typeof matchMedia` and `window.matchMedia.bind(window)`. The parser is TypeScript, so each wrapper is a node of its own between the name and the declaration.

Lint follows no value through a call, an object or an array. So the docs must say where the rule stops, and review holds the rest.

## Steps

1. Branch `clutch/cl-551-viewport-wrappers`.
2. Look through `as`, `satisfies`, `!`, an angle-bracket cast and parentheses before each test of the rule.
3. Fail a member of `matchMedia`, such as `.bind`.
4. Say in `docs/contributing/setup/lint-rules.md` that the rule sees a direct name only.

## Files

- `tools/lint/layout-policy.mjs`, `tools/lint/layout-policy.test.ts`
- `docs/contributing/setup/lint-rules.md`

## Acceptance criteria

- `window as Window`, `window!`, `window.matchMedia as typeof matchMedia` and `window.matchMedia.bind(window)` each fail lint when code gives them a name.
- `(window as Window).innerWidth` fails as a width read.
- No existing code breaks the rule.
