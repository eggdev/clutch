# CL-017: Add a reusable doctor workflow for downstream repos

## Goal

Neighborhood and Bar Savvy run `clutch doctor --check` (and `sync --check` in sync mode) from the Clutch commit pinned in their `clutch.yaml`, with one `uses:` line.

## Steps

1. Branch `clutch/cl-017-reusable-doctor`.
2. Add `.github/workflows/clutch-doctor.yml` with `on: workflow_call` (input `root`, default `.`) and a top-level `permissions: { contents: read }`, because `check-workflows` requires a top-level permissions block and bans `pull_request_target`. The steps:
   1. Check out the caller with `persist-credentials: false`.
   2. Read `template.repo` and `template.commit` from `clutch.yaml` with `yq` or a bun one-liner.
   3. Check out Clutch at that commit into `$RUNNER_TEMP/clutch` (public repo, no token).
   4. Run `jdx/mise-action` in the Clutch folder, then `bun install --frozen-lockfile` there.
   5. Run `bun $RUNNER_TEMP/clutch/apps/cli/src/main.ts doctor --check --root $GITHUB_WORKSPACE`, then `sync --check` when `template.mode` is `sync`.
3. Pin each action the way `ci.yml` does today. CL-103 moves all of them to SHAs.
4. Add a short "Use Clutch in another repository" section to `apps/cli/README.md` with the caller snippet:
   ```yaml
   jobs:
     clutch:
       uses: eggdev/clutch/.github/workflows/clutch-doctor.yml@<commit>
   ```
5. Test it from a scratch branch in this repo with a caller workflow that runs on `workflow_dispatch`. Remove the scratch caller before review.

## Files

- add `.github/workflows/clutch-doctor.yml`
- edit `apps/cli/README.md`

## Acceptance criteria

- `check-workflows` passes.
- A `workflow_dispatch` run on the scratch branch is green and its log shows the doctor summary.

## Verify

```bash
mise exec -- bun nx run check-workflows
gh workflow run <scratch-caller>.yml --ref clutch/cl-017-reusable-doctor && gh run watch
```
