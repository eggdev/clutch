# CL-516: Link each agent file to the docs it must read

## Goal

Each agent file names the docs that the agent must read, and the check fails when a named doc is missing. A project whose docs do not follow Clutch's layout then fails the check. Layer 01 "Done when": the Neighborhood `implement` agent links to the docs it must read (CL-611).

## Context

- Layer 01 of the factory stack. Read the Design section of CL-514.
- Clutch's docs layout: `AGENTS.md`, `docs/contributing/index.md`, `docs/contributing/project-intent.md`, `docs/principles/`, `docs/contributing/architecture/`, `docs/contributing/testing.md`, `docs/contributing/review.md` and `.clutch/README.md`.

## Design (coordinator defaults, 2026-11-04)

- Add an optional `reads` key to `agent.md`: a list of paths from the project root. Each path must exist. Addition versus stack.md.
- The prompt body links the same docs as Markdown links, so a person who reads the file can follow them. The check fails when a `reads` path has no link in the body.
- Each starter agent names the smallest set of docs its stage needs. `implement` reads the architecture index, testing and the deliver skill. `review` reads `docs/contributing/review.md`.

## Steps

1. Branch `clutch/cl-516-agent-reads`.
2. Add `reads` to the CL-514 schema and to the schema page, with tests for a missing path and a missing link.
3. Add `reads` to each agent in `factory/agents/`.
4. Name the layout on the `factory_as_code` capability page.

## Files

- `apps/cli/src/factory/` and its tests
- `factory/agents/*/agent.md`
- `docs/contributing/architecture/factory-tree.md`, `docs/contributing/capabilities/factory-as-code.md`

## Acceptance criteria

- `clutch factory --check` fails on an agent with a `reads` path that does not exist, and names the agent and the path.
- Each starter agent has `reads`.
- `mise exec -- bun run validate` passes.

## Verify

```bash
mise exec -- bun run clutch factory --check
grep -A6 '^reads:' factory/agents/implement/agent.md
```
