# CL-133: Check the lockfile's resolved URLs in the bot rule

## Goal

A Renovate PR auto-merges at `step: bots` only when its `bun.lock` change keeps every package on the npm registry.

## Context

CL-132's bot rule lets `bun.lock` change in any way. CI's `bun install --frozen-lockfile` confirms that the lockfile matches the `package.json` versions, but not its resolved URLs or integrity hashes. So a Renovate PR could point a package at another source without changing a version. Agent review raised this on #92.

## Steps

1. Branch `clutch/cl-133-lockfile-urls`.
2. In `tools/github/bot-rule.ts`, check each added `bun.lock` line that names a tarball: its URL must start with `https://registry.npmjs.org/`.
3. Add a negative test: a changed resolved URL to another host fails.

## Files

- `tools/github/bot-rule.ts`, `tools/github/bot-rule.test.ts`.

## Acceptance criteria

- A Renovate PR whose `bun.lock` points a package at another host fails the bot rule.

## Verify

```bash
mise exec -- bun test tools/github/bot-rule.test.ts
```
