# CL-493: Make doctor compare the live ruleset with the ruleset file

## Goal

`clutch doctor` fails when the ruleset on GitHub is weaker than `.github/rulesets/main.json`.

## Context

- The council review of 2026-11-13 found this gap at head `8563977b`. The owner approved the fix on 2026-11-14.
- The merge judge reads the required checks from the ruleset on GitHub, in `tools/github/main-checks.ts`.
- `protected_main` in `apps/cli/src/doctor/remote.ts` passes when the ruleset asks for pull requests and for the `validate` check. It does not look for `journeys`, `secrets`, `commits` or `sast`.
- So a project whose ruleset on GitHub lacks `journeys` merges with no proof, and no command reports it.
- `clutch ruleset` already compares GitHub with the file. CL-481 applies the file to GitHub. This issue only reports the difference.

## Steps

1. Branch `clutch/cl-493-doctor-ruleset`.
2. Find out first: what `apps/cli/src/ruleset-command.ts` compares, and how to use the same comparison from `doctor`.
3. Make `protected_main` fail when the ruleset on GitHub lacks a required check of the file, does not ask for a code owner's review when the file does, or has a bypass actor that the file does not name.
4. The message names each difference and the command that fixes it.
5. Keep the result `unknown` when the session cannot read the ruleset.
6. Update the doctor rule table in the docs.

## Files

- `apps/cli/src/doctor/remote.ts`
- The test file of the remote doctor rules. Find out first: its name.
- `apps/cli/src/ruleset-command.ts` and `apps/cli/src/ruleset/`
- The docs page with the doctor rule table. Find out first: its name.

## Acceptance criteria

- A test with a ruleset that lacks `journeys` fails `protected_main`, and the message names `journeys`.
- A test with a ruleset that has an extra bypass actor fails.
- A test with a ruleset that matches the file passes.
- `mise exec -- bun run clutch doctor --remote` passes in this repository.
