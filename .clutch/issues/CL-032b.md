# CL-032b: Release on each merge to main, and give each project a fresh changelog

## Goal

A merge to `main` with pending changesets bumps the version, writes `CHANGELOG.md` in a bot commit, tags `vX.Y.Z` and publishes a GitHub release. A project gets its own empty changelog and releases under its own package name.

## Steps

1. Changesets name the root package from `package.json`, not the fixed name `clutch`.
2. `tools/release/release.ts` runs the release and writes the version and the notes for the workflow.
3. `.github/workflows/release.yml` runs on each push to `main`.
4. `clutch.files.yaml` excludes `CHANGELOG.md` and pending changesets. It seeds `.changeset/README.md`. Install and init write a fresh `CHANGELOG.md`.
5. Tests and docs.

## Acceptance criteria

- A fresh install has a `CHANGELOG.md` with no Clutch entries.
- validate passes.
