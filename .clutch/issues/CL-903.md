# CL-903: Migrate the PGlite test database once per process

## Goal

Cut about 15 s of test time. Each PGlite test currently builds a fresh database and runs every migration, about 0.7 s per test (CL-029).

## Context

It is the cause of 9 of the 18 slow test files: event-log, feed, job-runner, access, notes-commands, count-notes, server, spaces and jobs.

## Steps

1. In `DatabaseTest` (`packages/sync/testing/database.ts`), migrate one PGlite database per process. Clone it for each test, for example with `dumpDataDir` and `loadDataDir`.
2. Keep every test.

## Acceptance criteria

- The nine files run at least 10 s faster in total.
- validate passes.
