# CL-610: Take one Neighborhood issue through all 5 stages in one lane run

## Goal

Prove layer 05 in Neighborhood: one real Neighborhood issue passes through `triage`, `spec`, `implement`, `review` and `verify` in one lane run, and merges.

## Context

- CL-314 adds the 5 stage agents, the hand-off contract and `clutch agent run`.
- Pick a small issue from Neighborhood's real backlog for the week. The work happens in `~/dev/neighborhood` under its `AGENTS.md` and merge rules.
- Neighborhood's alpha (Fri 2026-11-06) wins over this issue when they compete for a lane. A small alpha issue is a good pick, when its owner agrees.

## Steps

1. Sync Neighborhood to the release that carries CL-314, by its rules.
2. Run the 5 stages on one issue in one lane. Record each stage's marker and the time it took.
3. Merge under Neighborhood's rules. Write in this issue what each stage got wrong, and file a Clutch issue for each fix to an agent file.

## Acceptance criteria

- One merged Neighborhood PR shows a `clutch-stage` marker for each of the 5 stages.

## Verify

```bash
gh pr view <n> -R eggdev/neighborhood --comments | grep clutch-stage
```
