# CL-438: Move scheduled maintenance into task flows and T3 schedules

## Goal

No GitHub workflow runs on a cron. Maintenance either runs inside the task flow that meets it, or as a T3 scheduled session that a project registers.

## Context

Brendan, 2026-11-06: fold what a task meets into the task flow, and run the rest as T3 scheduled sessions.

- Flake hunt: babysit-pr quarantines a test that fails and then passes on the same commit.
- Clutch sync: the task start checks whether the project is behind the template, and the session opens the sync PR.
- Renovate, the security agent, gardening and the weekly digest: T3 scheduled sessions, listed in one file in the repository.

## Steps

1. Add the flaky-test quarantine step to babysit-pr, with a command that quarantines one test on its own branch.
2. Add `clutch sync --pr`, and run the behind check at task start.
3. List the schedules in one file, and add the steps that register them with T3.
4. Delete the cron workflows. Keep `renovate.yml` for a T3 dispatch.
5. Update the docs and the capability registry.

## Acceptance criteria

- No workflow in `.github/workflows/` has a `schedule` trigger.
- Each schedule has one entry in the schedules file, and kickoff registers it.
- `bun run validate` passes.

## Verify

`mise exec -- bun run validate`.
