# CL-470: Try the build service of Expo for the native build

## Goal

Know whether the build service of Expo can make the simulator build, so the repository does not build native code in CI or on each machine.

## Context

- The owner said on 2026-11-12 that the project should try to hand the native build to Expo, because it uses Expo for much else.
- The repository already keys a build by the native fingerprint (`@expo/fingerprint`). The build service of Expo can also key a build by a fingerprint.
- A trial needs an Expo account and a token, which the owner provides.

## Steps

1. Branch `clutch/cl-470-expo-build-service`.
2. Read the current docs of the service for a simulator build, for a build that is found again by its fingerprint, and for the cost of each build.
3. With the owner's token, make one simulator build of `apps/app` on the service, and run the iOS journey on it.
4. Write a decision record: the time, the cost, what the device host would call, and what a project needs at kickoff.

## Files

- `docs/contributing/decisions/`, `tools/native/device-host.ts`
- `apps/app/eas.json` (new, when the trial needs it)

## Acceptance criteria

- A decision record states adopt or not, with the measured time and cost of one build.
- No token is in the repository.

## Verify

- `mise exec -- bun run validate`
