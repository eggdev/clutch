# CL-109: Label each pull request with its kind, area and risk

## Goal

Every pull request carries labels that machines route on: `kind/*`, `area/*` and `risk/*`.

## Context

In the 2026-10-30 research over 58 repositories (see `.clutch/PLAN.md`), labels per merged PR were the strongest PR-level link to velocity. Fast repositories carry about two labels per PR, and the rest carry none. Labels feed risk tiers (CL-403), auto-merge (CL-404), release notes and metrics (CL-503). `docs/contributing/review.md` relies on a `one-way-door` label that nothing creates today.

## Steps

1. Branch `clutch/cl-109-labels`.
2. Add `.github/labels.yml` with the label set: `kind/<conventional type>`, `area/<top folder>` and `risk/low|medium|one-way-door`. A workflow creates missing labels with `gh label create --force`.
3. Add `.github/workflows/labels.yml` on `pull_request`. It sets `kind/*` from the PR title type, `area/*` from the changed paths, and `one-way-door` from the guardrail patterns in `tools/guardrail-files.json`. CL-403 later replaces the risk part with `clutch risk`.
4. Keep the job read-only apart from labels (`pull-requests: write`).
5. Document the labels in `docs/contributing/review.md`.

## Files

- `.github/labels.yml`, `.github/workflows/labels.yml`
- `docs/contributing/review.md`

## Acceptance criteria

- This PR gets a `kind/*` and an `area/*` label from the workflow.
- A PR that touches a guardrail file gets `one-way-door`.

## Verify

```sh
gh pr view <this PR> --json labels
```
