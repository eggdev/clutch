# CL-110: Revert a merged pull request with one label

## Goal

A person or an agent reverts a merged PR by adding the `revert` label, and a bot opens and lands the revert PR.

## Context

In the 2026-10-30 research over 58 repositories (see `.clutch/PLAN.md`), ClickHouse and Sentry run revert bots. Reverts are rare in fast repositories (about 0.24% of commits), so a cheap revert is the safety valve that makes auto-merge (CL-405) safe.

## Steps

1. Branch `clutch/cl-110-revert`.
2. Add `.github/workflows/revert.yml` on `pull_request` `labeled` with the label `revert`, for merged PRs only.
3. It runs `git revert -m 1 <merge commit>` on a `revert/<number>` branch, and opens a PR titled `revert: <original title>` that links the original. It uses the release bot token (CL-039), so CI runs on it.
4. It adds a friction entry for the revert once CL-306 exists. Until then it comments the reason request on the original PR.
5. Document it in `docs/contributing/operations/rollback.md`.

## Files

- `.github/workflows/revert.yml`
- `docs/contributing/operations/rollback.md`

## Acceptance criteria

- Labelling a merged test PR `revert` opens a revert PR whose CI runs.
- The revert PR passes `commits` (its title is a conventional `revert:`).

## Verify

```sh
gh pr list --head revert/ --state all
```
