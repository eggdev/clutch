# CL-521: Give agents a driver over the object pool, and one verify report

## Goal

An agent reads the state of the running app and runs a command by name on any client, and one command reports whether a change is done.

## Context

Exact drives every host with ten operations and one `verify` report. Clutch has journeys, a separate verify runner and screenshot baselines that only CI can compare. See `docs/contributing/architecture/contract.md`.

Built so far, with no test-only code in the app:

- A journey reads the object pool of a web page from IndexedDB: `poolState`, `records` and `settled` in `packages/journeys/testing/pool.ts`.
- A journey runs a command through its agent tool, as the same person: `callTool` in `packages/journeys/testing/tools.ts`. The call takes the server path, not the pool of a client.
- `screenProblems` and `atLargestText` in `packages/journeys/testing/screen.ts` report three layout problems, as shown and at 200% text: a page that scrolls sideways, clipped text, and text past the right edge.
- `mise exec -- bun run verify` runs the journeys and prints one report, from `tools/journeys/verify.ts`.

Still open:

- No driver runs a command on the pool of a client. That needs a seam in the app, which `docs/principles/no-invasive-test-only-code.md` limits.
- The pool reader knows the storage layout of the template engine. A project with another engine needs its own reader.
- The screen checks do not cover overlap, small touch targets, contrast or the dark scheme.
- A screen finding does not fail the report. The notes page has two findings on the phone at the largest text size, and the design work owns that fix.

## Steps

1. Decide the seam for a client-side `run`, in a decision record, or drop it from the goal.
2. Add the overlap, touch target and contrast checks, and run each check in both schemes.
3. Fix the two findings on the notes page, then make a finding fail the report.

## Files

- `packages/journeys/testing/pool.ts`, `packages/journeys/testing/tools.ts`, `packages/journeys/testing/screen.ts`
- `tools/journeys/verify.ts`, `package.json`

## Acceptance criteria

- A journey reads a record from the pool and asserts on it. `features/notes/journeys/notes-sync.journey.ts` does.
- `bun run verify` prints one report for the notes feature and exits 0 on this repository.
- A screen that clips text at the largest text size fails the report, and the line names the element. This one is open.
