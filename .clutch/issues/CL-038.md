# CL-038: Make doctor prove that a review or gardening agent can run

## Goal

`clutch doctor` never reports a capability as present from config files alone when the capability needs a credential or an app to run.

## Context

The P0 audit on 2026-10-30 found `ai_review_bot` and `gardener_bots` adopted and present while the repository had no Anthropic secret. Agent review passed with a notice and gardening never ran. Two smaller false signals: `ai_review_blocking` was partial because a comment says "blocking", and a `yaml` rule counted an empty value such as `ratchets: {}`.

## Steps

1. Detection: a capability is partial only when a rule fails. When its files pass and only remote rules are left, it is unknown without `--remote`.
2. Remote probes: `actions_secret:A|B` reads the Actions secret names, and `bot_review:a|b` reads reviews and comments on the 10 latest pull requests. Both send only GET requests.
3. Registry: `ai_review_bot` needs the Claude credential or a Bugbot or CodeRabbit comment. `gardener_bots` needs the Claude credential, and its schedule and action must be in one workflow. `ai_review_blocking` greps for the `.blocking` result check. A `yaml` rule needs a value that is not empty.
4. Update the capability docs, the CLI README and the tests.

## Files

- `apps/cli/src/doctor/detect.ts`, `rules.ts`, `remote.ts` and their tests, `seed.test.ts`
- `docs/contributing/capabilities/registry.yaml`, `ai-review-bot.md`, `gardener-bots.md`
- `apps/cli/README.md`

## Acceptance criteria

- `clutch doctor` reports `ai_review_bot` and `gardener_bots` as unknown.
- `clutch doctor --remote` reports both as present while the Anthropic secret exists, and partial without it.
- `doctor --check` passes.
