# CL-025: Give projects a working clutch command for the tracker

## Goal

A project that comes from Clutch can run `clutch issues` on its own `.clutch/issues/`.

## Context

- The root `package.json` script `clutch` runs `bun apps/cli/src/main.ts`. The full install merges `package.json` into the project, but it does not copy `apps/cli/`. So `bun run clutch` fails in a project.
- `.agents/skills/deliver/references/task-records.md` (CL-004) tells a project to run `mise exec -- bun run clutch issues --write`.
- CL-013 to CL-017 decide how a project runs the Clutch CLI (sync, init, the reusable workflow). This issue picks the same path for the tracker commands.

## Steps

1. Choose how a project runs the CLI: a pinned package, a pinned clone, or the reusable workflow path from CL-017. Ask Brendan in the PR when the choice is not clear.
2. Keep the `clutch` script out of the `package.json` merge until a project can run it.
3. Make `task-records.md` name a command that works in a project.

## Acceptance criteria

- In a project made by `clutch install`, the tracker command that `task-records.md` names runs.
- validate passes.

## Blocked

Waits on CL-902, Brendan's decision on how much `clutch` drives and whether it is installed per machine or pinned per repository. The way a project runs `clutch issues` follows from that choice. (2026-10-30)
