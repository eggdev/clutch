# CL-452: Hold only lossy SQL, and shrink the hard core

## Goal

The owner sees a migration only when it can lose data. Policy docs and decision records no longer wait for the owner.

## Context

Council review, 2026-11-08: `.clutch/risk.yaml` held every migration, and no code could tell a dropped table from a tweak. The owner said: "Mundane things that tweak a migration file is fine. Something that's going to delete a table is not."

## Steps

1. Replace the migrations path rule with a `lines` rule for SQL that drops, empties, deletes or retypes data.
2. Make `lines` rules case-insensitive.
3. Take `docs/contributing/review.md`, decision records, `docs/principles/**` and `.clutch/PLAN.md` out of the hard core.
4. Regenerate `.github/CODEOWNERS`.

## Files

- `.clutch/risk.yaml`, `.github/CODEOWNERS`, `apps/cli/src/risk/tiers.ts` and its test

## Acceptance criteria

- `ADD COLUMN` is medium, and `DROP TABLE` is one-way-door, in either case.
- `docs/principles/x.md` is low.
- `bun run validate` passes.

## Verify

`mise exec -- bun run validate`, and `tiers.test.ts` against this repository's risk file.

A move to a new system, or a delete in a script, has no SQL line here. The issue names those at scoping.
