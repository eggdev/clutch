# CL-445: Reach the owner in a T3 thread, never on a PR

## Goal

Each need for the owner is a T3 thread that waits on the owner, with what the owner needs to decide. No step asks the owner through a PR label, a PR comment or a review request. When nothing needs the owner, nothing contacts the owner.

## Context

- Brendan, 2026-11-06: "If there is a feature being built that needs me, it needs to be a T3 thread that contacts me." His flow: see that he is needed, discuss with the agent in the thread, steer, say it is good, and expect the merge when verification passes. "I don't want to have to look at a PR. I want to have to talk to an agent." And: "I don't want to talk to an agent if they have the right information and direction."
- `docs/principles/proof-gates-code.md#reach-the-owner-in-a-t3-thread` (CL-439) states the rule.
- Today the owner is reached on GitHub: `babysit:stuck` and the owner brief in `.agents/skills/babysit-pr/SKILL.md`, exit 3 of `pr merge` (CL-436), the batch approval in `.agents/skills/deliver/references/pull-requests.md`, and the stack approval in `.agents/skills/run-lanes/SKILL.md`.
- CL-915 plans a daily brief. A thread per need replaces it, and a green day sends nothing.

## Steps

1. In `deliver` and `babysit-pr`, make a session that needs the owner ask in its own thread with the question tool, so T3 shows the thread as waiting. Give the question a fixed form: the goal, 2 or 3 options, what each one changes for users, and the pick.
2. On exit 3 of `pr merge`, and on `pr babysit --stuck`, ask in the thread. Keep the `babysit:stuck` label only as state for the next round.
3. When T3 is not available, as in a project whose owner does not run it, fall back to one GitHub issue labelled `needs-owner` for each question, assigned to the owner, in the same fixed form.
4. After the owner says it is good, write the answer into the issue or project intent, then merge on proof. Until CL-441 frees the held paths, give the owner the PR's approve link in the thread as the one GitHub step.
5. Close CL-915 as replaced by this issue.

- No skill tells an agent to reach the owner on a PR.
- A held merge and a stuck PR each leave a T3 thread waiting on the owner, with the question in the fixed form. CL-438 opens the threads for needs with no session.
- A day with no need opens no thread.
- `bun run validate` passes.
