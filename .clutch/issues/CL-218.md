# CL-218: Name the slowest tests, and file an issue with each quarantine

## Goal

Name the slowest tests when the test budget fails, and file one tracker issue for each new quarantine entry.

## Context

`tools/test-budget.ts` fails a run that is over budget and says "make the slowest ones faster", but it never names them. Bun prints per-test times only under `GITHUB_ACTIONS`, so locally an agent cannot see which tests to fix.

A quarantine entry in `tools/flaky-tests.json` needs a tracker issue. The nightly flake hunt already files one issue per new flake with `clutch issues new` and commits it in the same PR, so the quarantine has an owner.

## Steps

1. `tools/test-budget.ts` writes a JUnit report of each `bun test` run to a temporary file, reads the per-test and per-file times, and prints the 10 slowest files and the 10 slowest tests when the budget fails or with `--report`. The budget and its failure are unchanged.
2. The flake hunt titles each issue `Fix the flaky test <file>: <name>`.
3. `docs/contributing/testing.md` and `docs/contributing/setup/checks.md` describe both.

## Files

- `tools/test-budget.ts`, `tools/test-budget.test.ts`
- `tools/flake-hunt.ts`, `tools/flake-hunt.test.ts`
- `docs/contributing/testing.md`, `docs/contributing/setup/checks.md`
- `.changeset/clutch-cl-218-test-feedback.md`

## Acceptance criteria

- A failing budget prints the 10 slowest test files and tests, slowest first, with their times.
- `--report` prints the same list when the run passes.
- The order of the printed list is covered by a test that feeds sample timings.
- The flake hunt titles each new issue with its file and test name, and the issue id goes in the quarantine entry.

## Verify
