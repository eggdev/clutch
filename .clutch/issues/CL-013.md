# CL-013: Add the clutch.files.yaml lineage and the clutch sync and sync --check commands

## Goal

One source-side file list (`clutch.files.yaml`) and one target-side lineage record (`.clutch/lineage.json`) generalize `template.files.yaml`, `review.files.yaml` and `.review/tooling.json`. `clutch sync` updates a downstream repo to the pinned or latest Clutch commit. `clutch sync --check` reports drift.

## Formats

`clutch.files.yaml` (in Clutch):

```yaml
version: 1
files:
  - path: tools/check-suppressions.ts
    rule: managed # managed: hash-tracked, replaced on sync, conflict if edited locally
    capability: suppression_discipline
  - path: package.json
    rule: merge # merge: uses the merge rule of install-template.ts (package.json, settings.json, hooks.json, .gitignore)
  - path: KICKOFF.md
    rule: seed # seed: written once by init, never synced again
retired: [.agents/skills/old-skill/]
exclude: [.agents/skills/verify/, .claude/skills/verify]
```

`.clutch/lineage.json` (in each downstream repo):
`{schemaVersion:1, templateRepo, templateCommit, files:{path: hash}}`. It is a superset of `.review/tooling.json`.

## Steps

1. Branch `clutch/cl-013-sync`.
2. Write `clutch.files.yaml`:
   - Start from `template.files.yaml`: `replace` becomes `managed`, `merge` stays `merge`, `add` becomes `seed` for folders the project owns after install, or `managed` for template tooling.
   - Then add every entry of `review.files.yaml` as `managed`.
   - Tag each tooling path with the capability it serves where one applies.
3. Add `apps/cli/src/sync/source.ts`. It loads the committed file list from the Clutch checkout. Generalize `loadReviewSource`.
4. Add `apps/cli/src/sync-command.ts` with this usage: `clutch sync [--root DIR] [--to <commit>|--latest] [--check] [--json]`.
   - `--check`: exit 0 when the lineage matches the pin and nothing drifts, exit 2 when a sync would change files, exit 1 on a conflict or error.
   - Without `--check`: refuse a dirty managed path. Then write the files, rewrite `.clutch/lineage.json`, set `clutch.yaml` `template.commit` and print the changed files. It never commits. The agent commits on a branch.
   - When `.clutch/lineage.json` is missing and `.review/tooling.json` exists, read the latter as the starting lineage (CL-014 migrates it).
5. Add `clutch.files.yaml` to guardrail files and CODEOWNERS.
6. Tests: a fixture Clutch repo with two commits and a fixture target cover clean sync, local edit conflict, retired removal, merge rule, `--check` codes and the review-tooling migration read.
