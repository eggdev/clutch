# CL-229: Honor a test integrity allow entry only in the change that adds it

## Goal

An entry in `tools/test-integrity-allow.json` covers a dropped test only in the change that adds it or changes its reason. An old entry that nobody deleted stops covering anything.

## Context

- `tools/test-integrity-allow.json` still has CL-122's entry for `tools/github/lifecycle.test.ts`, from Oct 31. The file says to delete the entry after the change merges. Nobody did.
- Entries never expired, so that reason silently covered PR #170, which lowered the file from 19 tests to 15. The check never fired. Agent review caught it and the owner approved it.
- Neighborhood has the same kind of stale entries.

## Steps

1. `tools/check-test-integrity.ts`: read the allow list at the base with `git show <base>:tools/test-integrity-allow.json` (missing means empty). An entry covers a file only when it is new or its reason differs from the base. A stale entry covers nothing, and the error says it predates this change.
2. `tools/check-test-integrity.test.ts`: cover an added entry, an unchanged entry at the base, a changed reason, and a missing allow file at the base.
3. Delete the stale CL-122 entry. Keep `"files": {}`.
4. `docs/contributing/testing.md#test-integrity` and the file's `description`: an entry counts only in the change that adds it.

## Files

- `tools/check-test-integrity.ts`, `tools/check-test-integrity.test.ts`
- `tools/test-integrity-allow.json`
- `docs/contributing/testing.md`
- `.clutch/issues/CL-229.md`

## Acceptance criteria

- A drop covered only by an entry already at the base fails, and the message says the entry predates this change.
- A drop covered by an entry the change adds, or whose reason it changes, passes.
- A missing allow file at the base works.
- The stale CL-122 entry is gone and the check still passes on `main`.

## Verify

- `mise exec -- bun test tools/check-test-integrity.test.ts`
- `mise exec -- bun run validate`
