# CL-517: Name the factory intake label and states in each tracker

## Goal

Each project's tracker states which labels and which states mean "ready for the factory", so C-Suite's intake knows what to pick up. Layer 06 "Done when": Neighborhood's docs name its intake label (CL-611).

## Context

- Layer 06 of the factory stack. C-Suite's GitHub intake turns an issue with the label `factory`, in a registered repository, into a work item. Linear intake comes later.
- Neighborhood also takes Linear work with an `Agent` label (Neighborhood PR #62, N-49).
- `clutch issues next` already picks a `todo` issue with `owner: agent` outside `later`.

## Design (coordinator defaults, 2026-11-04)

- Add `factory.intake` to `clutch.yaml`: `github` (a list of labels, default `[factory]`), `linear` (a list of labels, default empty), and `tracker` (the `.clutch/issues` states that are ready, default `[todo]` with `owner: agent`). `factory.root` becomes optional, so a project can set only `intake`. This is a Clutch setting, so it changes nothing in stack.md's tree format.
- The GitHub default matches C-Suite's `automations/github-intake/automation.md`, which watches the `factory` label.
- `clutch issues next` and the docs read the same setting, so the docs never disagree with the code.
- `.clutch/README.md` gets a short "Ready for the factory" section, which names the labels and the states from `clutch.yaml`. `clutch factory --check` fails when the section and `clutch.yaml` disagree. It runs when the section exists or when `clutch.yaml` sets `factory.intake`, so a project with neither still passes. `--root` skips it.
- Making the `factory` label on GitHub is a step that the project runs. It is not part of this PR or of sync.

## Steps

1. Branch `clutch/cl-517-intake-label`.
2. Add `factory.intake` to the `clutch.yaml` schema and docs, with tests.
3. Add the README section and the check.
4. Set Clutch's own intake in `clutch.yaml`.

## Files

- `apps/cli/src/clutch-config/schema.ts` and its tests
- `.clutch/README.md`, `apps/cli/README.md`, `docs/contributing/capabilities/factory-as-code.md`
- The check, in `tools/` or in `clutch factory --check`

## Acceptance criteria

- `clutch.yaml` in Clutch names its intake labels and states, and `.clutch/README.md` names the same.
- The check fails when they disagree.
- `mise exec -- bun run validate` passes.
