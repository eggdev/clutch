# CL-902: Decide how much of the workflow clutch drives

## Decision

Brendan, 2026-11-01, in the daily brief: "I'm presently not paying much attention, but it can drive most. I'd like to see it be the primary driver I guess."

Clutch is the primary driver of the workflow. A workflow step belongs in a `clutch` command, and reaches each project through the release binary. `package.json` scripts keep the work on the code that CI runs without Clutch: `validate`, `check`, `format`, `dev` and `journey`. The owner hears about what needs them, and not about the rest.

Follow-ups, each in `later` with its trigger: CL-912 (`clutch pr`), CL-913 (a delivery loop from `issues next` to merged), CL-914 (every skill step names a command) and CL-915 (`clutch brief`).

## Goal

Choose which commands belong to `clutch` and which stay `package.json` scripts, from what goes wrong in real sessions (decision by Brendan, 2026-10-29: watch first, decide later).

## Current split

- `package.json` scripts work on the repository's code, and CI needs them without `clutch`: `validate`, `check`, `format`, `dev`, `journey`, `native:build`, the hooks and `recap:*`.
- `clutch` handles the workflow around the code: `install`, `init`, `sync`, `doctor`, `issues`.
- `bun run pr` (CL-024) is a script for now. It could become `clutch pr`.
- `clutch` installs per repository: `mise.toml` names `github:eggdev/clutch` (CL-025b), and `tools/clutch.ts` runs it.

## What to watch

Add a note here when one of these happens in a session:

- An agent runs a `gh` or `git` step by hand that a command should do.
- The same command behaves differently in Clutch and in a project.
- A project lacks a command that a skill or doc tells it to run.
- An agent cannot tell whether to use `clutch` or `bun run`.
