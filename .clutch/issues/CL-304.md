# CL-304: Add a flaky-test quarantine registry with expiry

## Goal

A flaky test is quarantined with an owner and an expiry, not deleted or skipped silently.

## Context

- The CL-029 review found flaky tests in `tools/verification/test_verify.py`, the feed, server, jobs, boot-paint and session-queue tests, the CLI detect, init-command and decide tests, and `tools/check-changeset.test.ts`.
- `apps/cli/src/issues/parse.ts` parses issue frontmatter. Use it to read each entry's issue status.

## Steps

1. Branch `clutch/cl-304-flaky`.
2. Add `tools/flaky-tests.json`: `{tests:[{file, name, issue, until}]}`. Add it to `tools/guardrail-files.json` and `.github/CODEOWNERS`.
3. Seed the registry from the CL-029 review. One entry per flaky test:
   - `tools/verification/test_verify.py` goes to CL-107.
   - The feed, server, jobs, boot-paint and session-queue tests go to CL-309.
   - The CLI detect, init-command and decide tests go to CL-310.
   - `tools/check-changeset.test.ts` goes to CL-904.
4. Add `tools/check-flaky-tests.ts` with tests. It takes "today" as a parameter, as `apps/cli/src/doctor/gate.ts` does. It fails on:
   - an expired entry, with a fix message
   - an entry whose issue is missing or `done`
     Add root target `check-flaky-tests` and a `checks.md` row.
5. Quarantined tests run in a separate non-blocking CI step that retries them 3 times and reports.
6. Adopt `flaky_quarantine`.

## Acceptance criteria

- An expired fixture entry fails the check with a fix message.
- An entry whose issue is missing, or `done`, fails the check.
- The seeded registry passes the check.

## Verify

```bash
mise exec -- bun test tools/check-flaky-tests.test.ts
mise exec -- bun nx run check-flaky-tests
```
