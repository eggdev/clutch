# CL-570: Keep a removal from a merge file across syncs

## Goal

A project can remove a key, a list item or a line that Clutch adds to a merge file. Sync does not put it back, and says once when Clutch later changes that item.

## Context

- `clutch.files.yaml` gives the `merge` rule to `package.json`, `.gitignore`, `.gitattributes`, `.claude/settings.json`, `.codex/hooks.json` and `docs/contributing/architecture/primitives.yaml`.
- `merge` in `apps/cli/src/merge-package-json.ts` adds each key that the project lacks (line 26). It joins two lists and keeps the items of both (line 30). The JSON hook files use the same merge.
- `mergeLines` in `apps/cli/src/install-template.ts` adds each line of Clutch's copy that the project lacks (line 39).
- So a project cannot remove an item that Clutch adds. The next sync adds it back.
- `planMerges` in `apps/cli/src/sync/merges.ts` already records a kept value by its id, such as `package.json#scripts.validate`, with a hash of Clutch's value (line 47). A removal can use the same form.
- Neighborhood removed `check-deploy` from `nx.targets.checks.dependsOn` in `package.json`. Each sync put it back.

A **removal** is a merge item that the project removed on purpose. It is a project difference with `kind: removal`, as CL-568 defines.

## Steps

1. Branch `clutch/cl-570-merge-removals`.
2. Give each removal an id in `differences:` of `clutch.yaml`:
   - A key: `package.json#nx.targets.check-deploy`.
   - A list item: `package.json#nx.targets.checks.dependsOn[check-deploy]`. An item that is not a string uses its JSON text in the brackets.
   - A line: `.gitignore#test-output`.
3. Pass the removals to `mergePackageJson` and to `mergeLines`. Each one skips a removed key, list item or line, and does not add it back.
4. Add `--remove <id> --reason "<text>"` to `clutch sync`. It writes the `differences:` entry. Sync refuses an id that matches no item of Clutch's copy.
5. Record in `removed` of `.clutch/lineage.json` the hash of Clutch's value of each removed item, as `kept` records it for a kept value.
6. When that hash changes on a later sync, list the item once in the output and in `--json`. The words are "Clutch changed an item that the project removed". Then record the new hash.
7. When Clutch drops the item, `clutch doctor` says that the entry can go.
8. Extend the tests:
   - `apps/cli/src/merge-package-json.test.ts`: a removed key and a removed list item stay removed.
   - `apps/cli/src/install-template.test.ts`: a removed line stays removed.
   - `apps/cli/src/sync/merge-decisions.test.ts`: `--remove` records the entry, a later sync keeps the removal, and a change to Clutch's value is reported once.
9. Update the "Sync" section of `apps/cli/README.md`.

`docs/contributing/architecture/primitives.yaml` has its own merge, `mergePrimitives`. It is out of scope.

## Acceptance criteria

- A project that removes `check-deploy` from `nx.targets.checks.dependsOn`, and records the removal, keeps it removed through two syncs.
- A removed key of `package.json` and a removed line of `.gitignore` stay removed.
- A change to Clutch's value of a removed item is reported once, and not on the next sync.
- An id that matches no item of Clutch's copy is refused, with the id in the message.
- `mise exec -- bun run validate` passes.
