# CL-406: Lint raw elements that the design system wraps

## Goal

Product code renders the design system's components. A raw `<button>`, `<input>`, `Pressable` or `TextInput` outside `packages/design-system/` fails lint, and the message names the component to use.

## Context

`oxlint.config.ts` said "The design system's Button is the one place that renders `<button>`", and nothing enforced it. Neighborhood renders raw `Pressable` and `TextInput` from `react-native` in product code and gallery files. Sentry (`preferPrimitives`) and Twenty (`no-twenty-ui-override`) enforce the same rule. Supabase ratchets old call sites.

## Steps

1. Add the `repo-components` plugin in `tools/lint/component-policy.mjs`, with one `wrapped` list from raw element to design-system components.
2. Read the design system's exports at lint time. Flag a raw element only when one of its components exists.
3. Exempt the design system, tests and `testing/`. Skip the files that the `design-system-only` ratchet counts, and add `tools/lint/lint-counts.ts` to count them for `clutch ratchet`.
4. Fix the template's own call site: the notes row uses `TextField variant="inline"`.
5. Document the rule and the ratchet in `docs/contributing/setup/lint-rules.md`.

## Files

- add `tools/lint/component-policy.mjs`, `tools/lint/component-policy.test.ts`, `tools/lint/lint-counts.ts`
- edit `oxlint.config.ts`, `packages/design-system/ui/text-field.tsx`, `features/notes/components/note-row.tsx`, `docs/contributing/setup/lint-rules.md`

## Acceptance criteria

- `<button>` and `<input>` outside the design system fail lint in the template, with the component name in the message.
- `View`, `ScrollView`, tests and the design system pass.
- A ratcheted file is skipped by lint and counted by `lint-counts.ts`.
