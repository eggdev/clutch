# CL-136: Keep the release bot key in a release environment that only main deploys to

## Goal

Only a workflow run on `main` can read the release bot's private key.

## Context

- Today `CLUTCH_APP_PRIVATE_KEY` is a repository secret, so any workflow run on any branch of the repository can read it.
- An environment secret reaches only a job that names the environment, and a deployment branch policy limits which refs may run such a job.
- A job that names an environment still reads repository secrets. An environment secret wins over a repository secret with the same name. So the workflows can switch to the environment before the key moves, and releases keep working.
- Secrets cannot be copied. Brendan re-uploads the key to the environment, then removes the repository secret.
- `revert.yml` runs on a `pull_request` event, whose ref is `refs/pull/N/merge`, which a main-only policy refuses. It must dispatch a run on `main` instead. Lane A owns `revert.yml` (CL-110).

## Steps

1. Create the `release` environment with the API, with a deployment branch policy of `main` only. (Done on `eggdev/clutch` on 2026-10-30.)
2. Add `environment: release` to each job that mints the bot token: `release.yml`, `renovate.yml`, `gardening.yml` and `revert.yml`.
3. `revert.yml`: the labeled run dispatches `revert.yml` on the default branch with the PR number. The dispatched run checks the PR and reverts it.
4. Document the setup and the key move in `docs/contributing/setup/releases.md#the-release-bot`.
5. Brendan uploads the key to the environment, then deletes the repository secret.

## Files

- `.github/workflows/{release,renovate,gardening,revert}.yml`
- `docs/contributing/setup/releases.md`, `docs/contributing/setup/ci-credentials.md`

## Acceptance criteria

- Each job that mints the bot token names `environment: release`.
- A release still publishes after the merge, while the key is still a repository secret.
- After Brendan moves the key, a release and a Renovate run mint the token from the environment.
