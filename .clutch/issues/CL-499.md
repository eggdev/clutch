# CL-499: Find or make the native build by its fingerprint on the build machine

## Goal

One command gives an opened pool device the build of this checkout: `AGENT_DEVICE=<path> mise exec -- bun run native:build --platform ios --install`. It finds the build by its native fingerprint, makes it on the build machine when none exists, and installs it.

## Context

An iOS build needs Xcode, so it is made on the build machine, a Mac that this machine reaches over ssh. A leased pool device has no app, so each lease installs the build. Neighborhood proved the method in `tools/dev/simulator-app.ts` and `tools/dev/ios-simulator-build.sh` of its branch `chore/native-checks-on-device-pool`.

Clutch is a public repository, so it holds no machine name. The ssh name of the build machine and its build folder are a setting of the machine, in `~/.config/clutch/build-machine.json`. The project name comes from the root `package.json`.

On 2026-11-21 a trial of the script built `apps/app` of revision `30474e66` on the owner's Mac in 265 seconds, with fingerprint `35473d83`.

## Steps

1. Read the build machine setting: `{ "ssh": "<host>", "root": "<absolute folder>" }`. With no file, refuse and name the file and its two fields.
2. Add `tools/native/ios-simulator-build.sh`. It reads a `git archive` of the head commit on stdin, and writes only under `<root>/<project>/`: `work/`, `cache/`, `artifacts/<fingerprint>/` and `build.lock/`.
3. `native:build --platform ios` computes the fingerprint, then looks in `tmp/native/<fingerprint>/` and in `artifacts/<fingerprint>/` on the build machine. With no build, it makes one, and copies it here.
4. `--install` then installs the app on the opened device through the device host, and records the fingerprint that the device has.
5. Keep `native-fingerprint.json` as the record of the last build, so a review sees a native change. Remove the refusal for a fingerprint that did not change: a new lease needs an install each time. The command writes the record when the fingerprint differs from it.
6. Android stays a refusal with one sentence, until a project has an Android app to prove it with.

## Acceptance criteria

- C1: With no setting file, `native:build` stops before any ssh call and names `~/.config/clutch/build-machine.json`.
- C2: With a build of the fingerprint in `tmp/native/`, the command makes no ssh call.
- C3: With a build on the build machine, the command copies it and makes none.
- C4: A native change that no commit holds stops the command with both fingerprints.
- C5: `--install` with no `AGENT_DEVICE` refuses before any build.
- C6: On a real pool device, `--install` puts the template app on it.
