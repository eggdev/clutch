# CL-121: Fix three gaps in the bun run pr commands

## Goal

`bun run pr open`, `pr sync` and `pr failures` do what they say when an agent's checkout or a PR is not in the plain state.

## Context

Three gaps showed up while lanes used the CL-117 commands on 2026-10-30:

- `pr open` wrote its changeset and ran `git commit`, which also committed anything already staged. Lane A's staged refactor was swept into `chore(changeset): add a … changeset`, and they re-split it by hand.
- `pr sync 85` (CL-401) replayed the commits of its stack base, CL-109, after CL-109 was synced and merged. It stopped on `.clutch/issues/CL-109.md`, and needed a manual `git rebase --onto`.
- `pr failures 79` threw on `gh: HTTP 404` for the log of a cancelled job, and printed nothing about the other checks.

## Steps

1. Branch `clutch/cl-121-pr-gaps`.
2. Commit only the changeset path in `pr open`.
3. Record the fork point of a stacked branch in its git config when `pr open --base` stacks it, and after each `pr sync`. When the base no longer contains the fork point, `pr sync` runs `git rebase --onto origin/<base> <fork point>`.
4. In `pr failures`, report a job log that GitHub cannot return, and go on.

## Files

- `tools/github/pr.ts`, `tools/github/branch.ts`, `tools/github/failures.ts`
- `tools/github/pr.test.ts`, `tools/github/lifecycle.test.ts`

## Acceptance criteria

- The changeset commit names only the changeset path.
- `pr sync` on a branch whose base moved replays only the branch's own commits.
- `pr failures` prints the other failures when one job log is gone.
