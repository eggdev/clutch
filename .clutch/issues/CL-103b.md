# CL-103b: Lint workflows with actionlint and zizmor

## Goal

Catch workflow mistakes that the pin rule does not: actionlint errors and unsafe patterns that zizmor finds.

## Context

`check-workflows` already checks step and job references, `permissions` blocks and `pull_request_target`, and it runs in `checks`. CL-103 adopts `ci_security_lint` once the SHA pins land. This issue adds the two linters on top, so it changes no `clutch.yaml` line.

## Steps

1. Branch `clutch/cl-103b-workflow-lint`.
2. Pin `actionlint` and `zizmor` in `mise.toml`. `mise.toml` is a guardrail file.
3. Add the root target `check-workflow-lint` to `package.json`: `actionlint && zizmor --min-severity medium .github/workflows`. Add it to the `dependsOn` list of the `checks` target.
4. Add a row for `check-workflow-lint` to the checks table in `docs/contributing/setup/checks.md`.
5. Fix every finding, or narrow a permission. Never add an ignore file. Ask Brendan before ignoring anything.
6. Zizmor will likely flag `.github/workflows/release.yml`. Its checkout keeps the credential (no `persist-credentials: false`), and the job then pushes the release commit to main with it. The fix changes how the release pushes, so it is a design choice. Do not change it or ignore it on your own. Ask Brendan in the PR.

## Acceptance criteria

- `actionlint` and `zizmor --min-severity medium` pass, or the `release.yml` finding stays open with Brendan's answer in the PR.
- `check-workflow-lint` is in `checks`.

## Verify

```bash
mise exec -- bun nx run-many -t check-workflows check-workflow-lint
```
