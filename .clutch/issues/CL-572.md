# CL-572: Make the docs review rule name the owning page in a project

## Goal

A reviewer never asks a project to edit a page that Clutch manages. The review rule names the page in the project that owns the behavior.

## Context

- `docs/contributing/review.md` has the review rule "Docs that did not move with behavior" (line 105). The page that owns a module or flow changes in the same PR.
- It does not say what to do when that page is a managed file in the project. A project edit to a managed page is a decision on each sync.
- `docs/principles/index.md` says that a principle page never states a fact about one product. It links to the project page that owns the fact.
- In Neighborhood, a change to the boot script also set a color theme. Agent review named `docs/principles/fast-first-load.md`, a managed page, as the owner. It gave a `blocking` finding on each head.
- `clutch.files.yaml` is Clutch's own file, and sync does not deliver it. In a project, the `files` list of `.clutch/lineage.json` names each managed file.
- `clutch.files.yaml` makes `docs/contributing/review.md` a seed. So a project gets this change as a seed change, which the sync output lists for the owner to port.

## Steps

1. Branch `clutch/cl-572-review-managed-pages`.
2. Add to "Docs that did not move with behavior" in `docs/contributing/review.md`:
   - A page that `files` of `.clutch/lineage.json` lists is managed in this project.
   - When the page that owns a behavior is managed, the owning page is its notes block, as CL-571 defines it. It can also be the project page that the managed page links to.
   - A reviewer does not ask a project to edit the managed text of a managed page. A missing change to the notes block or the linked page is still `blocking`.
3. In `docs/contributing/agent-review.md`, the agent reads the pages that the diff touches. Add that it reads `.clutch/lineage.json` to learn whether a page is managed.
4. Make the rule example concrete. Use the boot script and `docs/principles/fast-first-load.md`.

## Files

- `docs/contributing/review.md`
- `docs/contributing/agent-review.md`

## Acceptance criteria

- The rule says how to find a managed page in a project: through `files` of `.clutch/lineage.json`.
- The rule names the notes block, or the linked project page, as the owning page of a managed page.
- The rule says that a reviewer never asks for an edit to the managed text of a managed page.
- `mise exec -- bun run validate` passes, including `check-sentences` and `check-docs-file-refs`.
