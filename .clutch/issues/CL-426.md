# CL-426: Run a scorer on Qwen on the Spark and record its score

## Goal

A scorer file in the factory tree runs on a Qwen model on the DGX Spark, judges one PR, and records its score where `clutch metrics` and C-Suite can read it. Layer 03 "Done when": a scorer runs on Qwen on the Spark and writes a score.

## Context

- Layer 03 of the factory stack. Read the Design section of CL-514 for the `scorer.md` and runner keys.
- The Spark serves Qwen with the OpenAI API:
  - Ollama: `qwen3.6:latest` at `http://localhost:11434/v1`.
  - llama-swap: `qwen3.8-27b` at `http://127.0.0.1:8092/v1`, with a 32,768-token context. llama-swap loads a model on the first call, so that call is slow.
- Both answered `GET /v1/models` on 2026-11-04. This costs no money.
- Warp's scorers: 1 to 20 labels with a score from 0 to 1, a pass mark, and a sample rate that is 25% by default.
- C-Suite's layer 04 row has a `task-compliance` scorer that judges each lane's PR against its work item. Clutch ships that scorer in the project tree, so C-Suite's scorer sweep can run `clutch score` in each project.

## Design (coordinator notes, 2026-11-04)

These notes replace the first Design defaults. The schema follows C-Suite's `docs/stack.md` on `main`, as CL-514 built it.

- A scorer has `agents`, `judge`, `labels` (`{value, score, description}`), `passingScore` and `samplingRate` (a percent). A scorer has no `runner` or `harness` key. `judge` is an id in `models.yaml`, or a person.
- `models.yaml` gets an optional `base_url` key: the base URL of an OpenAI-compatible server, such as `http://localhost:11434/v1` for `qwen3.6` and `http://127.0.0.1:8092/v1` for `qwen3.8-27b`. The factory check fails on a scorer whose judge has the harness `qwen` and no `base_url`. This replaces the runner `models` map. It is a change versus stack.md, so the PR lists it for C-Suite.
- C-Suite owns `task-compliance`. Clutch ships `factory/scorers/acceptance-criteria/scorer.md`, which judges a PR against the Acceptance criteria of its `.clutch/issues` file, with `agents: [implement]`. Its judge is the Qwen model that the measured results support.
- `clutch score <scorer> --pr <n> [--root DIR] [--repo OWNER/NAME] [--json] [--post] [--sample]` reads the PR title, body, files, diff and its `.clutch/issues` file at the head commit. It sends the judge prompt and the labels to the judge's `base_url`, and asks for JSON: `{ label, reason }`. The score is the label's score. The PR passes when the score is `passingScore` or more.
- `--root DIR` runs a scorer of another tree, so C-Suite can run its own `task-compliance` with `--root /path/to/c-suite`.
- Cut each part of the prompt to fit a 32,768-token context, and say in the prompt what was cut.
- Record each score in two places: print it, and with `--post` add a PR comment with the marker `<!-- clutch-score:<scorer>:<label>:<score>:<head sha> -->`. A project commits no score file, so no PR conflicts on it.
- `--sample` applies `samplingRate` for a sweep. Without it, the command always scores.
- Write no Qwen-only code path. Each model with a `base_url` goes through the same OpenAI client. A `claude` or `codex` judge may come later.

## Steps

1. Branch `clutch/cl-426-qwen-scorer`.
2. Add the `base_url` key to `models.yaml`, and the check rule for a `qwen` judge.
3. Add `factory/scorers/acceptance-criteria/scorer.md`, and `base_url` on the 2 Qwen entries of `factory/models.yaml`.
4. Add `clutch score`, with tests that use a fake OpenAI server.
5. Run it on 3 merged Clutch PRs with each Qwen model. Put the scores, the time per call and the model choice in the PR body.
6. Run C-Suite's `task-compliance` once with `--root` on a merged Clutch PR. Do not post that run.
7. Post one real score on one merged Clutch PR with `--post`.
8. Document the command in `apps/cli/README.md` and in the schema page.

## Acceptance criteria

- `clutch score acceptance-criteria --pr <n>` on the Spark returns a label, a score and a reason from Qwen.
- `clutch score task-compliance --root <c-suite> --pr <n>` runs C-Suite's scorer on a Clutch PR.
- One merged Clutch PR has a score comment with the marker.
- `clutch factory --check` fails on a scorer whose judge has the harness `qwen` and no `base_url`.
- `mise exec -- bun run validate` passes.
