# CL-417: Answer review findings without dropping the owner's approval

## Goal

After the owner approves a PR, the review loop of CL-415 answers new `owner` and `note` findings in the disposition and files them as issues. It does not push a fix, which would dismiss the approval.

## Context

On 2026-11-03 Brendan approved #186 at c1dac43. Lane E then pushed six fix commits for findings from later reviews. Two were real defects (a fail-open skip and an unfenced PR title), and the rest were hardening. Each push dismissed the approval, as the main ruleset requires, so the stack #185/#186 stayed BLOCKED after Brendan merged #181. `pull-requests.md` already said "never push to a PR unless GitHub reports it as DIRTY". The CL-415 step told agents to push again after each review, and nothing tied the two rules together.

## Steps

1. In `babysit-pr` step 7 and in "Answer each finding": after the owner's approval, push only for a `blocking` finding or a `DIRTY` merge state. Answer the rest as `not fixed: after the owner's approval`, and file the fix as an issue.

## Acceptance criteria

- Both pages say when a push after approval is allowed.
