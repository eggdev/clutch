# CL-131: Let clutch sync finish in a fresh project

## Goal

`clutch sync` from the release binary finishes in a fresh project made with `clutch init`.

## Context

CL-120's end-to-end check on 2026-10-30 used v0.13.2 in a scratch repo. The repo had a `package.json` with `oxfmt`, then ran `clutch init --yes` and `clutch sync`. Sync wrote the managed files, then stopped at `Could not format .claude/settings.json: Expected at least one target file. All matched files may have been excluded by ignore rules.` The managed `.oxfmtrc.json` ignores `.claude/**`, and sync formats the merged `.claude/settings.json`. Because sync stopped, `package.json` never got the `pr`, `clutch` and `validate` scripts, and the `.clutch/risk.yaml` seed was never written. A second `clutch sync` refuses, because the managed files are uncommitted.

Two smaller gaps surfaced too:

- `clutch init` in an empty repo needs `oxfmt` installed first, or it fails with `Could not find oxfmt`.
- Nothing tells the user the order: install `oxfmt`, run `init`, run `sync`, run `bun install`.

## Steps

1. Branch `clutch/cl-131-sync-fresh-project`.
2. Format a merged file only when the formatter config does not ignore it, or pass `--no-error-on-unmatched-pattern`.
3. Add a binary end-to-end test: an empty repo, `init`, `sync`, then `bun run pr --help` and `bun run clutch risk` both resolve.
4. Document the bootstrap order in `apps/cli/README.md`.

## Files

- `apps/cli/src/format.ts`, `apps/cli/src/sync/`, `tools/release/binaries.test.ts`, `apps/cli/README.md`.

## Acceptance criteria

- In a fresh project, `clutch sync` exits 0, and `package.json` has the `pr`, `clutch` and `validate` scripts.
