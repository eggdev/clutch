# CL-009: Seed the registry with 36 capabilities

## Goal

Fill `docs/contributing/capabilities/registry.yaml` with the 36 capabilities in Appendix B of the plan. Each entry gets detection rules that reproduce the audited template status.

## Steps

1. Branch `clutch/cl-009-seed-registry`.
2. Copy the entries from Appendix B (or `seed/registry.yaml` in the zip) into the registry. Keep the ids exactly as given. They match the research dataset (`clean/capabilities.csv`).
3. Fill `doc:` paths as `docs/contributing/capabilities/<id with dashes>.md`. The pages land in CL-018 and CL-019, so the doc-path check in the registry validator must accept a missing page until CL-019. Gate it behind a `--strict-docs` flag that CL-019 turns on by default.
4. Add a test `apps/cli/src/doctor/seed.test.ts` that runs `detect` on the template repo root and compares the result to the "Expected on template" column in Appendix B. When a rule disagrees, fix the rule, not the expectation. If the expectation looks wrong, record it in the PR body and ask Brendan there.
5. Validate, open the PR.

## Files

- edit `docs/contributing/capabilities/registry.yaml`
- add `apps/cli/src/doctor/seed.test.ts`

## Acceptance criteria

- The registry has 36 entries with unique ids.
- `seed.test.ts` passes. Every template status equals Appendix B, with remote rules `unknown`.

## Verify

```bash
grep -c '^- id:' docs/contributing/capabilities/registry.yaml   # 36
mise exec -- bun test apps/cli/src/doctor
```
