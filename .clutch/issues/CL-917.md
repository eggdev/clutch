# CL-917: Load a group from a snapshot, and trim the event log

## Goal

The first load of a client and the load of a group cost what the records cost, not what their history costs.

## Context

A council review on 2026-11-20 compared the sync engine with a study of Linear's client. Linear loads a client from a snapshot of the records, and then reads only the changes after the snapshot. Its server can answer that a client is too far behind, and the client then loads again. Our server replays the event log: `backlog` and `backfill` in `packages/sync/service/event-log.ts` read each past event of the groups. Nothing trims `sync_events`. A record that changed 1,000 times travels 1,000 times to each new device, after each dropped saved copy, and after each `ServerBehind` reset.

The protocol can hold a snapshot: a delta that carries the last change of each record is a snapshot. The pool already skips a change that is older than the one it holds.

Trigger: the first project whose first load is slower than its budget, or whose `sync_events` table grows faster than its records.

## Steps

1. Branch `clutch/cl-917-snapshot-and-trim`.
2. Measure the first load and a group load against the size of the log, and set a budget.
3. Serve a load from the last change of each record of a group, with the sync ID that it holds for.
4. Trim events that are older than a kept window. Answer a client that is behind the window with an error that makes it load again, as `ServerBehind` does.
5. Decide if a stale saved copy loads again after a fixed age. Linear uses about 21 days.

## Files

- `packages/sync/repo/events.ts`, `packages/sync/repo/schema.ts`, `packages/sync/service/event-log.ts`, `packages/sync/service/feed.ts`
- `packages/sync/runtime/server.server.ts`, `packages/sync/runtime/transport.ts`, `packages/sync/types/protocol.ts`

## Acceptance criteria

- A group load sends each record once, whatever its history.
- A client that is behind the kept window loads again and keeps its waiting transactions.
- The log stays under a stated size for a stated rate of writes.
