# CL-014: Fold template.files.yaml and .review/tooling.json into the lineage

## Goal

One file list, one lineage record and one sync command. `install` reads `clutch.files.yaml`, `clutch sync --only review` replaces `review install`, and the old files are retired.

## Steps

1. Branch `clutch/cl-014-one-lineage`.
2. Change `apps/cli/src/install-template.ts` to read `clutch.files.yaml` with the same rule mapping, and to write `.clutch/lineage.json` next to `.template-install/manifest.json`. Keep the manifest because the kickoff stages read it.
3. Replace `review install` with `clutch sync --only review`. `--only <capability|path>` limits a sync to entries with that tag. Keep the same exit codes. Remove the `review install` command. Do not keep it as an alias.
   - Port each `review install` test to the sync command with the same assertions, so no test is lost (`check-test-integrity`). If that check still fails, stop and ask Brendan. Do not weaken it.
   - Update every caller: `rg -n --hidden "review install" -g '!.clutch/**'`. This includes docs, skills and `exit codes` references such as CL-011.
4. Delete `template.files.yaml`, `review.files.yaml` and `review-baseline.json` only after every reader moves. Search with `rg -n "template.files.yaml|review.files.yaml|review-baseline"`.
5. `clutch sync` removes `.review/tooling.json` after it writes `.clutch/lineage.json`.
6. Update `apps/cli/README.md` and the docs that name the old files.

## Files

- edit `apps/cli/src/install-template.ts`, `apps/cli/src/review-install.ts`, `apps/cli/src/review-source.ts`, `apps/cli/README.md`, docs that reference the old files
- delete `template.files.yaml`, `review.files.yaml`, `review-baseline.json`

## Acceptance criteria

- `rg` for the three old file names prints only test fixtures or nothing.
- The install flow test in `main.test.ts` passes unchanged.
- `rg -n --hidden "review install" -g '!.clutch/**'` prints nothing, and `clutch review install` exits with an unknown-command error.

## Notes

- 2026-10-29, Brendan decided how install treats files the project already has:
  - A `managed` file with different content is a keep-or-take decision, as in sync.
  - A `seed` file with different content is a keep, take or merge decision. Merge writes both versions into the file with conflict markers, and a person or the kickoff session resolves them.
  - A person answers in a terminal. Without one, install lists the files and exits 2 before it makes the branch. The agent asks the owner and passes `--keep`, `--take` or `--merge`.
- Split: CL-014 moves install to `clutch.files.yaml` and writes the lineage. CL-014b replaces `review install` with `clutch sync --only review`, ports its tests and deletes the old list files.
