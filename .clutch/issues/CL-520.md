# CL-520: Ship each doc that a shipped file links to an existing project

## Goal

A managed or seeded file never names a doc that sync does not bring to an existing project.

## Context

- The starter agents in `factory/agents/` (CL-516) name `docs/contributing/stage-agents.md` in `reads`. That page falls under the `docs/` seed entry, which sync writes only at install. Neighborhood's sync to v0.55.0 failed `clutch factory --check` until the page was ported by hand.
- The managed `agent-review.yml`, `labels.yml` and `tools/journeys/visual-review.ts` link `docs/contributing/agent-review.md` and `review.md#owner-findings`. Neither reached Neighborhood. Agent review blocked Neighborhood PR https://github.com/eggdev/neighborhood/pull/68 until the pages were ported.
- `check-managed-links` checks managed Markdown links and `docs/` paths in workflows. It does not check `reads` paths, comments in tools, or anchors.

## Steps

1. Branch `clutch/cl-520-shipped-doc-links`.
2. Give `docs/contributing/stage-agents.md` and `docs/contributing/agent-review.md` their own seed entries with `add_on_sync: true`.
3. Extend `check-managed-links` to read `reads` in shipped agent files and `docs/` paths in shipped tool comments, with tests.
4. List a new seed page that sync adds in the sync PR body, as `seedChanges` does.

## Files

- `clutch.files.yaml`
- `tools/check-managed-links.ts` and its test
- `apps/cli/README.md`

## Acceptance criteria

- A sync of a project that lacks `stage-agents.md` adds it, and `clutch factory --check` passes after one sync.
- `check-managed-links` fails on a shipped agent whose `reads` names a doc that a project does not get.
- `mise exec -- bun run validate` passes.
