# CL-028: Follow the latest Clutch release instead of a pinned commit

## Goal

A project never pins a Clutch commit. `clutch init`, `clutch sync`, `clutch doctor` and the reusable workflow use the latest Clutch release (decision by Brendan, 2026-10-30).

## Context

- `clutch.yaml` `template.commit` is required today, and it must be a 40-character SHA. `init` writes the checkout HEAD into it. `sync` defaults to it. The reusable workflow checks it out. #34 raised the template's own pin.
- Clutch has no releases yet. "Latest release" needs a release process: tags, GitHub releases, and the way the CLI reaches a project (CL-025).

## Steps

1. Add a release process: a version tag on `main` makes a GitHub release.
2. `clutch.yaml`: drop `template.commit`. Optionally record the release that last synced, for the record only.
3. `init`, `sync`, `doctor` and `clutch-doctor.yml` read the latest release. `sync --to <tag>` stays for a one-off.
4. `.clutch/lineage.json` keeps the release it synced from, so `sync --check` can say "behind the latest release".
5. Update the docs, the README and the template's own `clutch.yaml`.

## Acceptance criteria

- No file asks for a commit SHA.
- `clutch sync --check` in a project compares it with the latest release.
- validate passes.
