# CL-565: The gardening pass writes no changeset and can list the stale proposals

## Goal

A gardening pull request has one changeset, and the pass can run its step for stale design proposals.

## Context

The first full run of the new gardening pass, on 2026-11-17, opened pull request 299. It showed two small defects of CL-554.

The pass runs `validate` to check its own work. In that run `check-changeset` fails, because the workflow writes the changeset in a later step, from the title that the pass returns. The pass fixed that failure in the only way it could: it wrote a changeset of its own. The workflow then wrote a second one. So the release notes get two lines for one change.

The pass could not run step 10. The prompt named the command as `bun tools/check-proposals.ts --stale`. The pass ran it with `mise exec --` in front, as it runs each other command, and the allowed tools did not have that form.

## Steps

1. Branch `clutch/cl-565-gardening-first-run`.
2. Tell the pass that `check-changeset` fails in its run, and that it writes no file in `.changeset/`.
3. Name the proposals command with `mise exec --`, and allow that form.
4. Say the same in the "Weekly gardening" section.

## Files

- `.github/workflows/gardening.yml`
- `docs/contributing/harness-engineering.md`

## Acceptance criteria

- The prompt and the docs page say that the pass writes no changeset.
- The allowed tools have the form of the proposals command that the prompt names.

## Verify

```sh
mise exec -- bun run validate
```
