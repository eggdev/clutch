# CL-535: Report the time of the agent loop, and block on counts only

## Goal

The owner sees when the agent loop gets slower, and no good change fails because a machine was slow.

## Context

Exact tracks its speed budgets on each commit. It blocks on counts and not on timers, because a count cannot fail by chance. Its rules say that nothing blocks on a step slower than 60 seconds, and that the boot graph is "counted, not timed".

Clutch follows this in part. `tools/check-bundle.ts` blocks above 390 modules before the first paint, which is a count. `tools/test-budget.ts` blocks a test target above 60 s. The 60 s budget of `validate --changed` in `tools/validate.ts` only warns, and that is correct. The measured time is 50 s for a small PR on the 4-core runner, so a budget that blocked would fail good changes on a slow machine.

The gap is the record. The full `validate` took 64 s at the median on 2026-10-31, and no report shows that number again. A slower loop shows only as a warning in one run.

## Steps

1. Branch `clutch/cl-535-loop-time-report`.
2. Add the loop times to `clutch metrics`: the median time of the validate step and of the whole CI run over the period, from the run data in the GitHub API.
3. Print the change of each against the period before, and mark a rise of more than 20%.
4. State the rule in `docs/contributing/setup/checks.md`: time is reported, and only a count blocks.

## Files

- `apps/cli/src/metrics-command.ts`, `apps/cli/src/metrics/`
- `docs/contributing/setup/checks.md`

## Acceptance criteria

- `clutch metrics` prints the median time of the validate step and of the CI run for the period, and the change against the period before.
- `checks.md` states that time is reported and that only a count blocks.
- No new check blocks on time.
