# CL-491: Fail a journey that passes only on its retry

## Goal

A journey that fails on its first run fails the `journeys` check. A pass on a second run does not merge a change.

## Context

- The council review of 2026-11-13 found this gap at head `8563977b`. The owner approved the fix on 2026-11-14.
- `tools/journeys/playwright.config.ts` sets `retries: 1`. A journey that fails, then passes, counts as a pass, and the runner files it as a flake.
- So the same commit can get two different verdicts, and a real defect that shows on some runs can merge.
- The nightly flake hunt already runs with `--retries 0` and counts first-run failures (CL-533). A flaky test has its own path: the quarantine in `tools/flaky-tests.json`.
- The production proof in `tools/deploy.ts` also tries twice. It reads a live site over the network, so it stays as it is. This issue does not change it.

## Steps

1. Branch `clutch/cl-491-no-journey-retry`.
2. Find out first: the first-run failures that the flake hunt recorded for each journey. If a journey fails often on its first run, fix its cause in this branch, or stop and report it.
3. Set `retries` to 0 in the Playwright config.
4. Remove the code of the runner that files a pass on the retry as a flake, and its tests. Find out first: where it is, in `tools/journeys/run.ts` and `packages/journeys/testing/test.ts`.
5. Remove `--retries 0` from the flake hunt, when the config makes it the default.
6. Update `docs/contributing/end-to-end-testing.md` and the comment of the config.

## Acceptance criteria

- The Playwright config for journeys has `retries: 0`.
- A test shows that a journey with one failed run fails the run of `bun run journey`.
- No code files a pass on a retry as a flake.
- The `journeys` check passes on the pull request with no retry.
