# CL-322: Add the Chief of Staff conversation of a project

## Goal

The owner talks to one standing thread for each project. It logs tickets, shows the state of the work and fetches anything about a piece of work.

## Context

The Chief of Staff does no real work itself. It is one pinned thread in T3 Code for each project, with the title "Chief of Staff: <project>", and it runs a new `chief-of-staff` skill. The owner reads T3 Code on the phone, so this design sends no push notification.

It may:

- add, hold and release tickets, and show the route and the reason that Triage wrote,
- read the store: `tickets list`, `tickets show`, `tickets ready`, `tickets events`,
- read threads with `t3 thread list` and `t3 thread show`,
- read pull requests and deployments with `gh`,
- report: the inbox, what waits for the owner, what runs, what merged since the last report, and each phase that is `in_progress` while its thread is not running.

It may not:

- change a file, claim a phase or set a phase to `done`,
- merge or close a pull request,
- answer a question that a work thread asked the owner.

Planning threads start from the driver (CL-318), not from the Chief of Staff. So work continues when the Chief of Staff is not running.

## Steps

1. Branch `clutch/cl-322-chief-of-staff`.
2. Write `.agents/skills/chief-of-staff/SKILL.md` with the lists above and the form of the report.
3. Add the skill to the files that Clutch syncs.
4. Document how to start and pin the thread for a project.
5. Hand test: start the thread in Clutch, log 2 tickets through it and ask for a report.

## Files

- `.agents/skills/chief-of-staff/SKILL.md` (new), `.agents/skills/README.md`
- `docs/contributing/` (the page that describes the ticket workflow)

## Acceptance criteria

- The owner says "log this: <bug>" and the thread answers with the ticket id. No work starts in that thread.
- The owner asks "what waits for me?" and the answer lists each phase that is `in_review` or `blocked`, with a link to its thread.
- The owner asks for a ticket by id and gets its thread, its pull requests and its evidence folder.
- `mise exec -- bun run validate` passes with the new skill.

## Verify

- `mise exec -- bun run validate`
- The hand test in step 5.
