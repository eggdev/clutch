# CL-563: Two findings from the reviews of CL-553 and CL-555 are fixed

## Goal

The capability page agrees with the one reviewer of CL-553, and the nightly seed of CL-555 raises no code scanning alert.

## Context

Both findings came after the merge of their pull request.

Agent review gave pull request 291 a `blocking` finding. CL-553 deleted `.cursor/BUGBOT.md`, because the template runs one reviewer. The adopt steps of `docs/contributing/capabilities/ai-review-bot.md` still told a project to add that file next to the review workflow. That reads as a second reviewer. `clutch doctor` still detects the file, because a project may use another review tool in place of the workflow, so the registry stays as it is.

Code scanning gave pull request 289 one alert of the level high. `newSeed` in `tools/claims-hunt.ts` took a random number modulo a limit, which makes some values a little more likely. The seed only picks test inputs, so the bias does no harm, but an open alert of that level hides the next real one.

## Steps

1. Branch `clutch/cl-563-review-follow-ups`.
2. Change step 4 of the adopt steps: one reviewer, tuned through the rules page.
3. Make `newSeed` take its value with a shift, with no modulo.

## Files

- `docs/contributing/capabilities/ai-review-bot.md`
- `tools/claims-hunt.ts`

## Acceptance criteria

- The page does not tell a project to run two reviewers.
- `newSeed` gives a whole number from 1 to 2^31 - 1, and uses no modulo.
