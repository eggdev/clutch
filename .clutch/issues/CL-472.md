# CL-472: List the owner findings of each week in the weekly digest

## Goal

The weekly digest lists each `owner` finding of agent review, so the owner can find a problem after the fact.

## Context

- The owner said on 2026-11-12 that a change which passes its checks should merge with no word from him, and that he pays a problem back after he finds it. See decision record 0005.
- A finding of agent review holds no merge. `pr status` counts the `owner` findings as advisory, and nothing lists them for the owner.
- The babysit read compares a thread's author with the GraphQL login of a bot. GraphQL gives that login without `[bot]`, and the REST API gives it with `[bot]`, so a bot's thread does not match.
- A major change and a contract break still wait for the owner: see CL-463.

## Steps

1. Branch `clutch/cl-472-owner-findings-to-digest`.
2. Write the failing tests first, for the digest script and for the babysit read.
3. Add a script that lists each `owner` finding of the week with its PR and its file, and a step in `weekly-digest.yml` that runs it. When the script fails, the step writes a line into the summary, so the digest of that repository still runs.
4. In the babysit read, add `[bot]` to a bot's GraphQL login, and fix the stale comment in `tools/github/babysit-read.ts`.
5. Add one sentence to `docs/contributing/review.md`: the weekly digest lists the `owner` findings.

## Files

- `.github/workflows/weekly-digest.yml`, `tools/github/owner-reviews.ts` and the new digest script
- `tools/github/babysit-read.ts`
- `docs/contributing/review.md`, `docs/contributing/capabilities/factory-observability.md`

## Acceptance criteria

- The next weekly digest lists each `owner` finding of the week with its PR and its file.
- A failure of the digest script leaves a line in the summary, and the rest of the digest runs.
- A babysit round matches a thread that a bot opened.
