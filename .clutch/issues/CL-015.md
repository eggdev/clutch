# CL-015: Add clutch init

## Goal

`clutch init` adopts Clutch in a repository. It writes `clutch.yaml`, `.clutch/lineage.json`, `.clutch/issues/` and `.clutch/doctor-baseline.json`, then prints the first doctor report.

## Steps

1. Branch `clutch/cl-015-init`.
2. Add `apps/cli/src/init-command.ts` with this usage: `clutch init [--root DIR] [--mode sync|doctor] [--adopt] [--yes]`.
   - It refuses when `clutch.yaml` exists.
   - It writes `clutch.yaml` with `template.repo`, `template.commit` (the current HEAD of the Clutch checkout) and `mode`.
   - `capabilities` starts from detection: present becomes `adopted`. A core gap becomes `waived` with `reason: Decide during adoption.` and no `issue`. The owner must replace each one.
   - `--adopt` (for repos that already hold template files, such as Neighborhood) writes `.clutch/lineage.json` from the current hashes of managed paths. The first `sync --check` then shows real drift, not "unknown".
   - In `mode: doctor` (Bar Savvy) it writes no lineage.
   - It creates `.clutch/issues/` with a README, and an empty TRACKER.md rendered by the issues module.
   - It writes the baseline.
   - It never commits. It prints the next steps: the branch name, `clutch doctor --check` and the files to review.
3. It uses `@clack/prompts` for confirmation unless `--yes` is set, like the install flow.
4. Tests on fixtures for both modes.

## Files

- add `apps/cli/src/init-command.ts` plus test
- edit `apps/cli/src/commands.ts`, `apps/cli/README.md`

## Acceptance criteria

- In a fresh fixture, `clutch init --yes` and then `clutch doctor --check` exits 0.
- In a fixture with an existing `clutch.yaml`, init exits 1 with a clear message.
