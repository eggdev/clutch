# CL-108: Run a daily security agent in every project

## Goal

Each project runs a security agent every day. It triages new vulnerability reports, checks the installed dependencies and the code for known problems, reads the project's logs for signs of abuse, and opens one PR or advisory update with what it found. This loop is what keeps the SECURITY.md promises (acknowledge in 3 business days, critical fix in 30 days) without a person on call (decision by Brendan, 2026-10-30).

## Context

- `.github/workflows/gardening.yml` is the pattern: a scheduled job that finds the Anthropic credential, skips with a notice when there is none, runs the agent with a fixed tool allowlist, and opens one PR with the GitHub App token, so CI runs on it.
- Inputs the agent reads:
  - private vulnerability reports and repository security advisories (`gh api repos/{owner}/{repo}/security-advisories`). CL-106 turns on private vulnerability reporting.
  - code scanning alerts from CodeQL (CL-102) and secret scanning alerts (CL-106).
  - dependency alerts and pending Renovate PRs (CL-104), plus `audit-prod` (`bun audit`, already in `validate`).
  - a full-history `gitleaks git` scan, which CL-101 makes clean with `.gitleaksignore`.
  - the project's logs. Clutch has no log source of its own, so this is a kickoff slot: each project names its source and a read-only command.
- No Anthropic secret is set in eggdev/clutch today, so agent-review and gardening run as no-ops. This loop needs one too.

## Steps

1. Add `.github/workflows/security.yml`: daily schedule and `workflow_dispatch`. Least privilege: `contents: read`, `security-events: read`, plus what the PR step needs. One open security PR at a time, as gardening does.
2. Add the agent prompt as a skill or a reference under `.agents/skills/`, with the triage rules: acknowledge each new report in its advisory within the SECURITY.md window, rate severity, propose a fix PR for each confirmed issue, and never publish an advisory without Brendan.
3. Add a `<!-- kickoff: ... -->` slot to `docs/contributing/security.md` for the log source and its read-only command.
4. Add a capability `security_agent_loop` to `docs/contributing/capabilities/registry.yaml` with a doc page, detected by a workflow that runs the security agent. Update the tests that count capabilities (or land CL-310 first).
5. Adopt it in `clutch.yaml` and run `clutch doctor --write-baseline`.

## Acceptance criteria

- A `workflow_dispatch` run with the secret set triages a test advisory and opens one PR or advisory comment.
- Without the secret, the run ends green with a notice.
- validate passes.

## Notes

- Each project runs this loop. The workflow is managed, so `clutch sync` brings it to every project.
