# CL-595: Give a new project the device pool with no setup

## Goal

An agent in a new project with a native app learns the device pool from the template: the kickoff skill, the verify skill, the hook messages and `clutch doctor` all point to it. No step asks the owner which machine has the simulators.

## Context

Kickoff installs Maestro, asks the owner which machine runs the simulators, and has the agent write a device host by hand. The verify skill says that native flows are refused. The hook messages say "reuse the booted device". CL-498, CL-499 and CL-594 made each of these wrong.

## Steps

1. Kickoff: replace the device host step with a check of the machine setting and a first run on a pool device.
2. Verify skill: say how a native flow runs on a pool device.
3. Hook messages in `tools/agent-hooks/` and `.agents/hooks/`: name the pool as the fix.
4. `clutch doctor`: for a repository with a native app, say when the machine has no build machine setting, and when T3 Code has no device pool.
5. Glossary and the app README.

## Files

- `.agents/skills/kickoff/SKILL.md`, `.agents/skills/verify/SKILL.md`
- `tools/agent-hooks/simulator-tools.ts`, `tools/agent-hooks/guard-dev-servers.ts`, `.agents/hooks/guard-dev-servers.ts`
- `apps/cli/src/doctor/`, `apps/cli/src/doctor-command.ts`
- `docs/contributing/glossary.md`, `apps/app/README.md`

## Acceptance criteria

- C1: The kickoff skill has no step that installs Maestro, asks for the simulator machine or writes a device host.
- C2: Each refusal of the device hook names the device pool and `device_open`.
- C3: `clutch doctor` in a repository with a native app prints one line for the build machine and one for the pool. Neither line fails `doctor --check`.
