# CL-118: Allocate issue ids safely across parallel branches

## Goal

Two parallel branches never file an issue under the same id.

## Context

On 2026-10-30 two lanes both filed CL-113, and CL-114 and CL-115 were renumbered. Each lane picked the next id from its own checkout, which did not see the files on other branches.

## Steps

1. Branch `clutch/cl-118-issue-ids`.
2. Add `clutch issues new --phase <P> --title <title> [--depends ...] [--owner ...] [--range CL-NNN..CL-NNN]`. It fetches origin and takes the next id above the highest one in the phase's range or in `--range`. It counts the files in the working tree, in each local branch and in each `origin/*` branch. It writes the file with `status: todo` and rewrites the tracker.
3. Show that `clutch issues --check` fails when two issue files claim one id.
4. Document it in `.clutch/README.md`.

## Files

- `apps/cli/src/issues/new.ts`, `apps/cli/src/issues-command.ts`, `.clutch/README.md`, `apps/cli/README.md`.

## Acceptance criteria

- `clutch issues new` skips an id that only an `origin/*` branch uses.
- `--range` hands out each id in its block once, then fails.
