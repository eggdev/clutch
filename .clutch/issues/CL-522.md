# CL-522: Write each journey once and run it on web and native

## Goal

A journey is written once, as data, and runs on web and on native with the same outcomes and budgets.

## Context

A web journey is a Playwright file and a native journey is a Maestro file, so one user goal has two scripts, and the budgets hold on web only. Exact compiles one test file to steps that one driver runs on every host.

Built so far:

- A journey in data form is `features/<feature>/journeys/<id>.journey.ts`. Its steps come from the builders in `packages/journeys/testing/steps.ts`.
- The web run registers it as a Playwright test, in `packages/journeys/testing/journey.ts`. `notes-sync` runs in this form on the phone, the tablet and the desktop.
- The native run compiles it to a Maestro flow with `toMaestro` in `tools/journeys/maestro.ts`. A step with no native form needs the `webOnly` mark, or the compile fails.
- `tools/journeys/native.ts` counts the taps before each outcome, and applies the click budget of the web run.

Still open:

- No device has run a compiled flow. `tools/journeys/native.test.ts` proves the native path with a fake device host. The template app `apps/app` builds for iOS, and Maestro reads its flow, but only the owner boots a device.
- A core journey stays a Playwright file, because the core rules in `tools/journeys/core-rules.ts` read its source. So the click budget, which only a core journey has, does not reach a data journey yet.
- The native flow of `notes-sync` leaves out the second device, the axe checks and the pool check. On iOS it stays online.

## Steps

1. Run a compiled flow on an iOS simulator and an Android emulator in a project with a native app.
2. Teach the core rules to read the steps of a data journey, then move one core journey to the data form.

## Files

- `packages/journeys/testing/steps.ts`, `packages/journeys/testing/journey.ts`, `packages/journeys/types/steps.ts`
- `tools/journeys/maestro.ts`, `tools/journeys/native.ts`
- `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- One journey file runs on web and on native. Web is proven. Native is open.
- A native run records each outcome and fails over the click budget. The fake host proves the code, and no core journey uses it yet.
- `check-journeys` accepts the one form for both platforms.
