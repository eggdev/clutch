# CL-546: Move the other checks to the finding type, in batches

## Goal

Each check of `validate` reports its findings as data, so `validate --json` covers every check.

## Context

CL-534 added the finding type in `tools/findings.ts` and `validate --json`. It moved `check-file-size` and `check-contract`. The other checks print free text only, so `validate --json` does not list their findings. `docs/contributing/setup/checks.md#findings` holds the rule and the mechanism.

Move the checks in batches of about five, one PR per batch, so each PR stays small to review. Start with the checks that agents fail most often, such as `check-sentences`, `check-terms` and `check-docs-file-refs`. A check that reads a line gives the line.

## Steps

1. Pick a batch of about five checks that print text only.
2. Return findings from the exported function of each check, with an id as `<check>/<problem>` for each kind of problem.
3. Write the findings with `writeFindings` in the `import.meta.main` block, and print the text with `formatFinding`.
4. Pin each id in the test of the check.
5. Update the list of moved checks in `docs/contributing/setup/checks.md#findings`.
6. Repeat until each check reports findings.

## Files

- `tools/check-*.ts` and their tests
- `docs/contributing/setup/checks.md`

## Acceptance criteria

- `mise exec -- bun run validate --json` lists the findings of each check.
- Each id has a test that pins it.
- The text output and the exit code of each check stay as they are.

## Verify

```sh
mise exec -- bun run validate --json
mise exec -- bun run validate
```
