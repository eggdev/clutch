# CL-585: End the session of an open sync socket when its actor is gone

## Goal

When the identity layer says that the session of an open sync socket ended, the client learns it at once, stops its engine and clears its local database.

## Context

CL-919 (PR #321) made the server close a new sync socket with code 4401 when `Actors.fromHeaders` dies with `SessionEnded` at the upgrade (`trackedWebsocket` in `packages/sync/runtime/server.server.ts`). A client of every build reads a 4401 close as an ended session.

`Pull`, `Push` and `Load` each call `actors.fromHeaders(headers)` again while the socket is open. When the identity layer then dies with `SessionEnded`, and nobody called `Sessions.end`, the call dies with a defect and the socket stays open. The client pulls again every 3 seconds or less, for ever, and the data of the ended session stays on the device.

## Steps

1. Branch `clutch/cl-585-end-open-socket-session`, stacked on CL-584.
2. Write the tests first, over the real socket: an `Actors` layer that names an actor at the upgrade and then dies with `SessionEnded` ends a `Pull` and a `Push` with a 4401 close. Another defect gives no 4401 close.
3. When `fromHeaders` dies with `SessionEnded` inside `Pull`, `Push` or `Load`, close the socket of that call with code 4401. Any other defect stays a server fault.

## Files

- `packages/sync/runtime/server.server.ts`, a new file beside it for the socket of each RPC client
- `apps/api/src/sessions.test.ts`, `apps/api/src/test/socket.ts`
- `docs/contributing/architecture/local-first-sync.md`

## Acceptance criteria

- A `Pull`, a `Push` or a `Load` whose actor dies with `SessionEnded` closes its socket with code 4401.
- Another defect of the actor does not close the socket with code 4401, and the client keeps its data.
- `packages/identity/**` does not change.
