# CL-302: Add clutch ratchet, a shrink-only baseline engine

## Goal

A generic ratchet: count violations per file for a named rule, fail when a count rises against the merge base or the baseline, and fail when a count drops and the baseline was not lowered.

## Steps

1. Branch `clutch/cl-302-ratchet`.
2. Format: `.clutch/ratchets.json` `{schemaVersion:1, ratchets:{<name>:{command|pattern, files: glob, counts:{path: n}}}}`.
   - `pattern` is a regex counted per file.
   - `command` prints `path:count` lines. Use it for oxlint JSON output or tier rules.
3. Add `apps/cli/src/ratchet/*.ts` and `apps/cli/src/ratchet-command.ts`:
   - `clutch ratchet check [--base <ref>]`
   - `clutch ratchet update`, which only lowers counts and refuses a raise
   - `clutch ratchet add <name> --pattern ... --files ...`, which seeds counts
4. Port the semantics of Bar Savvy `.github/scripts/check-lint-suppressions.cjs`, which counts against the merge base. Read it in `blockmen-group/bar-savvy-web` at `epic/refactor`.
5. Add root target `check-ratchets` (to `checks`) and a row in `checks.md`. The template ships `.clutch/ratchets.json` with no entries.
6. Add `.clutch/ratchets.json` to guardrail files and CODEOWNERS. Adopt `ratchets`.

## Acceptance criteria

- Tests cover a raise (fail), a drop without update (exit 2) and a drop with update (pass).
- An update cannot raise a count.

## Verify

mise exec -- bun nx run check-ratchets
