# CL-215: Hold only workflow changes that grant write access or secrets

## Goal

A workflow change holds for the owner only when it grants write access, reaches
a secret or environment, or runs with a privileged trigger. A read-only
`permissions:` block is `medium`.

## Context

The second `one-way-door` rule in `.clutch/risk.yaml` matched any added or
removed line with `permissions:` or a scope set to `read`, `write` or `none`.
Every workflow in this repository declares a least-privilege block, so any
workflow change that touched one was held. Decision 0002 wants the owner to
see credentials and privileged triggers, not read-only blocks.

## Steps

1. Replace the `permissions:` and scope-`read|write|none` line patterns with a
   write-scope pattern and a `write-all|read-all` pattern.
2. Update the rule comment, the risk README section, decision 0002 and the
   deliver PR reference.
3. Add test cases: read-only block is `medium`; write scope, secret and
   `write-all` are `one-way-door`.
4. Replay the last 40 merges under the old and new rules and report the tiers.

## Acceptance criteria

- A workflow adding `permissions:` with `contents: read` is `medium`.
- A workflow adding `contents: write`, `${{ secrets.X }}` or `permissions: write-all`
  is `one-way-door`.
- `bun test apps/cli/src/risk` passes, and the new cases fail under the old rules.
