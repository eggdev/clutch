# CL-907: Require a person's review on each one-way-door path

## Goal

A change to any one-way-door path needs a person's approving review, not only the guardrail files.

## Context

From CL-605. Neighborhood's `one-way-door.yml` fails a PR that changes a migration without the `one-way-door` label. Clutch labels `risk/one-way-door` automatically (CL-403), and auto-merge never takes it (CL-132). The ruleset sets `require_code_owner_review`, but `.github/CODEOWNERS` lists only the guardrail files. So migrations, auth and agent steering need no code owner.

## Steps

1. Add an owner in `.github/CODEOWNERS` for each `one-way-door` glob in `.clutch/risk.yaml`.
2. Extend `check-agent-hooks`, or add a check, that fails when a `one-way-door` glob has no CODEOWNERS line.

## Acceptance criteria

- A PR that changes a migration or auth code asks for a code owner's review.
