# CL-232: Prune the checkouts of merged and closed PRs

## Goal

`clutch worktree prune` removes each checkout whose PR is finished, so a schedule can clear them with no one asking.

## Context

- Nothing removes a checkout when its PR merges. On 2026-11-03, `~/dev/clutch` had 23 extra checkouts, 19 with merged PRs, and Neighborhood had 4 more.
- Most PRs now merge through auto-merge on GitHub, so no local command runs at merge time.
- Some PRs are squash-merged, and GitHub deletes the branch, so `git branch --merged` and the remote-branch check both miss them. The PR's state and head commit from `gh` do not.
- T3 and other tools make checkouts outside `worktree.root`, so prune covers every checkout of the repository.

## Steps

1. `worktree/prune.ts`: decide per checkout, keep or remove, with the reason.
2. `FindPr` also returns the PR's head commit.
3. `clutch worktree prune [--dry-run] [--base REF]` in `worktree-command.ts`.
4. Docs: the CLI README, the worktrees setup page, and the commands table.

## Acceptance criteria

- A clean checkout of a merged PR is removed with its branch, a squash merge with a deleted remote branch included.
- A clean checkout of a closed PR is removed, and its branch is kept.
- It keeps the main checkout, the one it runs in, a detached one, one without a PR, one with an open PR, one with uncommitted changes, and one with commits after its PR.
- `--dry-run` removes nothing. A failed removal is reported, the rest go on, and the exit code is 1.
