# CL-594: Run native journeys through agent-device on a pool device

## Goal

`AGENT_DEVICE=<path> mise exec -- bun run journey --native ios` runs each native journey of the template on an opened pool device, with `agent-device` only.

## Context

The `agent-device` daemon is on the pool machine. It refuses each script step of a flow that it gets over the network, and a screenshot that it takes stays there. The template compiles a `tool` step and a `serverHolds` step to `evalScript` steps that call `http.post`, and a `shot` step to `takeScreenshot`. Neighborhood solved this in `tools/dev/flow-parts.ts`: the runner cuts the flow at each top-level script and screenshot step, sends each stretch of device steps to the device, and runs the steps between on its own machine.

A pool device is on another machine, so it cannot reach the dev servers of this one by a `localhost` name. A simulator shares the network of its Mac. So the runner forwards the port of the dev proxy from the build machine to this machine, with `ssh -R`.

A trial on a pool iPhone 17 on 2026-11-21 proved the forward: the template app loaded its JavaScript from this machine and a note reached the server. It also showed two differences between `agent-device` and the Maestro command line tool:

- A launch argument of `launchApp` reaches the app only when its name starts with `-`, such as `-RCT_jsLocation`.
- A `text` selector matches the label of a text field, never its value. The native commands `agent-device wait` and `agent-device fill` take `label="…" value="…"`. So a step on a `fieldWith` target compiles to a script step that calls one of them.

## Steps

1. Add `tools/journeys/flow-parts.ts`: the parts of a flow, and a script host that gives `evalScript` the `http.post` and `json` functions of Maestro, the `output` object, and a `device` object for the native `wait` and `fill` commands.
1. Compile each launch argument with a leading `-`, and each step on a `fieldWith` target to a `device` script step.
1. The runner sends each stretch with the device host, runs each script here, and saves each screenshot with `agent-device screenshot`.
1. The runner refuses a device that has no build of the sources, by the record that `native:build --install` wrote.
1. Add the dev server link: probe each dev server from the build machine, and start the forward when one does not answer.
1. Write the output, the parts and the screenshots to `test-results/journeys/native/<id>/`.
1. Rewrite the native part of `docs/contributing/end-to-end-testing.md`.

## Acceptance criteria

- C1: A flow with an `evalScript` step and a `takeScreenshot` step runs in parts, in order, and stops at the first part that fails. A test with a fake host holds this.
- C2: A script or screenshot step inside another step is refused before the device gets a step.
- C3: A device with no install record, or with the build of another fingerprint, runs no flow.
- C4: The journey `notes-sync` passes on a pool iPhone 17, with its screenshots and output as evidence.
