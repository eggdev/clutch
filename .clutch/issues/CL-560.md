# CL-560: A bot writes a changeset that passes the format check

## Goal

A pull request that a bot opens passes `format-check` with the changeset that the bot wrote.

## Context

Each pull request carries one changeset file. Four writers make that file: `changesetText` in `tools/release/changeset.ts` for `pr open` and for the revert, `tools/release/renovate-changeset.mjs`, and a `printf` line in the security workflow and in the gardening workflow.

Each writer put the package name in double quotes. The formatter keeps single quotes, so `format-check` refuses the file. A pull request from `pr open` passes only because the `pre-commit` hook formats the file. A bot has no Git hook.

So a bot's pull request opened red. The revert of pull request 282 needed a commit by hand to format its changeset. The gardening pull request 286 failed `validate` for the same reason. A revert that cannot turn green alone does not pay a wrong merge back.

## Steps

1. Branch `clutch/cl-560-changeset-format`.
2. `changesetText` and `renovate-changeset.mjs` write the package name in single quotes.
3. The `printf` line in `.github/workflows/security.yml` does the same.
4. A test runs the formatter on the text of the two tool writers.
5. The same line in `.github/workflows/gardening.yml` changes in CL-554, which rewrites that step.

## Files

- `tools/release/changeset.ts`, `tools/release/changeset.test.ts`
- `tools/release/renovate-changeset.mjs`, `tools/release/renovate-changeset.test.ts`
- `.github/workflows/security.yml`

## Acceptance criteria

- The formatter accepts the text that `changesetText` and `renovateChangeset` return, and a test proves it.
- The release still reads a changeset in each quote style.

## Verify

```sh
mise exec -- bun run validate
```
