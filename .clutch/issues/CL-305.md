# CL-305: Add a CI failure explainer

## Goal

When CI fails on a PR, an agent comments with the failing step, the likely cause and the fix command.

## Context

- `.github/workflows/agent-review.yml` already has the pattern to copy. It skips drafts, and it passes with a notice when no API secret is set.
- The workflow `CI` is defined in `.github/workflows/ci.yml`.

## Steps

1. Branch `clutch/cl-305-ci-explainer`.
2. Add `.github/workflows/ci-explain.yml`:
   - `on: workflow_run` of `CI`, types `completed`. Guard the job with `if:` on all three of: `github.event.workflow_run.event == 'pull_request'`, `github.event.workflow_run.conclusion == 'failure'`, and `github.event.workflow_run.head_repository.full_name == github.repository`. `workflow_run` runs on the default branch, so the guard keeps fork PRs from reaching the secrets.
   - top-level `permissions: { contents: read }`, job permissions `pull-requests: write` and `actions: read`
   - steps: download the failed job logs with `gh run view --log-failed`, trim them to 20k characters, and call `anthropics/claude-code-action` with a prompt that answers in at most 15 lines
3. When no API secret is set, pass with a notice (copy the pattern from `agent-review.yml`).
4. Adopt `ci_failure_explainer`.

## Acceptance criteria

- A deliberately failing scratch PR gets one comment.
- A fork PR, and a run that passed, start no explainer job.
- `check-workflows` passes.

## Verify

```bash
mise exec -- bun nx run-many -t check-workflows
```
