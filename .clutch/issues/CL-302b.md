# CL-302b: Add the clutch ratchet commands, target and adoption

## Goal

Expose the ratchet engine from CL-302 as `clutch ratchet` commands and a root check, and adopt it with a real ratchet.

## Context

- The template ships `.clutch/ratchets.json` with no entries, so `ratchets` can only be adopted with a real ratchet in the same PR. The first real consumer is CL-703.
- The `ratchets` registry rule uses `hasPath`. An empty `ratchets: {}` therefore makes `clutch doctor` report the capability present while `clutch.yaml` waives it.

## Steps

1. Branch `clutch/cl-302b-ratchet-commands`.
2. Add `apps/cli/src/ratchet-command.ts`:
   - `clutch ratchet check [--base <ref>]`
   - `clutch ratchet update`, which only lowers counts and refuses a raise
   - `clutch ratchet add <name> --pattern ... --files ...`, which seeds counts
3. Add root target `check-ratchets` to `checks`, and a row in `checks.md`.
4. Fix the detection. Make the `ratchets` yaml rule require a non-empty object, or ship a real ratchet in the adopt PR. Test both.
5. Add `.clutch/ratchets.json` to `tools/guardrail-files.json` and `.github/CODEOWNERS`.
6. Adopt `ratchets` in `clutch.yaml` with the first real ratchet.

## Acceptance criteria

- A `clutch ratchet check` fails on a raise, and exits 2 on a drop without an update.
- An empty `ratchets: {}` reports `ratchets` as missing, not present.

## Verify

```bash
mise exec -- bun test apps/cli/src/ratchet
mise exec -- bun nx run check-ratchets
mise exec -- bun run clutch doctor --phase P3
```
