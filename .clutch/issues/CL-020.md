# CL-020: Add clutch doctor --remote GitHub settings probes

## Goal

`--remote` evaluates `remote:` rules with read-only `gh api` calls, so doctor sees protected main, secret scanning, push protection, merge queue, auto-merge and CodeQL default setup.

## Probes

Each probe reads the repo from `git remote get-url origin`, or from `--repo owner/name`.

- `protected_main`: `gh api repos/{repo}/rules/branches/{default}` has a `pull_request` rule and a `required_status_checks` rule that includes `validate`. The classic protection API is the fallback.
- `secret_scanning` and `push_protection`: `gh api repos/{repo}` `.security_and_analysis.secret_scanning.status == "enabled"` and `.secret_scanning_push_protection.status == "enabled"`.
- `merge_queue`: the branch rules include `merge_queue`.
- `allow_auto_merge`: `gh api repos/{repo}` `.allow_auto_merge`.
- `code_scanning_default_setup`: `gh api repos/{repo}/code-scanning/default-setup` `.state == "configured"`.
- `required_check:<name>`: the required status checks include `<name>`.

## Steps

1. Branch `clutch/cl-020-doctor-remote`.
2. Add `apps/cli/src/doctor/remote.ts`. It only runs `gh api` with GET, and it caches each response per run. When `gh` is missing, unauthenticated, or the API returns 403 or 404, the probe is `unknown` and the evidence holds the reason. Never write settings.
3. Wire `--remote` in `doctor-command.ts`. `--check --remote` fails on `missing`, and `unknown` stays a warning.
4. Tests use `fakeBin` to fake `gh` responses.

## Files
