# CL-404: Add the low-risk auto-merge workflow in dry-run mode

## Goal

Low-risk agent PRs that pass every required check and the agent review get queued for merge without Brendan.

## Steps

1. Branch `clutch/cl-404-automerge`.
2. Add `.github/workflows/auto-merge.yml`. It triggers on `pull_request` (`opened`, `synchronize`, `reopened`, `ready_for_review`) and on `check_suite` completed. It does not read labels, because a label set with `GITHUB_TOKEN` starts no workflow. It computes its inputs itself.
   - Conditions: `clutch risk --json` gives `low`, `clutch pr-size --json` is not `XL`, the PR is not a draft, the base is the default branch (a stack cannot enter a merge queue), the head branch starts with `clutch/cl-`, and every required check is green.
   - The branch prefix stands in for an author allowlist. `pr open` runs under the operator's `gh` login, so the author cannot tell agents from people.
   - When `clutch.yaml` `automerge.mode` is `dry-run`, comment "would auto-merge". Put a marker `<!-- automerge-dry-run:<head sha> -->` in the comment, and skip the comment when the PR already has that marker, so reruns do not repeat it.
   - When it is `on`, run `gh pr merge --auto --merge`. Merge commits match `tools/github/pr.ts`.
3. Add `automerge` with its `mode` to the `clutch.yaml` schema. Ship with `mode: dry-run`. Turning it on is part of CL-405.
4. Update `.agents/skills/deliver/references/pull-requests.md`. Its rule "Merge only when the owner says so" must name the one exception, a low-risk PR under `automerge.mode: on`.

## Acceptance criteria

- 5 low-risk PRs get the dry-run comment, and no medium or higher PR does.
- A PR from a branch that does not start with `clutch/cl-` gets no comment.

## Verify

```bash
gh pr list --label risk/low --state all --limit 10
```
