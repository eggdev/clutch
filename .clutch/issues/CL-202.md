# CL-202: Isolate env, ports and DB per worktree, including tests and journeys

## Goal

Tests, journeys and any external service run side by side across worktrees with no shared port, profile or database.

## Steps

1. Branch `clutch/cl-202-worktree-isolation`.
2. Audit for fixed ports and shared paths: `rg -n "localhost:[0-9]{4}|:1355|/tmp/" apps packages tools features -g '!*.md'`. Check the Playwright config of the journeys and `tools/journeys/**` (guardrail files).
3. Export `CLUTCH_WORKTREE=<slug>` from `clutch worktree new` into a `.clutch/worktree.env` file that `tools/dev.ts` and the journey runner read (only when present). Derive any port the app picks from portless, not from a constant.
4. Add the optional `worktree.db` hooks to `clutch.yaml` for repos with an external DB: `create` and `drop` commands with `{slug}` substitution. Neighborhood and Bar Savvy fill these in RN and RB. The template uses PGlite, so it leaves them empty.
5. Write `docs/contributing/setup/worktrees.md`. Follow the doc rules.

## Acceptance criteria

- `bun run journeys` passes in two worktrees at the same time.
- The doc page passes the doc checks.

## Verify

```bash
(cd ../clutch.worktrees/demo-a && mise exec -- bun run journeys) & (cd ../clutch.worktrees/demo-b && mise exec -- bun run journeys); wait
```
