# CL-202: Isolate env, ports and DB per worktree, including tests and journeys

## Goal

Tests, journeys and any external service run side by side across worktrees with no shared port, profile or database.

## Context

- The audit is mostly done. Portless assigns each app its port. `apps/api/src/main.ts` reads `PORT` (default 4000).
- PGlite uses the cwd-relative `.data/pglite` folder (`apps/api/src/main.ts`). Each checkout has its own copy.
- `.data/dev.lock` is per checkout (`tools/dev.ts`).
- So the remaining work is the audit result, a worktree doc page, and proof that two checkouts run together.
- `tools/dev.ts` and `tools/journeys/**` are guardrail files. Changes there need Brendan's approval in the PR.

## Steps

1. Branch `clutch/cl-202-worktree-isolation`.
2. Audit for fixed ports and shared paths: `rg -n "localhost:[0-9]{4}|:1355|/tmp/" apps packages tools features -g '!*.md'`. Check the Playwright config in `tools/journeys/playwright.config.ts` and the rest of `tools/journeys/**`. Fix any fixed port or shared path that the audit finds.
3. Add the optional `worktree.db` hooks to `clutch.yaml` for repos with an external DB: `create` and `drop` commands with `{slug}` substitution. Neighborhood and Bar Savvy fill these in RN and RB. The template uses PGlite, so it leaves them empty.
4. Write `docs/contributing/setup/worktrees.md`. Follow the doc rules.

## Acceptance criteria

- `mise exec -- bun run journey --all` (or `mise exec -- bun nx run clutch:journeys`) passes in two worktrees at the same time.
- The doc page passes the doc checks.

## Verify

```bash
(cd ../clutch.worktrees/demo-a && mise exec -- bun run journey --all) & (cd ../clutch.worktrees/demo-b && mise exec -- bun run journey --all); wait
```

## Notes

- The `worktree.db` schema idea is not in this issue. The config loader rejects unknown keys in the `worktree` block (`apps/cli/src/clutch-config/schema.ts`). Adding `db` hooks would need a schema change. Make it a later issue when RN or RB needs it.
- The `worktree_parallel` waiver in `clutch.yaml` should name this issue, CL-202, not CL-201. Brendan or the parent agent makes that edit.
