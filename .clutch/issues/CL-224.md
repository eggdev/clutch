# CL-224: Find the web app, and say so when no journey ran

## Goal

The required `journeys` check in a project must fail or say so when it tests nothing. A project whose web app is not `apps/web` must still run its journeys, and a run with no journey must show a warning.

## Context

- `tools/journeys/run.ts` required `apps/web`. Neighborhood's web app is `apps/app`, so `bun run journey --all` printed "No web journey exists yet. Nothing ran." and exited 0. The required `journeys` check was green and tested nothing.
- The generator's journey template imports `@repo/journeys/testing/a11y`. `packages/journeys/` is a managed path with the `a11y_checks` capability, so sync ships the helper to a project that adopts it. PR #162 (CL-219) adds the knip entry and the managed-link fix that a project needs for it, so this change does not touch the helper.
- A project before its first journey must still merge, so zero journeys keeps exit 0.

## Steps

1. `journeys.webApp` in `clutch.yaml` names the web app, as `apps/app`. The schema accepts it and rejects any other path.
2. The runner finds the web app with `devApps` from `tools/dev.ts`. Without the key, it is the one app under `apps/` with a `dev` target that is not tagged `platform:server` or `platform:native`. Several candidates without the key fail with a message that names the key.
3. Zero journeys keep exit 0. The runner prints a `::warning title=No journey ran::` annotation and writes a line to `$GITHUB_STEP_SUMMARY` that names what to add and links `docs/contributing/end-to-end-testing.md`.
4. `clutch doctor` reports `a11y_checks`, the closest journeys capability, as `partial` when the runner ships and no journey imports the helper. The registry has no `e2e_smoke_tests` capability.

## Files

- `apps/cli/src/clutch-config/schema.ts`, `apps/cli/src/clutch-config/schema.test.ts`
- `tools/journeys/run.ts`, `tools/journeys/run.test.ts`, `tools/journeys/web-app.ts`, `tools/journeys/web-app.test.ts`
- `docs/contributing/capabilities/registry.yaml`, `docs/contributing/capabilities/a11y-checks.md`
- `apps/cli/README.md`, `docs/contributing/setup/verification.md`

## Acceptance criteria

- With `apps/app` as the only app that has a web entry, the runner selects it, with no key.
- With `journeys.webApp` set, the runner uses that app, even when several apps have a web entry.
- Several web entries without the key fail, and the message names each app and the key.
- `journeys --all` with no web journey exits 0, prints the warning annotation, and writes the step summary line.
- The `journeys.webApp` key loads, and a bad value names its YAML path.
