# CL-558: Each pull request records how its change was verified

## Goal

Each pull request carries a record of the flows that verified its change. The record comes from the verify receipts. A gate in `clutch.yaml` can log or block a change with a missing flow.

## Context

The owner compared Clutch with the article "How the Claude Code team thinks about verification". On 2026-11-16 the owner said to fully meet two practices: verification means running the change, and a new gate starts in observe mode. The verify runner writes a receipt for each run, but nothing reads the receipts. No one can list the pull requests that merged with no verification.

## Steps

1. Branch `clutch/cl-558-verification-record`.
2. Write the tree id of each run into its receipt.
3. Map each flow to its paths in the verify config.
4. In `pr open`, build the record from the receipts and write it as the first line of the "Verification" section.
5. Add the gate setting `verification.gate` to `clutch.yaml`: `off`, `observe` or `enforce`.
6. Document the record, the gate and the query command.

## Acceptance criteria

- A change to a mapped file, with a passing receipt for the current tree, gives a record that names the flow.
- A receipt for an older tree does not count.
- `observe` prints a notice and goes on. `enforce` refuses with no reason, and passes with a reason that is then in the record.
- A docs-only change gives `docs-only` and no notice.
- A second `pr open` leaves one record in the body.
