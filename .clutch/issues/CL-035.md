# CL-035: Make the CLI tests independent of the clone and the registry size

## Goal

The CLI tests pass in a shallow clone, a fork without tags and an interactive terminal, and adding a capability breaks none of them.

## Context

From the CL-029 review:

- `apps/cli/src/init-command.test.ts:24, 60, 71`: `initCommand` uses the real checkout and needs a `v*` tag (CL-028).
- `apps/cli/src/sync/decide.test.ts:105`: in a TTY, `syncCommand` prompts instead of exiting 2.
- `apps/cli/src/doctor/detect.test.ts:56`: a 1000 ms timing assertion on a walk of the real repository. Lines 58-62 repeat `doctor/seed.test.ts:59`.
- `apps/cli/src/doctor-command.test.ts:48, 69, 77-78, 92-96` hard-code 36 capabilities, 34 undeclared and the P4 ids.
- `apps/cli/src/doctor/seed.test.ts:52` lists the registry ids. Its `expected` table (lines 13-50) repeats `.clutch/doctor-baseline.json`.
- `apps/cli/src/doctor/registry.test.ts:77` and `apps/cli/src/issues/parse.test.ts:57` check only the error count.

## Steps

1. init tests: pass a `gitRepo` template fixture with a `v0.1.0` tag.
2. Make the interactive check in `syncCommand` injectable, and turn it off in the test.
3. Drop the timing assertion and the repeated status checks in `detect.test.ts`.
4. Read the counts and ids from `loadRegistry`. Compare `seed.test.ts` with the baseline file.
5. Assert the error message, not only the count.

## Acceptance criteria

- `bun test apps/cli` passes in `git clone --depth 1` and with a TTY.
- validate passes.
