# CL-201: Add clutch worktree new and list, and the WorktreeBackend interface

## Goal

One command creates an isolated, ready-to-run worktree for one issue. One command lists them. The removal command lands in CL-201b.

## Context

- Portless prefixes the branch name in a linked worktree (`docs/contributing/setup/local-development.md`).
- PGlite data lives in `apps/api/.data/pglite` inside each checkout.
- `tools/dev.ts` holds `.data/dev.lock` and supports `dev --check`. It has no stop flag.
- So a git worktree is already isolated for the web, API and DB. This command adds the setup steps and safety.
- Build on plain `git worktree` only. No other tool is required.
- The `worktree:` block already exists in `apps/cli/src/clutch-config/schema.ts`. When the block is present, `root` is required. `copy` and `setup` default to empty lists. So the defaults for a repo with no block live in the command code, not in the schema.
- The command runs from the release binary, not from a Clutch clone. It is not in the `clone` set in `apps/cli/src/commands.ts`. Do not import `tools/dev.ts`.
- Bar Savvy uses `BAR_SAVVY_INSTANCE` for isolated instances (CL-704 reviews it for upstream ideas).

## Steps

1. Branch `clutch/cl-201-worktree`.
2. Add a backend interface in `apps/cli/src/worktree/backend.ts`: `WorktreeBackend` with `create({slug, branch, base, path})`, `list()` and `remove({path, force})`, returning plain records `{path, branch, head, dirty}`. Add the only implementation, `apps/cli/src/worktree/git-backend.ts`, which runs `git worktree`. The commands call the interface only, never `git worktree` directly, so the backend can change later without touching the commands.
3. Add `apps/cli/src/worktree/{new,list}.ts` and `apps/cli/src/worktree-command.ts`. Register the command in `apps/cli/src/commands.ts`.
   - `clutch worktree new <slug> [--issue CL-NNN] [--base origin/main]`:
     1. `git fetch`, then `git worktree add <root>/<slug> -b <branch> <base>`. Without `--issue`, `<branch>` is `clutch/<slug>`. With `--issue`, it is `clutch/cl-NNN-<slug>`, as `.clutch/README.md` says.
     2. Copy each `worktree.copy` file that exists.
     3. Run each `worktree.setup` command in the new folder. The default is `mise exec -- bun install`, which also installs git hooks.
     4. With `--issue`, run `clutch issues set <id> in_progress`.
     5. Print the path, the branch and any dev URL that `bun run dev --check` reports. Treat its output as information only. It exits 1 when any server is down, which is always true for a new worktree. Call `bun run dev` only if the project has a `dev` script in `package.json`.
   - `clutch worktree list [--json]`: parse `git worktree list --porcelain` and show branch, dirty state, linked issue (read from the branch name) and PR (`gh pr view` when available).
4. Read defaults from `clutch.yaml` `worktree`. When there is no block, use `root` `../<repo>.worktrees`, empty `copy`, and `setup` `mise exec -- bun install`.
5. Tests on a `gitRepo` fixture. Add one test that runs the commands against a fake `WorktreeBackend`, to prove the commands do not depend on git directly.
6. Edit `docs/contributing/agent-workflow.md` and `docs/contributing/delivery.md`. Remove the Sprig claims about task environments and version control. Name `clutch worktree` as the owner of task environments, built on plain git worktrees. Say that Sprig is a possible later backend, tracked in `.clutch/issues/CL-901.md`.
   - `docs/contributing/delivery.md:45-46` says "Sprig owns task environments and version control when configured". Remove that clause.
   - `docs/contributing/agent-workflow.md:108` says "Use Sprig when configured and host delegation". Remove the Sprig part.
   - `docs/contributing/agent-workflow.md:120` says "Sprig owns configured version control and environments." Replace it with the `clutch worktree` owner.
   - Suggested text: "`clutch worktree` owns task environments. It uses plain git worktrees. Sprig is a possible later backend. See `.clutch/issues/CL-901.md`."
   - Keep Simplified Technical English and the `check-terms` rules. If `check-docs-temporal` rejects the wording, rephrase it as a fact with no time words. Do not add the doc to an ignore list.

## Acceptance criteria

- `clutch worktree new` creates a worktree with the right branch name, runs the setup commands, and prints the path and branch.
- `clutch worktree list` shows each worktree with branch, dirty state and linked issue.
- `rg -n "git worktree" apps/cli/src -g '!**/git-backend*'` prints nothing outside tests.
- `docs/contributing/agent-workflow.md` and `docs/contributing/delivery.md` name `clutch worktree` as the owner of task environments and no longer say Sprig owns them.
