# CL-554: The gardening pass tries to disprove each candidate rule, and the owner approves a new rule

## Goal

The weekly gardening pass turns repeated misses into rules with evidence. It tries to disprove each candidate rule, and the owner approves each new rule.

## Context

On 2026-11-16 the owner compared Clutch with the practice "turn misses into rules", and said to meet it fully. Before this change, the pass proposed a guardrail from one repeated comment, with no evidence and no attempt to disprove it. A gardening pull request of a low risk tier merged with no person, also when it added a review rule. The agent could not run a check, so pull request #286 opened red, and no session owned it.

## Steps

1. A candidate rule needs the same mistake in at least 2 pull requests, and a trigger that can be read from a diff.
2. The pass makes 3 independent attempts to disprove each candidate, one subagent each, and drops it when one attempt succeeds.
3. The pull request body has a section "Candidate rules" with the evidence and the result of each attempt.
4. The bot rule holds a gardening pull request that adds a line to `docs/contributing/review.md`, or changes a guardrail file, until the owner approves its head.
5. The agent runs `validate`, and the workflow runs it before the commit. A red pass opens no pull request.
6. An expiring flaky test is fixed or deleted, as the testing page says.

## Files

- `.github/workflows/gardening.yml`
- `tools/github/bot-rule.ts`, `tools/github/bot-rule.test.ts`
- `tools/github/auto-merge.ts`, `tools/github/auto-merge-owner.test.ts`
- `docs/contributing/harness-engineering.md`, section "Weekly gardening"
- `.agents/skills/deliver/references/pull-requests.md`, section "Auto-merge"

## Acceptance criteria

- A gardening pull request that adds a line to `review.md` waits for the owner, and the owner's approval lifts the hold.
- A gardening pull request that only deletes lines from `review.md` merges as before.
- The prompt and the docs page name the same steps.
- The job opens no pull request when `validate` fails.
