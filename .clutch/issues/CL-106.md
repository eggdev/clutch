# CL-106: HUMAN GATE: Turn on the main ruleset, secret scanning and push protection

## Goal

Brendan applies the repo settings that agents need before many PRs run in parallel.

## Context

`release.yml` pushes the release commit to main with the default `GITHUB_TOKEN`. A main ruleset that blocks direct pushes therefore breaks releases, unless it has a bypass for the GitHub Actions integration or `release.yml` stops pushing to main directly.

## Gate

Stop. Changing repo settings, rulesets and secret scanning needs Brendan. Brendan does these by hand:

1. Turn on secret scanning, push protection and private vulnerability reporting. SECURITY.md (CL-101) tells reporters to use private reporting.
2. Create the main ruleset with a bypass for the GitHub Actions integration, so the release can push to main. Or change `release.yml` so it does not push to main directly. That choice is Brendan's.
3. Optionally, install the Renovate GitHub app (CL-104).
4. Approve the `clutch.yaml` flip PR in step 4 below.

## Steps (agent)

1. Prepare the exact commands in the PR and in this issue. Do not run them.
   - Secret scanning and push protection: `gh api -X PATCH repos/eggdev/clutch -F security_and_analysis[secret_scanning][status]=enabled -F security_and_analysis[secret_scanning_push_protection][status]=enabled`
   - Private vulnerability reporting: `gh api -X PUT repos/eggdev/clutch/private-vulnerability-reporting`
   - Main ruleset: write the JSON to `.github/rulesets/main.json` in the PR, or paste it in the PR body. Do not leave it in `/tmp`. Include `name`, `target: branch`, `enforcement: active`, and `conditions` with `ref_name` including `~DEFAULT_BRANCH`. Rules: `pull_request` (0 approvals while Brendan is the only reviewer, dismiss stale reviews), `required_status_checks` (`validate`, `journeys`), `non_fast_forward` and `deletion`. Bypass: the repo admin role, and the GitHub Actions integration for the release push. Command: `gh api -X POST repos/eggdev/clutch/rulesets --input .github/rulesets/main.json`
   - Optional: install the Renovate app (CL-104).
2. Ask Brendan in the PR: "CL-106: P1 needs repo settings. Commands are in .clutch/issues/CL-106.md. Approve to run, or apply them yourself. Also decide: a bypass for the release push, or change release.yml?"
3. After Brendan acts, run `mise exec -- bun run clutch doctor --remote --check` and paste the result in this issue.
4. Follow-up PR, after Brendan acts: set `protected_main` and `secret_scanning` to `adopted` in `clutch.yaml`, then run `mise exec -- bun run clutch doctor --write-baseline`. Brendan approves this PR.

## Acceptance criteria

- `clutch doctor --remote --check` reports `protected_main` and `secret_scanning` present.
- The follow-up PR in step 4 is merged, and both capabilities are adopted in `clutch.yaml`.

## Verify

```bash
mise exec -- bun run clutch doctor --remote --check
```
