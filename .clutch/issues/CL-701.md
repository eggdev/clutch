# CL-701: Adopt Clutch in Bar Savvy in doctor mode on epic/refactor

## Goal

Bar Savvy (`blockmen-group/bar-savvy-web`) is checked by Clutch but keeps its own files. It runs doctor and the reusable workflows, without sync.

## Steps

1. Branch `clutch/cl-701-adopt` from `epic/refactor` (audited at 1562fbb2).
2. Check first: Bar Savvy has no `clutch.yaml` and no competing `.clutch/` tracker. Then pull the Clutch tags: `git -C ~/src/clutch pull --tags`.
3. `bun ~/src/clutch/apps/cli/src/main.ts init --root ~/src/bar-savvy-web --mode doctor --yes`. Init adopts every capability it detects as present. Do not re-declare those.
4. Hand-declare only partial capabilities, each with a reason. A value is `adopted` or `{status, reason}`. Do not write strength names such as `control-bar-savvy` as values.
   - `secret_scanning` is likely partial without `--remote`. Run `clutch doctor --root ~/src/bar-savvy-web --remote --repo blockmen-group/bar-savvy-web` first. If it is still partial, waive it with a reason.
5. Waive the other gaps with reasons and issues in Bar Savvy's own tracker.
6. Add the `clutch:` job to Bar Savvy CI, calling `eggdev/clutch/.github/workflows/clutch-doctor.yml@main`. Doctor mode does not sync, so the job runs no sync.
7. Open a PR against `epic/refactor`.

## Acceptance criteria

- `clutch doctor --check --root ~/src/bar-savvy-web` exits 0.
- Bar Savvy has a `clutch:` job that calls `clutch-doctor.yml@main`.

## Verify

```bash
bun ~/src/clutch/apps/cli/src/main.ts doctor --check --root ~/src/bar-savvy-web
```
