# CL-504: HUMAN GATE: Run a weekly cross-repo doctor digest

## Goal

Every Monday, a workflow writes doctor and metrics summaries for Clutch, Neighborhood and Bar Savvy to its job summary.

## Gate

Reading the other repositories from Actions needs a token with read access to them. Adding that secret is a credential change. Brendan creates a read-only fine-grained PAT or a GitHub App with Contents, Metadata, Administration, Actions and Pull requests (read) for `eggdev` and `blockmen-group`, then runs `gh secret set <NAME> --repo eggdev/clutch`.

## Steps (agent)

1. Add `fleet` to the `clutch.yaml` schema in `apps/cli/src/clutch-config/schema.ts` first. Each entry has a `repo` (`owner/name`) and a `ref` (the branch to read). Clutch is `eggdev/clutch` on `main`, Neighborhood is `eggdev/neighborhood`, and Bar Savvy is `blockmen-group/bar-savvy-web` on `epic/refactor` until CL-705 moves it.
2. Prepare `.github/workflows/weekly-digest.yml` with `schedule` and `workflow_dispatch:`. Check out each repo at its `ref` with the read token, because the doctor's detect rules read local files. For each `fleet` entry, it runs `clutch doctor --remote --repo <repo> --json` and `clutch metrics --repo <repo>`, and writes both to `$GITHUB_STEP_SUMMARY`.
3. Give the job `actions: read` in its `permissions` block.
4. When the secret is missing, skip with a notice, as gardening does. Name the secret in the workflow, and name it in the PR so Brendan can run the gate's `gh secret set` command.

## Acceptance criteria

- One run's job summary shows the digest for each repo in `fleet`.
- With the secret missing, the run passes with a notice.

## Verify

```bash
gh workflow run weekly-digest.yml
```
