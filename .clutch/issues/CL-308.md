# CL-308: HUMAN GATE: Make agent review and SAST required checks

## Goal

A green PR means agent review and static analysis passed, in Clutch and in every project made from it.

## Context

- `.github/workflows/agent-review.yml` passes with a notice when no Anthropic secret is set. It also skips draft PRs. So a required `agent-review` check can be green with no review run.
- CodeQL does not exist yet. CL-102 adds the workflow, and its check name is only known after that.
- The main ruleset comes from CL-106.

## Gate

A ruleset change needs Brendan. Brendan does these steps:

1. Decide whether a missing Anthropic secret should fail `agent-review`. Until he decides, the check cannot prove a review ran.
2. After CL-102 merges, read the CodeQL check name from `gh pr checks` on a PR.
3. In the main ruleset, as an admin, add `agent-review` and the CodeQL check as required status checks.
4. Tell the agent. The agent then flips the capability and runs the verify command.

## Steps (agent)

1. Wait for Brendan's decision on the missing-secret behavior, and apply it to `agent-review.yml` if he asks for a change.
2. Confirm that `agent-review` and CodeQL ran green on 5 recent non-draft PRs (`gh pr checks`).
3. Prepare the ruleset patch that adds both to `required_status_checks`. Ask Brendan in the PR, with the command.
4. Flip `ai_review_blocking` to `adopted` in `clutch.yaml` in the same PR.
5. After Brendan changes the ruleset, run the verify command and confirm that `ai_review_blocking` is present.

## Acceptance criteria

- `required_check:agent-review` and `required_check:sast` probes pass on `eggdev/clutch`.
- `.github/rulesets/main.json` is a managed file, and `clutch ruleset --apply` sends it to any repository.
- `clutch doctor --remote` shows whether each ruleset file matches GitHub.

## Verify

The probe needs a token that can read rulesets.

```bash
mise exec -- bun run clutch doctor --remote --phase P3
```
