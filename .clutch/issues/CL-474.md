# CL-474: Start the native lanes only for a change that can reach the app

## Goal

A PR starts the native lanes only when its change can reach the app. A change to the merge gate or to the risk policy runs the web journeys only.

## Context

- `reachOf` in `tools/journeys/reach.ts` said that a sensitive path reaches native. A sensitive path is a file whose tier in `.clutch/risk.yaml` is `one-way-door`.
- The merge-gate files are in that tier: `.clutch/risk.yaml`, `tools/github/auto-merge*.ts`, the workflows and others. So each PR that changed them started the iOS lane.
- The merge judge in `tools/github/auto-merge-rules.ts` holds a PR whose native job is not `success`, `skipped` or `missing`. It held these PRs on a lane that says nothing about their change.
- The owner decided on 2026-11-12 that a sensitive path alone does not reach native. A native app, a native journey, `tools/native/` and a shared runtime package still do. A push to the default branch still reaches every platform.
- The owner accepted the cost: a change to server-only auth code outside those folders, such as under `apps/api`, does not force an iOS run.

## Steps

1. Branch `clutch/cl-474-reach-without-sensitive-paths`.
2. Remove the sensitive-path clause from `reachOf`, and state the rule as it is in the header comment.
3. When nothing else reads the `tier` of a change, remove it and the code that computes it.
4. Change the tests with the behaviour.
5. Update each page that states the reach rule.

## Files

- `tools/journeys/reach.ts`, `tools/journeys/reach.test.ts`
- `docs/principles/proof-gates-code.md`, `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- A change to `.clutch/risk.yaml` and `tools/github/auto-merge-rules.ts` reaches web only.
- A change under a native app, `packages/access/`, `tools/native/`, or to a `*.journey.ts` or `*.maestro.yaml` file reaches native.
- No page says that a sensitive path starts the native journeys.
