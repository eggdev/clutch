# CL-449: Record native core journey outcomes and measures on the device

## Goal

A native core journey proves its outcomes in the run, the way a web one does. Its run also records layout shift, taps and accessibility results.

## Context

- On web, `outcome()` records each outcome that held, and `bun run journey` fails a core journey whose run missed one (CL-440). CL-442 adds the per-device measures.
- On native, the source rules are the only check. `<id>.<platform>.json` holds only the result and the time (`docs/contributing/end-to-end-testing.md`). A Maestro flow can list an outcome label that never ran, and nothing notices.
- No native lane can run on the machine where CL-440 and CL-442 were built. There is no iOS simulator, no KVM, and no native app in the template. The council reviews of both PRs named this gap.

## Steps

1. Read the steps that ran from Maestro's output (`--format junit` or the debug report). Record each `outcome <name>` assertion that passed, in order, to `test-results/journeys/outcomes/<run>/<id>.<platform>.jsonl`.
2. Make the run check of `tools/journeys/run.ts` (`unprovenCore`) read native records. A native core journey whose run did not record `signed-up` first, followed by every catalog outcome, fails.
3. Record taps and text entry from the flow's own steps against the `clicks` budget. Fail over budget.
4. Record what the platform's accessibility audit finds, where Maestro or the platform exposes one, and name what it cannot check.
5. Prove each step on a real iOS simulator and a real Android emulator in CI, with a scratch native app.

## Files

- `tools/journeys/native.ts`, `tools/journeys/run.ts`, `tools/journeys/measures.ts`
- `tools/native/device-host.ts`
- `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- A native core journey whose run skips a catalog outcome fails, even when Maestro passes.
- A native sign-up over its tap budget fails.
- Both lanes ran in CI against a native app.
- `bun run validate` passes.

## Verify

The `native-ios` and `native-android` CI jobs on a PR with a scratch native app, run once with an outcome skipped and once with all of them.
