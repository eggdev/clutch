# CL-525: Declare read tools, jobs and routes in the contract

## Goal

A read tool, a job and an HTTP route are each declared in the contract, so the manifest lists every way into a package.

## Context

The contract declares records, commands and load functions. An agent tool exists only for a command, so a project still writes each list, get and search tool by hand. Jobs and routes are registered in `runtime/` lists and appear in no manifest. See `docs/contributing/architecture/mcp.md`.

## Steps

1. Branch `clutch/cl-525-reads-jobs-routes`.
2. Add a `query` declaration: a record, the slim fields of its list, a limit and a cursor. Derive `list` and `get` tools from it, with the access rule of the group.
3. Add `job` and `route` declarations with their payload fields, and list them in the manifest.
4. Classify their changes in `compareManifests`.

## Files

- `packages/sync/contract/query.ts`, `packages/sync/contract/tools.ts`, `packages/sync/contract/manifest.ts`
- `packages/notes/contract/notes.ts`

## Acceptance criteria

- The notes package offers `notes_list` and `notes_get` with no handler of its own.
- `contract.json` lists the `count-notes` job and the import route.
