# CL-553: One reviewer applies the review rules that the diff triggers

## Goal

Agent review applies only the rules whose triggers match the diff. Each rule names its trigger and its source. Agent review is the one configured reviewer.

## Context

On 2026-11-16 the owner asked Clutch to fully meet two practices of the article "How the Claude Code team thinks about verification". Review rules trigger on the diff, and one reviewer is tuned through its rules file. Before this change, no rule in `docs/contributing/review.md` had a trigger or a source, and `.cursor/BUGBOT.md` set up a second reviewer.

## Steps

1. Give each rule in `review.md` a `Trigger:` line and a `Because:` line. Keep each rule's meaning and level.
2. Add `tools/github/review-rules.ts`. It reads the page and a diff, and prints the rules that match. A trigger it cannot read applies always.
3. Run the base branch's copy of the tool in `agent-review.yml`. Tell the reviewer to apply the printed rules.
4. Add a unit test that fails when a rule on the real page has no `Trigger:` or `Because:` line.
5. Delete `.cursor/BUGBOT.md`, name agent review as the one reviewer, and update the docs.

## Files

`docs/contributing/review.md`, `docs/contributing/agent-review.md`, `tools/github/review-rules.ts` and its test, `.github/workflows/agent-review.yml`, `.cursor/BUGBOT.md` (deleted), `tools/guardrail-files.json`, and the docs that named Bugbot.

## Acceptance criteria

- On a docs-only diff, the tool prints only the rules whose triggers match docs.
- On a diff that deletes a test file, it prints the rule about a weaker or deleted test.
- The unit test fails when one rule loses its `Trigger:` or `Because:` line.
- Each rule that was on the page before is on the page after, with the same level.
- The repository has one configured reviewer.

## Verify

- `mise exec -- bun test tools/github/review-rules.test.ts`
- `mise exec -- bun run validate`
