# CL-016: Wire the clutch checks into validate, pre-push and CI

## Goal

`bun run validate` runs `clutch doctor --check`, `clutch issues --check` and (in downstream repos) `clutch sync --check`. CI therefore fails on a regression, an unwaived gap or a stale tracker.

## Context

- `validate` = `CI=1 nx run-many -t typecheck test lint format-check lint-policy-test skill-tests audit-prod checks`.
- `checks` is an `nx:noop` that depends on the `check-*` targets in root `package.json` `nx.targets`.
- `docs/contributing/setup/checks.md` has one row per target. `check-docs-claims` fails a doc that claims a check that does not exist.
- The pre-push hook (`tools/hooks/pre-push.ts`) runs `checks`.
- `package.json` is a guardrail file. The guard hook stays off while `KICKOFF.md` exists, and CODEOWNERS asks Brendan to review the change.

## Steps

1. Branch `clutch/cl-016-wire-checks`.
2. Root `package.json` `nx.targets`: add
   - `"check-clutch": { "command": "bun apps/cli/src/main.ts doctor --check", "cache": true, "inputs": ["default", "{workspaceRoot}/clutch.yaml", "{workspaceRoot}/.clutch/**/*", "{workspaceRoot}/docs/contributing/capabilities/registry.yaml"] }`
   - `"check-clutch-issues": { "command": "bun apps/cli/src/main.ts issues --check" }`
   - Add both to `checks.dependsOn`. Copy the cache and inputs style of the existing `check-*` targets. Read two of them first.
3. Add two rows to `docs/contributing/setup/checks.md` with the fix commands `bun run clutch doctor` and `bun run clutch issues --write`.
4. CI (`.github/workflows/ci.yml`) already runs `validate`, so no new job. Confirm that the Nx cache inputs of each new target include the files it reads.
5. Validate. Then break the baseline on purpose in a scratch commit, confirm the pre-push hook fails, and drop the commit.

## Files

- edit `package.json`, `docs/contributing/setup/checks.md`

## Acceptance criteria

- `mise exec -- bun nx run check-clutch` passes.
- `checks` lists both new targets.
- CI on the PR is green.
