# CL-116: Keep main green after a release commit

## Goal

`validate` passes on each `chore(release)` push to `main`.

## Context

The CL-503 baseline shows 72 main-red minutes in 14 days, almost all of them after a release. The release job pushes `chore(release): vX.Y.Z`, which deletes the changesets it consumed. On that push, `check-changeset` compares against `github.event.before`, finds no new changeset and fails. Main stays red until the next merge. A red `main` also blocks auto-merge in P2.

## Steps

1. Branch `clutch/cl-116-green-release`.
2. In `tools/check-changeset.ts`, pass a range that only releases. Either every commit in it is a release commit (subject `chore(release): vX.Y.Z` by `github-actions[bot]`), or it only consumes changesets. In both cases the range may touch only the release outputs: deleted changesets, `CHANGELOG.md` and the root `package.json`.
3. Test each case. Also test that a pull request without a changeset still fails, including one that copies the release subject.

## Files

- `tools/check-changeset.ts`
- `tools/check-changeset.test.ts`
- `docs/contributing/setup/releases.md`

## Acceptance criteria

- The first `main` CI run on a release commit after the merge is green.
- A change outside `.clutch/` without a changeset still fails.

## Verify

```bash
mise exec -- bun test tools/check-changeset.test.ts
```
