# CL-001: Bootstrap the Clutch tracker in the repository

## Goal

Put this plan's issues into the repository as `.clutch/issues/CL-*.md` plus `.clutch/TRACKER.md`, so every later step reads and updates tracked files.

## Context

- The template tracks work today in `.delivery/*.md` (see `.agents/skills/deliver/references/task-records.md`). CL-004 reconciles that. This issue only adds `.clutch/`.
- `tools/docs-files.ts` lists the files the doc checks scan. `.clutch/**` is not in that list, so `check-sentences`, `check-terms` and `check-docs-temporal` do not scan these files. Do not add `.clutch/` to `tools/docs-files.ts`.
- `tools/check-structure.ts` does not police root folders, so a root `.clutch/` folder is allowed.

## Steps

1. `cd ~/src/project-template && git fetch origin && git switch main && git pull --ff-only`
2. `git switch -c clutch/cl-001-tracker`
3. Unzip the artifact into the repo root: `unzip -o /path/to/clutch-plan.zip '.clutch/*' -d .` If you only have `CLUTCH_PLAN.md`, run the extractor in Appendix A of the plan.
4. Check the copy: `ls .clutch/issues | wc -l` prints the issue count in the plan header.
5. Set this issue to `in_progress` in `.clutch/issues/CL-001.md` (frontmatter `status: in_progress`, `owner: agent`). Update its row in `.clutch/TRACKER.md` by hand (the `clutch issues` command lands in CL-003).
6. Add `.clutch/README.md` with: what the folder is, the frontmatter fields, the status values, and the rule "one issue per PR". Copy the text from the plan section "The tracker".
7. `mise exec -- bun run format` then `mise exec -- bun run validate`.
8. Commit: `git add .clutch && git commit -m "Add the Clutch issue tracker"`.
9. Push and open a draft PR: `git push -u origin HEAD && gh pr create --draft --title "Add the Clutch issue tracker (CL-001)" --body-file .github/pull_request_template.md` then edit the body sections.
10. Set `status: review` and `pr: <url>` in CL-001.md, regenerate the row in TRACKER.md, commit, push.
11. `clutch notify` does not exist yet. Send the milestone with the curl fallback in the plan section "Notify Bix".

## Files

- add `.clutch/README.md`
- add `.clutch/TRACKER.md`
- add `.clutch/issues/CL-*.md`

## Acceptance criteria

- Every issue in the plan has one file in `.clutch/issues/` with valid frontmatter.
- `.clutch/TRACKER.md` lists every issue once.
- `mise exec -- bun run validate` passes.
- No file outside `.clutch/` changed.

## Verify

```bash
ls .clutch/issues/CL-*.md | wc -l
grep -L '^status: ' .clutch/issues/*.md   # prints nothing
git diff --name-only origin/main | grep -v '^\.clutch/'   # prints nothing
mise exec -- bun run validate
```
