# CL-923: Make Android builds on the build machine and run native journeys on a pool emulator

## Goal

A project with an Android app gets its build from the build machine, and its native journeys run on a pool emulator.

## Context

CL-499 makes only the iOS build. `native:build --platform android` refuses with one sentence. The template ships iOS only, so no Android app exists to prove a build with. Two facts from the work on CL-594 matter:

- `agent-device` passes launch arguments on Apple devices only. The iOS flow gives the app its dev server and its organization as launch arguments (`-RCT_jsLocation`, `-devOrganization`). An Android run needs another way.
- The dev server link forwards a port of the build machine. An emulator reaches the build machine at `10.0.2.2`, not at `localhost`.

## Steps

1. Add an Android build script beside `tools/native/ios-simulator-build.sh`, with the same folders and the same fingerprint rule.
2. Give the Android app its dev server and its organization without a launch argument.
3. Prove one journey on a pool emulator.

## Files

- `tools/native/`
- `tools/journeys/maestro.ts`
- `docs/contributing/setup/native.md`

## Acceptance criteria

- C1: `AGENT_DEVICE=<path> mise exec -- bun run native:build --platform android --install` puts an Android app on a pool emulator.
- C2: One native journey passes on a pool emulator.

## Verify

Run both commands on a pool emulator, in a project with an Android app.
