# CL-441: Hold a PR until the journeys its paths name pass on its head

## Goal

A sensitive path names the journeys that prove it. Its PR merges when those journeys pass on its head and agent review has 0 blocking findings. No owner approval is needed.

## Context

- `docs/principles/proof-gates-code.md`: proof gates code, and a path stays held until its journeys exist and pass.
- `.clutch/risk.yaml` gives each path a tier, and `tools/codeowners.ts` turns the one-way-door paths into CODEOWNERS rules that need the owner. Auto-merge reads the tier in `tools/github/auto-merge-rules.ts`.
- On Neighborhood, `tools/journeys/run.ts` passed the required `journeys` check with no journey and only a warning (`noJourneyNotice`). `tools/check-journeys.ts` should reject a feature with a screen and no journey. Find why it did not on Neighborhood: a pinned version or a waiver.
- On Neighborhood, the 2026-10-29 template refit deleted Capture, and no check saw a feature disappear.

## Steps

1. Add `journeys:` to a `risk.yaml` rule: the core journeys and project journeys that a change to its paths must pass. For example, `packages/identity/**` names sign-up, sign-in and roles and access.
2. Make the judge take a held path's PR when each named journey passed on the head, on each platform, and agent review has 0 blocking findings. Take the path out of CODEOWNERS when every one of its journeys exists.
3. Make `tools/journeys/run.ts` fail when the project has a feature and no journey.
4. Hold a PR whose body says `unverified`, or whose verification section names a flow that did not run.
5. Run every journey before and after a Clutch sync or refit, and fail when a route or a feature is gone.
6. Keep the owner hold for a PR that takes a journey off a path, deletes a journey, or weakens one.
7. Remove the owner approval steps from `.agents/skills/deliver/references/pull-requests.md` (the batch approval) and `.agents/skills/run-lanes/SKILL.md`, once no path is held.

## Files

- `.clutch/risk.yaml`, `apps/cli/src/risk/tiers.ts`, `apps/cli/src/risk-command.ts`
- `tools/codeowners.ts`, `tools/github/auto-merge-rules.ts`
- `tools/journeys/run.ts`, `tools/check-journeys.ts` and their tests
- `.agents/skills/deliver/references/pull-requests.md`

## Acceptance criteria

- A PR that changes `packages/identity/**` auto-merges when sign-up, sign-in and roles and access pass on its head, with no owner approval.
- The same PR holds when one of those journeys fails or did not run.
- The `journeys` check fails in a project with a feature and no journey.
- `bun run validate` passes.

## Verify

`mise exec -- bun run validate`, the auto-merge rules tests, and a dry run of the judge on a held PR.
