# CL-441: Hold a PR until the journeys its paths name pass on its head

## Goal

A sensitive path names the journeys that prove it. Its PR merges when those journeys pass on its head and agent review has 0 blocking findings. No owner approval is needed.

## Context

- `docs/principles/proof-gates-code.md`: proof gates code, and a path stays held until its journeys exist and pass.
- `.clutch/risk.yaml` gives each path a tier, and `tools/codeowners.ts` turns the one-way-door paths into CODEOWNERS rules that need the owner. Auto-merge reads the tier in `tools/github/auto-merge-rules.ts`.
- On Neighborhood, `tools/journeys/run.ts` passed the required `journeys` check with no journey and only a warning (`noJourneyNotice`). `tools/check-journeys.ts` should reject a feature with a screen and no journey. Find why it did not on Neighborhood: a pinned version or a waiver.
- On Neighborhood, the 2026-10-29 template refit deleted Capture, and no check saw a feature disappear.

## Steps

1. Find why `tools/check-journeys.ts` did not fail Neighborhood's features with no journey: a pinned Clutch version or a waiver. Fix that cause first.
2. Run every core journey on every PR, whatever its tier. All 7 Neighborhood breaks were on `risk/medium` PRs.
3. Run each journey as the default branch has it, against the PR head. When the PR changes a journey, run its own copy too, and compare the two copies with a check that parses the `outcome(name, expected)` calls of CL-440. The PR's copy passes the check only when:
   - it has every outcome name of the default copy, and may add more
   - each outcome's expected URL, text or stored state is unchanged
   - its budgets, entry and platforms are the same or stricter

   Locators may change freely, so a renamed button or a moved field merges with no owner. Any other change is a weaker journey.

4. Add `journeys:` to a `risk.yaml` rule: the core journeys and project journeys that a change to its paths must pass. For example, `packages/identity/**` names sign-up, sign-in and roles and access.
5. Make the judge take a held path's PR when each named journey passed on the head, on each platform that the change reaches, and agent review has 0 blocking findings. A sensitive path reaches every platform. CL-442 defines the reach of a path. Take the path out of CODEOWNERS when every one of its journeys exists.
6. Make `tools/journeys/run.ts` fail when the project has a feature and no journey.
7. Hold a PR whose body says `unverified`, or whose verification section names a flow that did not run.
8. Compare the routes and features on the PR head with the default branch, on every PR and on each Clutch sync or refit. A renamed route with a redirect passes. A route or feature that disappears with no redirect holds the PR for the owner, since it removes a journey.
9. Hold a PR that takes a journey off a path, deletes a journey, or weakens one by the check of step 3, and ask the owner in a T3 thread (CL-445). It is a product decision, never a diff review.
10. Hold a PR that changes a migration path until its head has a rehearsal record: the migration run on a branch of the production database, with the difference before and after attached. See `docs/principles/two-way-doors.md`.
11. Remove the owner approval steps from `.agents/skills/deliver/references/pull-requests.md` (the batch approval) and `.agents/skills/run-lanes/SKILL.md`, once no path is held.

- the CI workflow that runs the journeys

## Acceptance criteria

- A PR that changes `packages/identity/**` auto-merges when sign-up, sign-in and roles and access pass on its head, with no owner approval.
- The same PR holds when one of those journeys fails or did not run.
- The `journeys` check fails in a project with a feature and no journey. A feature is a `features/<name>/` folder with a screen that an app ships, as `tools/check-journeys.ts` defines it.
- A `risk/medium` PR that breaks sign-in holds.
- A PR that renames a button and updates its journey merges with no owner.
- A PR that removes an assertion from a journey holds, and asks the owner in a T3 thread.
- A PR that swaps an outcome's expected text for a weaker one, at the same count of assertions, holds.
- A PR that changes a migration path with no rehearsal record holds.
- `bun run validate` passes.

## Verify

`mise exec -- bun run validate`, the auto-merge rules tests, and a dry run of the judge on a held PR.
