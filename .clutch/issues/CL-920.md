# CL-920: Test the wake against a real Postgres server

## Goal

A test proves that `WakePostgres` carries each signal between two processes over a real Postgres server, also after its `LISTEN` connection drops.

## Context

CL-918 made live deltas cross server processes through `Wake` (`packages/sync/service/wake.ts`). `WakePostgres` in `packages/sync/runtime/wake.server.ts` uses `LISTEN` and `NOTIFY`. Each test of the wake runs on PGlite, whose `LISTEN` reaches each listener of one database in one process. No test in the repository runs against a real Postgres server, so `WakePostgres` is not proven: not its `pg_notify` inside a transaction, not two connections that hear each other, and not a dropped `LISTEN` connection that listens again.

Each reader of the log reads it again every 30 seconds (`rereadInterval` in `packages/sync/service/event-log.ts`), as a net for a lost wake. CL-584 logs a warning each time that net finds events that no wake announced. This issue is the root fix that the rule "Fix the root bottleneck" asks the net to link: proof that the signal path holds on the real server.

The owner agreed on 2026-11-20 to a Postgres service in CI, and moved this issue from `later` to P5.

## Steps

1. Branch `clutch/cl-920-real-postgres`.
2. Add a Postgres service to CI, with the owner's agreement.
3. Run two `WakePostgres` layers over one real server. Show that a commit in one reaches a live connection of the other, and that a rollback sends nothing.
4. Drop the `LISTEN` connection of one process, such as with `pg_terminate_backend`. Show that it listens again, says `listening`, and that its readers catch up with no timed read.

## Files

- `packages/sync/testing/postgres.ts`, and each `*.postgres.test.ts`
- `packages/sync/service/migrations.ts`, which a test on the real server showed to break when two processes start at once
- `.github/workflows/ci.yml`, `docs/contributing/architecture/server.md`, `docs/contributing/testing.md`

## Acceptance criteria

- A test over a real Postgres server shows each signal crossing two processes.
- A test shows that a dropped `LISTEN` connection recovers, and its readers catch up.
- `server.md` no longer says that `WakePostgres` is not tested.
- CI fails when the tests on the real server are missing, skip, or none passes.
