# CL-113: Make the auto-merge workflow pass workflow lint

## Goal

`validate` passes on main again.

## Context

CL-404 added `auto-merge.yml` with a `workflow_run` trigger. CL-103b added `check-workflow-lint`. The two PRs merged minutes apart, so neither saw the other. zizmor rejects `workflow_run` as a dangerous trigger, at high severity, and `validate` fails on main.

The trigger is needed. A check suite that GitHub Actions creates starts no `check_suite` workflow, so `workflow_run` is the only event that sees CI and agent review complete. The risk is a fork: its branch can carry a `clutch/cl-` name, and the job's token can write pull request comments.

## Steps

1. Branch `clutch/cl-113-auto-merge-lint`.
2. In the `workflow_run` condition of the `decide` job, require `github.event.workflow_run.head_repository.full_name == github.repository`.
3. Add `# zizmor: ignore[dangerous-triggers]` on the `workflow_run:` line, with a comment that gives the reason. Brendan left the choice to lane C on 2026-10-30, asking for the cheap fix that scales.

## Acceptance criteria

- `check-workflow-lint` passes on the branch.
- A fork PR's completed CI run skips the `decide` job.

## Verify

```bash
mise exec -- bun nx run-many -t check-workflows check-workflow-lint
```
