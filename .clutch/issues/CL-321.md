# CL-321: Add the Review phase that compares the built work with the approved prototype

## Goal

No ticket reaches a pull request until the built work matches the prototype that the owner approved and passes its acceptance checks.

## Context

The owner's rule: the approved prototype is the finish line. A part that was left out does not become a follow-up ticket. The ticket goes back to Build.

Review runs in the work thread, after Build and before Deploy opens a pull request.

1. Run the `emil-ui-review` skill on the change, when the ticket changed something a user sees.
2. Take screenshots of the built work at the same widths and states as the prototype. Save them to `~/.local/state/clutch/<project>/tickets/<id>/review/`.
3. Run the `council` skill. Give it the prototype screenshots, the review screenshots, the acceptance checks of the ticket and the diff. Ask one question: does the built work match the approved prototype and pass each check?
4. Save the answer of the council in the same folder, and link the folder with `tickets link --kind evidence`.
5. On a mismatch, set Build back to `ready` with the list of differences as the reason. Review then runs again after Build.
6. On a match, set Review to `done`. For a change that a user sees, post 2 to 4 of the review screenshots in the thread. The owner reads them when the owner wants. The ticket does not wait.

A ticket with no `design` on its route skips steps 1 and 2, and the council checks only the acceptance checks.

The nightly backup covers `~/.local/state`, so the evidence is never lost.

## Steps

1. Branch `clutch/cl-321-review-phase`.
2. Write the `review` entry of the default `.clutch/phases.yaml`, with `needs: [dev_stack]`, and `device` for a project with a native app.
3. Add a `check` that fails when the evidence folder has no council answer.
4. Hand test: one ticket whose build leaves out a part of the prototype on purpose.

## Files

- `.clutch/phases.yaml`
- `apps/cli/src/tickets/` (the evidence check)

## Acceptance criteria

- A build that leaves out a part of the prototype goes back to Build, and the reason names the part.
- A build that matches goes to Deploy with no action from the owner.
- `tickets phase <id> review done` exits 1 when the evidence folder has no council answer.
- `tickets show <id>` lists the evidence folder.
