# CL-540: Add a lint rule that binds keys only in the shortcut registry

## Goal

A key binding outside the shortcut registry fails lint.

## Context

Keyboard first says one shortcut registry holds every action, and no other file defines a key. No check holds the principle, so only review stops a stray `keydown` handler (CL-531). The registry does not exist yet, so the rule names the registry file that the first shortcut adds.

## Steps

1. Branch `clutch/cl-540-shortcut-registry-lint`.
2. Add a rule to `tools/lint/` that fails a key listener, such as `keydown` or `onKeyDown`, outside the registry file. Text inputs that read keys for their own editing are not shortcuts, so name how the rule tells them apart.
3. Turn it on in `oxlint.config.ts`, with tests.
4. In `docs/principles/index.md`, replace `Review only` with the new rule's name, and delete the rule from `docs/contributing/review.md` in the same PR.

## Files

- `tools/lint/`, `oxlint.config.ts`
- `docs/principles/index.md`, `docs/contributing/review.md`

## Acceptance criteria

- A key listener outside the registry fails lint, and the message names the registry.
- The principle's `Held by` cell names the new rule.
