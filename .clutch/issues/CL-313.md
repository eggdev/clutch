# CL-313: Add a verify agent that drives the app on the Spark and posts a screenshot

## Goal

The `verify` agent in each project's tree starts the app on the Spark, drives the changed flow with a browser tool, and posts a screenshot of the result on the PR. Layer 02 "Done when", second half: `verify` posts a screenshot on a PR (CL-609).

## Context

- Layer 02 of the factory stack. CL-515 adds a short `factory/agents/verify/agent.md`. This issue makes it work.
- The local `verify` skill (`.agents/skills/verify/SKILL.md`) owns how a project starts and drives its app. The agent follows that skill. It does not start a second lifecycle.
- The browser tools: `agent-browser`, which is not on the Spark on 2026-11-04, or the T3 device and preview tools, which a T3 lane has.
- GitHub has no API to attach an image to a comment. A screenshot needs a URL that the PR page can show.

## Design (coordinator defaults, 2026-11-04)

- Put the screenshot in the PR's own branch under a path that sync and checks ignore, or on an orphan `verify-shots` branch. Link it from the PR comment by its `blob/<sha>/<path>?raw=true` URL, which shows in a private repository for a reader who has access. Pick the one that keeps `main` free of screenshots, and say why in the PR.
- Add a small `clutch verify post --pr <n> <png>...` command that commits the image and posts the comment with a marker such as `<!-- clutch-verify:<head sha> -->`. The agent prompt calls it. A second run edits the same comment.
- Install `agent-browser` only if the T3 tools do not cover a lane that runs outside T3. Pin its version.

## Steps

1. Branch `clutch/cl-313-verify-agent`.
2. Write the `verify` agent prompt: read the PR and its issue, run the mapped journey or drive the changed screen, take a screenshot on mobile and desktop widths, and post it.
3. Add `clutch verify post`, with tests that fake `gh` and `git`.
4. Run the agent on one open or recent Clutch PR that changes the web app, and post a real screenshot.
5. Document the agent and the command.

## Files

- `factory/agents/verify/agent.md`
- `apps/cli/src/verify-post/` (new) or a module the lane names, its tests, `apps/cli/src/commands.ts`, `apps/cli/README.md`
- `.agents/skills/verify/SKILL.md` only for a link to the agent

## Acceptance criteria

- One Clutch PR has a comment with the marker and a screenshot that shows on the PR page.
- The comment names the head SHA it checked.
- `mise exec -- bun run validate` passes.

## Verify

```bash
mise exec -- bun run clutch verify post --pr <n> /tmp/shot.png
gh pr view <n> --comments | grep clutch-verify
```
