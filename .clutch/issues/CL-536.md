# CL-536: Name the journey that proves each hard invariant, and count the invariants with none

## Goal

Each hard invariant names the journey that proves it, and the count of invariants with no journey only goes down.

## Context

A hard invariant is a promise that the product never breaks, such as who sees which data. `docs/contributing/project-intent.md` says: "A journey proves that each change keeps it." Nothing holds that sentence today. An invariant in `docs/contributing/architecture/primitives.yaml` has `id`, `summary` and `docs`. `tools/check-primitives.ts` asks for the `docs` link only, so an invariant with no journey passes, and no one sees that the promise has no proof. In Bend, a law with no proof fails the check. The Clutch form is softer: an invariant with no journey is allowed, but it is counted, and the count only goes down.

The template has no invariants, because kickoff writes them. So this check works in each project.

One sentence in the repository is false. `tools/guardrail-files.json` exempts `project-intent.md` with the reason "The hard core in .clutch/risk.yaml holds this path by name, so the owner still reviews it." `.clutch/risk.yaml` has no such entry, and it puts `docs/**` in the low tier. The owner decided on 2026-11-13 that no person holds this page for now, so that agents ship more work alone. The guard that asks the owner before a change to a hard invariant comes later, in CL-916. So this issue corrects the sentence and adds no hold.

## Steps

1. Branch `clutch/cl-536-invariant-proof`.
2. Add a required `journey` field to each invariant in `primitives.yaml`. `tools/check-primitives.ts` fails on an invariant with no `journey` field, and on a journey that does not exist.
3. An invariant whose journey is not written yet says so in the field. A ratchet in `.clutch/ratchets.json` counts those invariants, and the count only goes down.
4. Correct the reason for `project-intent.md` in `tools/guardrail-files.json`. It states that no guard holds the page yet, and it names CL-916.
5. Update the kickoff slot in `project-intent.md` and the comment in `primitives.yaml`, so that kickoff writes the journey of each invariant.

## Files

- An invariant with no `journey` field fails `validate`, and the message names the invariant.
- The count of invariants with no journey cannot rise.
- The reason for `project-intent.md` in `guardrail-files.json` is true.
- No path gets a new hold that needs a person.
