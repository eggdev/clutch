# CL-481: Apply the ruleset file to GitHub when it changes

## Goal

A change to a file under `.github/rulesets/` reaches GitHub with no person. If that cannot happen, the merge is not done until a person applies it.

## Context

- `.github/rulesets/main.json` no longer lists `agent-review` as a required check. CL-458 made that change.
- On 2026-11-12 the live ruleset on GitHub still required `agent-review`.
- Nothing runs `clutch ruleset --apply` after a merge.
- `clutch doctor` reports the drift.
- This changes branch protection. The owner decides how it works.

## Steps

1. Branch `clutch/cl-481-apply-rulesets`.
2. Find out first: whether the release bot may write rulesets.
3. Find out first: what the owner wants. He can choose a workflow that applies the file after a merge, or a block until a person applies it.
4. Build the path that the owner chooses. Report the question to the owner before any write to branch protection.

## Files

- `.github/rulesets/main.json`
- The release workflow. Find out first: its file name.
- The code of `clutch ruleset`. Find out first: its file name.

## Acceptance criteria

- After a merge that changes a file under `.github/rulesets/`, GitHub has the same rules as that file.
- Or the merge reports that it is not done.

- `mise exec -- bun run clutch doctor`
- `mise exec -- bun run validate`
