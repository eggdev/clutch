# CL-459: Let a sensitive path pass on its journeys

## Goal

A sensitive path leaves the owner's hold when the journeys that prove it exist on the default branch. This takes steps 5 and 6 of CL-441.

## Context

System review, 2026-11-08: each one-way-door path had no exit from owner approval. Native jobs were not read by the judge, although `tools/journeys/reach.ts` says they are.

## Steps

1. Add `journeys:` to a `.clutch/risk.yaml` rule.
2. Drop a rule when each of its journeys exists, in `clutch risk` and `tools/codeowners.ts`.
3. Hold a PR whose native journey job failed or is running.

## Files

- `.clutch/risk.yaml`, `apps/cli/src/risk/tiers.ts`, `apps/cli/src/risk-command.ts`, `tools/codeowners.ts`, `tools/github/auto-merge.ts`, `tools/github/auto-merge-rules.ts`

## Acceptance criteria

- With each named journey present, `packages/identity/**` is not one-way-door.
- With one missing, it stays one-way-door.
- A failed native job holds the PR.

## Verify

`mise exec -- bun run validate`.
