# CL-475: Make pr merge agree with the server about findings

## Goal

The session path and the server judge use one rule for findings of agent review. A finding holds no merge.

## Context

- The server judge in `tools/github/auto-merge-rules.ts` ignores findings of agent review.
- The session path in `tools/github/merge.ts` still refuses a merge until each `blocking` finding has a "fixed in <sha>" disposition.
- The disposition check is in `tools/github/findings.ts`.
- `blockingGuard` in `tools/github/babysit-answer.ts` sends an unfixed `blocking` finding to the owner.
- `decisionsNow` in `tools/github/babysit-owner.ts` does the same.
- The docs in `.agents/skills/deliver/references/pull-requests.md` and `docs/contributing/review.md` say a finding holds no merge.
- Decision record 0005 says that agent review reports and does not hold. The owner chose that rule.

## Steps

1. Branch `clutch/cl-475-findings-hold-nothing`.
2. Remove the merge refusal for an unfixed `blocking` finding from `tools/github/merge.ts`. Find out first: which tests cover that refusal.
3. Stop `blockingGuard` and `decisionsNow` from sending such a finding to the owner.
4. Keep the rule that the session answers each finding in its thread.
5. Change the tests with the behaviour. Check that the docs still match.

## Files

- `tools/github/merge.ts`, `tools/github/findings.ts`
- `tools/github/babysit-answer.ts`, `tools/github/babysit-owner.ts`
- `tools/github/auto-merge-rules.ts`, for reference only
- `.agents/skills/deliver/references/pull-requests.md`, `docs/contributing/review.md`

## Acceptance criteria

- `pr merge` merges a pull request with an unfixed `blocking` finding when its checks pass.
- The owner gets no decision for an unfixed `blocking` finding.
- The session still answers each finding in its thread.
