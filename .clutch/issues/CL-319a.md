# CL-319a: Add the Triage, Build and Deploy phases to the ticket driver

## Goal

The driver of CL-318 can take a ticket from Triage to the end of Deploy, so CL-319 only changes the pull request tooling.

## Context

CL-319 does not fit one pull request under the size limit, so it splits in two. This part changes the phase file and the driver. CL-319 changes `pr open` and `pr babysit` on top of it. The design and the decisions are in [CL-319](./CL-319.md).

## Steps

1. Branch `clutch/cl-319a-ticket-phases`.
2. Write the `triage`, `build` and `deploy` entries of `.clutch/phases.yaml`, and add its `command` key.
3. Add a reason to `tickets hold`, and show it in `tickets show`.
4. Give the `check` the ticket id in `CLUTCH_TICKET`, and add `tickets merged`.
5. Make `done` ask the work thread for the worktree when the ticket has no `worktree` link.
6. Make `dispatch` remove the worktree and the merged local branches of each finished ticket.
7. Add the capture line to `AGENTS.md`.

## Files

- `.clutch/phases.yaml`, `AGENTS.md`, `.clutch/README.md`
- `apps/cli/src/tickets/store.ts`, `change.ts`, `phases.ts`, `dispatch.ts`, `finish.ts` (new)
- `apps/cli/src/tickets-command.ts`, `apps/cli/src/worktree/prune.ts`

## Acceptance criteria

- With the default phase file, triage of a full bug report starts a Build thread in a new worktree, and the route has no `planning` and no `design`.
- A ticket that triage holds keeps its reason, and no Build thread starts.
- `tickets phase <id> deploy done` exits 1 while a linked pull request is open.
- After the merge, each phase is `done`, and the next dispatch from outside the worktree removes it and its merged branch.
- A store of version 1 opens, and its tickets have no hold reason.
