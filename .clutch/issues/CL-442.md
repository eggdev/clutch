# CL-442: Run each core journey on every device with its quality budgets

## Goal

Each core journey runs on mobile web, desktop web, iOS and Android, and fails on a layout shift, a click over budget, an accessibility error or a visual change from its baseline.

## Context

- `docs/principles/proof-gates-code.md`: a journey runs on every device and meets its budgets.
- `tools/journeys/playwright.config.ts` runs only `Desktop Chrome`. Maestro runs `.maestro.yaml` journeys on a device. The Neighborhood iOS crash ("Property 'crypto' doesn't exist") and the Hermes sign-in crash had no device journey.
- On Neighborhood, the owner found the layout shifts on the email screen by hand.

## Steps

1. Add Playwright projects `Pixel 7` (a mid-range phone, 412 px) and `Desktop Chrome` at 1280 px, the widths in `docs/principles/mobile-first.md`. Both run on every PR.
2. Measure cumulative layout shift in each web journey with `PerformanceObserver`, counting only shifts with no recent input. Fail at the limit in `budgets:` of `clutch.yaml` (default 0.01), and name the shifted element.
3. Count the clicks and key presses in each journey, and fail over its budget.
4. Run axe in each web journey, and fail on any error.
5. Keep a visual baseline per journey and device, and use `tools/journeys/visual-review.ts` for a change.
6. Run each native core journey with Maestro on an iPhone 16 simulator (a `macos` runner) and a Pixel 7 API 35 emulator (an `ubuntu` runner with KVM). Run them on a PR that touches a native app, a shared runtime package or a sensitive path in `.clutch/risk.yaml`, and on each merge to `main`. Write this reach rule in one place, which CL-441's judge reads. Keep each native job under 25 minutes.
7. Retry a failed journey once. A journey that passes on the retry passes the check, and the run files a `flake` friction entry with the journey and the platform.

## Files

- `tools/journeys/playwright.config.ts`, `tools/journeys/run.ts`
- `tools/journeys/visual-review.ts`
- `.github/workflows/ci.yml`
- `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- A web journey with a layout shift fails, and names the shifted element.
- A sign-up journey with 4 clicks fails its budget of 3.
- Each core journey has a web result for both widths on every PR, and native results on a PR that touches native code, shared runtime code or a sensitive path.
- Each journey writes its measures (layout shift, clicks and keys, axe results, timings) to one JSON file, which CL-446 reads.
- `bun run validate` passes.

## Verify

`mise exec -- bun run validate`, and a journey run that adds a layout shift on purpose and fails.
