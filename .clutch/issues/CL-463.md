# CL-463: Hold the gate files, their tests and the agent instructions by rule

## Goal

A change to the code of the merge gate, to a test of that code, or to an agent instruction waits for the owner by a rule. It does not depend on a finding of agent review.

## Context

- `.clutch/risk.yaml` gives `**/*.md` and `**/*.test.ts` the tier `low`, and each unmatched path the tier `medium`. Auto-merge takes both at the step `medium`. So a PR can change `tools/check-*.ts`, `oxlint.config.ts`, the test of a check, or a `SKILL.md`, and merge with no person.
- The one guard is an `owner` finding of agent review, which a language model writes. The council review of 2026-11-12 named this as the largest gap. On PR 251, four review passes gave four different lists of findings.
- `apps/cli/src/risk-command.ts` reads a `guardrails:` key on a rule and adds the patterns of that file to the rule. No rule in `risk.yaml` uses the key.
- Do not hold the whole guardrail list. A feature PR must change some guardrail files: `contract.json`, the generated `packages.ts` lists, a `package.json`, a `tsconfig`, `knip.jsonc` and `.agents/skills/verify/verification.json`. A hold on those would send each feature PR to the owner.
- Decision record 0002 says that rules start permissive and tighten on evidence. The owner asked for this tightening on 2026-11-12.

## Steps

1. Branch `clutch/cl-463-gate-files-by-rule`.
2. Measure first. For the last 100 merged PRs, count how many changed a file of the proposed held set, and how many changed any guardrail file. Put both numbers in the PR body.
3. Split `tools/guardrail-files.json` into two lists: the code of the gate, and the lists that a feature changes. The code of the gate is each check script and its test, the lint plugins and the lint config, the hooks, the budgets, the allow-lists, the journey runner and the workflows.
4. Give the code of the gate the tier `one-way-door` through the `guardrails:` key.
5. Take the agent instructions out of the tier `low`: `AGENTS.md`, `CLAUDE.md`, `.agents/**`, `.claude/**`, `.cursor/**` and `factory/agents/**`. Take the tests under `tools/**` and `apps/cli/**` out of it too.
6. Run `mise exec -- bun tools/codeowners.ts --write`.
7. Move the docs with the rule: `docs/contributing/review.md`, `docs/contributing/harness-engineering.md` and decision record 0002.

## Acceptance criteria

- `clutch risk` gives `one-way-door` for a change to `tools/check-contract.ts`, to `tools/check-contract.test.ts`, to `oxlint.config.ts` and to `.agents/skills/deliver/SKILL.md`.
- It gives `low` for a test and a doc of a product package, and `medium` for a change that only adds a command to `contract.json`.
- `.github/CODEOWNERS` names the owner for each held pattern.
- The PR body states the share of past PRs that the new rule would have held.
