# CL-114: Re-tier risk to Brendan's rule

## Goal

`.clutch/risk.yaml` trusts the agents with product code, and keeps a person on what other teams gate.

## Context

Brendan, 2026-10-30: "This repository is like a template so I'm not wildly concerned about much of anything. But things that are particularly critical to the execution of the automation is important, and anything that will change a billing operation probably. Otherwise for the most part the agents are doing the work so I should be trusting them a lot of the way."

The coordinator's research over the 75-repo dataset found three published risk policies: PostHog `.stamphog/policy.yml`, kody `ship-pr` and openclaw `security-review-policy.yml`. All three hold auth, billing, secrets and infra, migrations and destructive changes, CI config and agent steering for a person. Brendan does not want to depart from that direction without a reason.

## Steps

1. Branch `clutch/cl-114-retier-risk`.
2. `one-way-door`: the guardrail list, `.github/rulesets/**`, `.clutch/risk.yaml`, agent steering, auth and migrations. Add two rules with empty path lists and kickoff slots: billing, and infra, deploy and secrets.
3. `medium`: product code, including `packages/sync/**` (down from `high`), and `bun.lock` (down from `high`). `low`: docs and tests. `unmatched` stays `high`.
4. Note in CL-405 step 1 that a Renovate PR that changes only dependency versions, lockfiles and changesets merges under the bot rule, not under path tiers.
5. Update the tier comments in `risk.yaml` and the risk docs, and add decision 6 to `.clutch/PLAN.md`, which cites the three policies.

## Acceptance criteria

- A change to a workflow, `clutch.yaml`, `package.json`, `AGENTS.md`, a skill, auth code or a migration is `one-way-door`.
- A change to product code, `packages/sync` or `bun.lock` is `medium`.
- An unlisted path is `high`.
