# CL-114: Re-tier risk to Brendan's rule

## Goal

`.clutch/risk.yaml` trusts the agents. Only the automation itself and billing code need a person.

## Context

Brendan, 2026-10-30: "This repository is like a template so I'm not wildly concerned about much of anything. But things that are particularly critical to the execution of the automation is important, and anything that will change a billing operation probably. Otherwise for the most part the agents are doing the work so I should be trusting them a lot of the way."

## Steps

1. Branch `clutch/cl-114-retier-risk`.
2. `one-way-door` holds only two things:
   - Automation-critical files: the guardrail list, `.github/rulesets/**` and `.clutch/risk.yaml`.
   - Billing: a rule whose path list is empty in the template, plus a kickoff slot that names the project's payment and billing code.
3. Migrations become `high`. Auth (`**/auth/**`, `packages/access`, `packages/identity`), agent steering (`AGENTS.md`, `CLAUDE.md`, the skills), `packages/sync/**` and `bun.lock` become `medium`. `unmatched` stays `high`.
4. Note in CL-405 step 1 that a Renovate PR that changes only dependency versions, lockfiles and changesets merges under the bot rule, not under path tiers.
5. Update the tier comments in `risk.yaml`, the risk docs, and add decision 6 to `.clutch/PLAN.md`.

## Acceptance criteria

- A change to a workflow, `clutch.yaml` or `package.json` is `one-way-door`.
- A change to auth code, `AGENTS.md`, a skill, `packages/sync` or `bun.lock` is `medium`.
- A migration is `high`.

## Verify

```bash
mise exec -- bun run clutch risk --json
```

## Notes

- Brendan should confirm migrations at `high`. A deployed migration in a project can lose data, and `high` keeps it out of auto-merge without the code-owner gate of `one-way-door`.
