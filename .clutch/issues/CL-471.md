# CL-471: Require the iOS lane when a change reaches iOS

## Goal

A PR that reaches iOS merges only when the iOS journey passed on its head.

## Context

- `tools/journeys/reach.ts` states which platforms a change reaches, and its comment says that the merge judge reads it. Only `ci.yml` reads it.
- `native-ios` is not in the required checks of `.github/rulesets/main.json`. A ruleset cannot require a check for some PRs only, so the judge must hold the rule.
- The lane must be able to pass first: see CL-469.

## Steps

1. Branch `clutch/cl-471-require-ios-lane`.
2. Write the failing tests first, in the tests of `tools/github/auto-merge-rules.ts`.
3. In the judge, read the reach of the PR. When it reaches iOS, hold the PR until `native-ios` passed on the head.
4. Give `pr status` and `pr merge` the same verdict.
5. Move `docs/contributing/end-to-end-testing.md` and `docs/principles/proof-gates-code.md` with the rule.

## Files

- `tools/github/auto-merge-rules.ts`, `tools/github/auto-merge.ts`, `tools/github/merge.ts`, `tools/journeys/reach.ts`
- `docs/contributing/end-to-end-testing.md`, `docs/principles/proof-gates-code.md`

## Acceptance criteria

- A PR that changes `packages/sync` does not merge while `native-ios` is red or missing.
- A PR that changes only docs is not held by this rule.

## Verify

- `mise exec -- bun test tools/github tools/journeys`
- `mise exec -- bun run validate`
