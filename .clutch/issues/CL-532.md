# CL-532: Prove the claims of each contract with one test on generated inputs

## Goal

Each claim that a contract makes about a command is proven on generated inputs, by one shared test that reads the contract.

## Context

In Bend, a person writes each law once and a proof holds it for every input. TypeScript has no proof checker, so a test on generated inputs is the nearest form. It tries many inputs, not all of them.

Clutch already states its laws in one place: the contract. A command in `packages/notes/contract/notes.ts` declares `idempotent: true`, what it `does`, what it `refuses`, and the limits of each input field, such as the longest title. Those are laws, and few of them have a proof. A test proves a claim only where a person wrote that test by hand.

The parts for one shared test exist. `createPool(client.localChanges, client.contract)` and `pool.run(command, input)` run any command of any contract. The declared fields say what a valid input is. `packages/sync/runtime/pool-conformance.test.ts` has a seeded generator.

So the laws stay in the contract, and no new file lists them. The test runs under `bun test`. Add no test runner and no package.

## Steps

1. Branch `clutch/cl-532-contract-claims`.
2. Move the seeded generator out of `pool-conformance.test.ts` into `packages/sync/testing/`.
3. Add one function in `packages/sync/testing/` that takes a contract and its local changes. It makes valid inputs from the declared fields of each command, runs the commands on a pool, and checks each claim.
4. Check these claims first. A command with `idempotent: true` changes nothing on a repeat. An input outside a declared limit is refused. A command does what its `does` says: it adds, changes or removes.
5. Call the function for `packages/notes` and `packages/access`, in one `bun test` file each. A failing run prints the seed and the inputs that broke the claim.
6. Extend `tools/check-contract.ts`. It fails on a package that has a contract and no call of the function. Add no new check target.
7. Describe the claims and their proof in `docs/contributing/architecture/contract.md`.

## Files

- `packages/sync/testing/`, `packages/sync/runtime/pool-conformance.test.ts`
- `packages/notes/`, `packages/access/`
- `tools/check-contract.ts`, `tools/check-contract.test.ts`
- `docs/contributing/architecture/contract.md`

## Acceptance criteria

- A local change that breaks the idempotence of `notes/rename` fails the notes test, and the output shows the seed.
- A package with a contract and no call of the function fails `validate`.
- The repository has no new test runner, no new package and no new check target.
- No declaration of `packages/sync/contract/` changes.
