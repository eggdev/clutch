# CL-031: Enforce conventional commits

## Goal

Every commit and every PR title follows Conventional Commits, so a change's type decides its version bump (decision by Brendan, 2026-10-30).

## Steps

1. Add a `commit-msg` hook in `.githooks/` that checks `type(scope)!: subject`, with the types `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci` and `chore`. Prefer a small check in `tools/hooks/` over a new dependency. Look at Bar Savvy's commitlint setup first.
2. Make `bun run pr open` refuse a PR title that is not conventional.
3. Update `.clutch/README.md`, the deliver skill's pull request rules and the commit guidance in docs. The old rule was an imperative subject with no prefix.
4. Tests for the hook and the title check.

## Acceptance criteria

- A commit message such as `Add a thing` is rejected, and `feat(cli): add a thing` passes.
- validate passes.
