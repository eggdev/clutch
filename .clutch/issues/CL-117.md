# CL-117: Add repeatable PR lifecycle commands to bun run pr

## Goal

Each agent, in each project made from Clutch, follows a PR to green and merges it with the same commands, not with hand-written `gh` loops.

## Context

The coordinator audited 413 shell commands that three lanes ran on 2026-10-30. Each lane hand-wrote the same loops: check polling, log digging, tracker rebases and the done commit. Lane A had to run `gh stack merge` by hand, because `pr merge` sent a PR that GitHub still counted as stacked to the plain merge.

## Steps

1. Branch `clutch/cl-117-pr-lifecycle`.
2. Add `pr status`, `pr wait`, `pr failures`, `pr sync` and `pr ready` to `tools/github/pr.ts`.
3. Make `pr merge` retry through `gh stack merge` when GitHub refuses a plain merge for its stack, then wait for the release run and print the version.
4. Read the repository from `origin` and the agent branch prefix from `pr.branchPrefix` in `clutch.yaml`, with `clutch/cl-` as the default. Change the tracker through `tools/clutch.ts`, so a project runs the release binary.
5. Document each command in `.agents/skills/deliver/references/pull-requests.md`, and link the command index (CL-120).
6. Test with a fake `gh`. Also run the commands in a project that `clutch init` made with the release binary.

## Files

- `tools/github/pr.ts`, `status.ts`, `failures.ts`, `branch.ts`, `merge.ts`, `github.ts`
- `tools/github/lifecycle.test.ts`, `tools/github/project.test.ts`
- `apps/cli/src/clutch-config/schema.ts`
- `.agents/skills/deliver/references/pull-requests.md`

## Acceptance criteria

- Each new command works in a project made by `clutch init`, with no Clutch source.
- `pr merge` merges a PR that GitHub still counts as stacked, and reports the release.
- A PR without a changeset still fails `check-changeset`, and `pr sync` stops on a conflict outside the tracker.

## Verify

```bash
mise exec -- bun test tools/github
mise exec -- bun run pr status <number>
```
