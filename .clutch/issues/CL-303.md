# CL-303: Run CI on the affected scope for PRs

## Goal

PR CI runs `nx affected` against the PR base. Main runs everything.

## Context

- `.github/workflows/ci.yml` already sets `fetch-depth: 0` and passes `CHECK_BASE` to `bun run validate`. For a PR it is `origin/<base_ref>`. For a push it is `github.event.before`.
- `tools/hooks/pre-push.ts` finds its base with `git merge-base` against `origin/HEAD` or `origin/main`. `tools/hooks/paths.mjs` defines docs-only.
- CL-204 (`clutch checks --changed`) needs the same base. Share one base helper with it.
- `ci.yml` has no `merge_group` trigger.

## Steps

1. Branch `clutch/cl-303-affected-ci`.
2. In `ci.yml`, for a PR, pass `--base=$CHECK_BASE`. Keep root checks always on: run `nx run clutch:checks` unconditionally, then `nx affected -t <same targets as validate> --base=$CHECK_BASE`. Do not gate `checks` on affected output, because root checks are global.
3. Guard a `CHECK_BASE` of all zeros. That is `github.event.before` for a new branch or a force push. Fall back to the full run.
4. On `push` to main, keep `bun run validate`.
5. Adopt `changed_scope_check`.

## Acceptance criteria

- A docs-only PR runs only `checks`.
- A main push runs the full validate.
- An all-zero base runs the full validate, and a test covers it.

## Verify

```bash
gh run list --workflow ci.yml --limit 3
```
