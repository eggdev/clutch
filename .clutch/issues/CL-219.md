# CL-219: Make a sync land with no hand fixes

## Goal

A Clutch sync PR changes only what `clutch sync` writes, so the bot rule can merge it without a person. Neighborhood's sync to v0.40.0 (its PR #37) needed four hand fixes, and a bot sync would have failed on each.

## Context

- Managed files linked docs that sync never ships. `packages/journeys/README.md` linked `docs/contributing/capabilities/a11y-checks.md`, which sits under the `docs/` seed, so a project installed before the page existed never got it.
- A project needs a knip entry and a primitive claim for `packages/journeys`. Neither reached a project through sync.
- The `clutch` pin in `mise.toml` never moved, because sync treated the file as kept.
- The v0.40.0 binary and the source wrote `.claude/settings.json` differently. The binary formatted with the project's oxfmt config and the source with the clone's, so `.claude/**` was formatted by one and ignored by the other.

## Steps

1. Managed links: a managed Markdown link, and a `docs/` path named in a workflow or devcontainer file, must point at a path that a project gets. A capability page is linked by its GitHub URL. `tools/check-managed-links.ts` checks this.
2. Journeys: `knip.jsonc` gets a `packages/journeys` workspace entry for the helper, as Neighborhood's PR #37 does. The primitives registry is a merge file, so each shipped folder joins the primitive with the same id.
3. Pin: sync moves the version of the clutch tool line in `mise.toml` to the release it syncs to. A release that moves only the pin asks nothing.
4. Formatting: the CLI formats with the project's own `.oxfmtrc.json` when it has one, so the source and the binary write the same bytes.

## Acceptance criteria

- A managed link to a capability page by path fails `check-managed-links`, and a link to an excluded or uncovered path fails too.
- `clutch sync` moves the pin in `mise.toml` and leaves the rest of the file alone, and a release that moves only the pin asks nothing.
- The source and the v0.40.0 binary write the same `.claude/settings.json` for the same project.
- A new primitive folder that sync ships is claimed by the primitive with the same id.
