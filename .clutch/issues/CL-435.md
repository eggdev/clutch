# CL-435: Push the babysitter's commit from a job that never ran the PR's code

## Goal

The release bot token never shares a runner with code from the PR, so a PR cannot steal it.

## Context

- `.github/workflows/babysit.yml` (CL-420) runs `bun install` and `validate` on the PR's code in the Validate step. A later step in the same job mints the bot token and runs `git push` with the token in the URL.
- Code from the PR runs as the same user, with the same `$HOME` and `$RUNNER_TEMP`. It can write `~/.gitconfig` (an `insteadOf` rule or a credential helper), or leave a process that reads the `git push` command line from `/proc`. The comment "No code from the PR runs while the token is set" is not true.
- Agent review raised this as an owner finding on Neighborhood PR https://github.com/eggdev/neighborhood/pull/68 (comment 4475216379). Brendan chose on 2026-11-05 to merge that sync and fix the flaw here.
- A dependency in a Renovate PR is the realistic attacker. The token has `contents`, `pull-requests`, `issues` and `actions` write.

## Steps

1. Branch `clutch/cl-435-babysit-push-job`.
2. Split the push into a second job that needs the first. The first job uploads the validated commit as a git bundle artifact. The second job checks out nothing from the PR, fetches the bundle into a fresh repository, mints the token and pushes.
3. Move the replies, the thread resolves and the reruns that need the bot token into the second job too.
4. Pass the token to git with `GIT_CONFIG_GLOBAL=/dev/null` and an `http.extraHeader`, not in the URL.
5. Add a `check-workflows` rule, with a test, that fails when a job both runs `validate` or `bun install` on PR code and mints the bot token.

## Files

- `.github/workflows/babysit.yml`
- `tools/check-workflows.ts` and its test
- `docs/contributing/agent-review.md` or the babysit skill, where the token boundary is described

## Acceptance criteria

- No job in `babysit.yml` both runs the PR's code and holds the bot token.
- The new `check-workflows` rule fails on a fixture that does both.
- `mise exec -- bun run validate` passes.

## Verify

```bash
mise exec -- bun run validate
grep -n "create-github-app-token\|bun run validate" .github/workflows/babysit.yml
```
