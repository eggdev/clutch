# CL-126: Move the validate runner into tools/ so projects get it on sync

## Goal

A synced project gets each change to `validate` without a decision on its `package.json` scripts.

## Context

CL-125 put `--outputStyle=static-failures-only` in the `validate` and `check` scripts. `clutch sync` merges `package.json` key by key with no baseline, so each change to `scripts.validate` asks every project to keep or take it. `tools/` is managed, so a change to a file there arrives with no decision.

## Steps

1. Branch `clutch/cl-126-validate-runner`.
2. Add `tools/validate.ts`. It holds the target lists, and it runs `nx run-many --outputStyle=static-failures-only`. `--quick` runs the `check` subset. Add `tools/validate.test.ts`.
3. Set the scripts to `"validate": "bun tools/validate.ts"` and `"check": "bun tools/validate.ts --quick"`. The pre-push hook calls `runTargets`.
4. List `tools/validate.ts` as a guardrail file, because it decides which checks run.
5. Prove a project synced from the release before CL-125 gets the runner.

## Acceptance criteria

- A planted type error makes `validate` print the error inline.
- A sync from the old release to this branch writes `tools/validate.ts` and asks one decision, `package.json#scripts.validate`. After a take, the project's `validate` prints a failure inline.

## Verify

```bash
mise exec -- bun test tools/validate.test.ts
mise exec -- bun run validate
```
