# CL-564: The escape hatch table lists the observed checks and the pushes with no hooks

## Goal

The docs name the two escape hatches that CL-559 and CL-562 added, so review sees a change to either one.

## Context

Agent review gave two pull requests findings after their merge.

On pull request 292 (CL-559): the list `observedTargets` in `tools/validate.ts` stops a listed check from blocking. That is an escape hatch, and the escape hatch table in `docs/contributing/harness-engineering.md` had no row for it. A pull request can also move a blocking check back to the observed list, and `check-scope` does not stop that.

On pull request 295 (CL-562): the gardening workflow pushes with the Git hooks off. No page said so, and the table had no row for a workflow push with no hooks.

## Steps

1. Branch `clutch/cl-564-hatch-rows`.
2. Add a row for the observed list and a row for a workflow push with no Git hook to the escape hatch table.
3. Say in the section "Weekly gardening" that the workflow commits and pushes with the hooks off, and why.
4. Say in `docs/contributing/setup/checks.md` which workflows push with no hook, and that a check moved back to the observed list is a weaker check.

## Files

- `docs/contributing/harness-engineering.md`
- `docs/contributing/setup/checks.md`

## Acceptance criteria

- The escape hatch table has a row for each of the two hatches.
- Each new sentence is true for the code.
