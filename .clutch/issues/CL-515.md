# CL-515: Add the factory_as_code capability and ship a starter tree with sync

## Goal

`clutch doctor` reports whether a project has a factory tree that passes its check, and `clutch sync` gives each project a starter tree. Layer 00 "Done when": Neighborhood has the tree on `main` through a sync PR (CL-608).

## Context

- Layer 00 of the factory stack. CL-514 defines the schema and `clutch factory --check`. The schema follows C-Suite's `docs/stack.md` on `main` and C-Suite's live tree. Those win over the old CL-514 Design defaults. Read `docs/contributing/architecture/factory-tree.md` first.
- Sync rules are in `clutch.files.yaml`. A `seed` file is written once, and the project owns it after that. Sync names each later Clutch change to a seed file with a compare link (`apps/cli/src/sync/seed-changes.ts`). Agent prompts are tuned for each project, and self-improvement PRs change them, so the tree is a seed.
- Before CL-515, only install wrote a seed file, so a project that already synced never got a new one. `add_on_sync: true` on a seed entry makes sync add each file under it that the project lacks, once. `seeded` in `.clutch/lineage.json` lists each file that install or sync wrote or found, so a file that the project deleted does not come back (`apps/cli/src/sync/seed-adds.ts`).
- Bar Savvy is in doctor mode on `epic/refactor` (CL-701), so sync does not run there yet. Doctor reports the gap there.

## Steps

1. Branch `clutch/cl-515-factory-capability`.
2. Add `factory_as_code` to `docs/contributing/capabilities/registry.yaml`: category `Agent context`, phase `P5`, level `extra`. It is present when `factory/agents/*/agent.md` exists. Doctor also runs the CL-514 check, and reports the capability as broken when the check fails, if the doctor rules allow that. Otherwise the lane files the gap with `clutch issues new`.
3. Write `docs/contributing/capabilities/factory-as-code.md` with the Why, Detection, Adopt and Waive sections, as the other pages have.
4. Add Clutch's own tree at `factory/`, with a header comment or a README that links the schema page:
   - `models.yaml`: `claude-opus-5-5`, `claude-sonnet-5-5`, `qwen3.6` and `qwen3.8-27b`, in the order of C-Suite's `models.yaml`, then the Codex model for `review`: `gpt-6-luna`, the model that `codex` on the Spark runs by default.
   - `runners/spark.yaml`: as C-Suite's, with the setup commands from `worktree.setup` in `clutch.yaml`.
   - `agents/triage`, `agents/spec`, `agents/implement`, `agents/review` and `agents/verify`, each with a short prompt that names the skill it follows. CL-314 makes the prompts complete. Models: Claude for `implement` and `spec`, Codex for `review`, Claude for `verify`, and Claude for `triage` until a Qwen scorer proves it is good enough (CL-426). No foreman: C-Suite owns it.
5. Ship the tree as `seed` in `clutch.files.yaml`, with `capability: factory_as_code` and `add_on_sync: true`. Confirm that `clutch sync` writes it into a project that has none, and leaves a project's edits alone after that.
6. Set `factory_as_code: adopted` in Clutch's `clutch.yaml`, and refresh the doctor baseline.

## Files

- `docs/contributing/capabilities/registry.yaml`, `docs/contributing/capabilities/factory-as-code.md`, the capabilities index
- `apps/cli/src/doctor/`: the `factory` detect rule (`agents` and `check`)
- `apps/cli/src/sync/`: `add_on_sync` for a seed entry
- `factory/` (new)
- `clutch.files.yaml`, `clutch.yaml`, the doctor baseline

## Acceptance criteria

- `clutch doctor` lists `factory_as_code` as present in Clutch, and as a gap in a project with no tree.
- `clutch sync` in a scratch project that has no tree writes `factory/`, and `clutch factory --check` passes there.
- A second sync after an edit to `factory/agents/implement/agent.md` keeps the edit, and names any Clutch change with a link.
- `mise exec -- bun run validate` passes.
