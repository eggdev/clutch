# CL-231: Retry GitHub errors and re-decide stale PRs in auto-merge

## Goal

Auto-merge does not fail on a moment of GitHub trouble, and a green PR that was never decided gets decided.

## Context

On Neighborhood #53 the Auto-merge decide job failed on one `HTTP 503` from `gh repo view`, and the Labels apply job failed on one 503 from `gh api`. Both passed on a re-run. Neighborhood revert #49 was opened before the new rules reached main, and its decision was never re-run, so it sat green until someone pushed to its branch.

## Steps

1. The auto-merge runner retries a `gh` read up to 3 times on a transient error. A write is never retried, since a 5xx on a write may have taken effect.
2. The Labels apply step retries its label creates, adds and reads, which are idempotent. A removal runs once.
3. Auto-merge gains a `workflow_dispatch` trigger with a PR number. The hourly sweep (`auto-merge-sweep.yml`) dispatches it for each green PR with no verdict for its head, or whose last decide run failed. It runs on a push that changes an auto-merge rule file.

## Files

- `tools/github/gh-retry.ts`, `tools/github/command.ts` and their test
- `tools/github/auto-merge-sweep.ts` and its test
- `tools/github/auto-merge.ts` (its runner moves to `command.ts`)
- `.github/workflows/auto-merge.yml`, `.github/workflows/auto-merge-sweep.yml`, `.github/workflows/labels.yml`
- `.agents/skills/deliver/references/pull-requests.md`

## Acceptance criteria

- A transient `gh` read failure succeeds on a retry, and a non-transient one or any write does not retry.
- The sweep dispatches at most 20 PRs a run, the least recently decided first, and nothing while auto-merge is off.
- The sweep holds only `actions: write`, `pull-requests: read`, `checks: read` and `contents: read`.

## Verify

`mise exec -- bun test tools/github/gh-retry.test.ts tools/github/auto-merge-sweep.test.ts`, then `mise exec -- bun run validate`.
