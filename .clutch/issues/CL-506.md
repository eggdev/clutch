# CL-506: Snapshot the public surface of Clutch and fail on a silent break

## Goal

A change that removes or renames a `clutch` flag, a `clutch.yaml` key, a `doctor --json` field or a managed file fails CI unless it carries a deprecation note.

## Context

In the 2026-10-30 research over 58 repositories (see `.clutch/PLAN.md`), 30% of top repositories run API contract checks, against 9% of the rest. Clutch releases on every merge, and projects follow the latest release, so a break reaches them at once. v0.4.0 renamed `templateCommit` to `templateRelease` with only a person noticing.

## Steps

1. Branch `clutch/cl-506-surface`.
2. Add `clutch surface --json`: the commands and flags from `apps/cli/src/commands.ts`, the `clutch.yaml` schema keys, the `doctor --json` fields and the managed paths in `clutch.files.yaml`.
3. Commit the output as `apps/cli/surface.json`, and add a `check-surface` target to `checks`.
4. An item that disappears fails, unless a changeset in the PR is breaking (`!`) or names it under a `Deprecated:` line (CL-507).

## Files

- `apps/cli/src/surface.ts`, `apps/cli/surface.json`
- `tools/check-surface.ts`
- `package.json`

## Acceptance criteria

- Removing a flag without a breaking changeset fails `check-surface`.
- Adding a flag updates the snapshot and passes.
