# CL-003: Add a subcommand router and the clutch issues command

## Goal

Give the CLI a small command table, and add `clutch issues` to list, pick, update and render the tracker.

## Context

- `apps/cli/src/main.ts` dispatches by hand: `if (process.argv[2] === 'review') ...`. With no subcommand it runs the install and kickoff flow.
- `apps/cli/src/review-command.ts` is the pattern for a command: `node:util` `parseArgs`, `--check`, `--json`, exit codes 0 (ok), 2 (planned or drift under `--check`), 1 (error), JSON errors `{schemaVersion:1,status:'error',message}`.
- Tests use `bun:test`, `@/testing/git-repo` (`gitRepo`) and `@/testing/fake-bin`. The CLI test target runs under `tools/test-budget.ts 60`, so keep tests fast.
- Source files are capped at 400 lines (`tools/file-size-budgets.json` `limit`). Suppression comments fail `check-suppressions`. knip fails on unused exports.

## Steps

1. Branch `clutch/cl-003-issues`.
2. Add `apps/cli/src/commands.ts`: `export const commands: Record<string, { summary: string; run: (args: Array<string>, cwd: string) => Promise<number> }>`. Register `review` (wrap `reviewCommand`), `install` (the current default flow), and `issues`.
3. Edit `main.ts`: when `argv[2]` is a key of `commands`, run it and `process.exit(code)`. With no subcommand or a leading flag (for example `--yes`, `--agent`), keep the current install flow so `template --yes` keeps working. `--help` lists the commands from the table.
4. Add `apps/cli/src/issues/parse.ts`: read `.clutch/issues/*.md`, parse the frontmatter with the `yaml` package. Fields: `id` (`CL-\d{3}[a-z]?`), `title`, `phase` (`P0`..`P5`, `RN`, `RB`, `later`), `status` (`todo|in_progress|blocked|review|done`), `depends_on` (list of ids), `pr` (URL or empty), `owner` (`agent|brendan`). Return typed records and a list of errors (unknown field, bad value, unknown dependency, dependency cycle, file name not equal to id).
5. Add `apps/cli/src/issues/render.ts`: render `.clutch/TRACKER.md` from records. Layout: a header line "Generated by `clutch issues --write`. Do not edit by hand.", a count table by phase and status, then one table per phase with columns `ID | Title | Status | Depends on | PR | Owner`, sorted by id.
6. Add `apps/cli/src/issues/next.ts`: the next issue is the first record, in phase order P0, P1, P2, P3, P4, P5, RN, RB and then id order, where `status: todo`, `owner: agent`, and every dependency has `status: done`. It never picks a `later` issue. Those are backlog until Brendan moves them to a phase. With `--stack`, a dependency in `review` also counts, up to a stack depth of 3.
7. Add `apps/cli/src/issues-command.ts` with these forms:
   - `clutch issues` prints the table.
   - `clutch issues --write` rewrites TRACKER.md.
   - `--write` formats TRACKER.md with oxfmt (the same way `install-template.ts` formats from `cliRoot`), so `format-check` and `issues --check` agree.
   - `clutch issues --check` exits 2 when TRACKER.md is stale and 1 on parse errors.
   - `clutch issues next [--stack] [--json]` prints the next issue id, title and file path, or exits 1 with "no unblocked issue".
   - `clutch issues set <id> <status> [--pr <url>] [--owner <owner>]` edits only that file's frontmatter and then rewrites TRACKER.md.
   - `--json` gives `{schemaVersion:1, issues:[...], errors:[...]}`.
8. Tests: `apps/cli/src/issues/*.test.ts` and `issues-command.test.ts` cover parse errors, cycle detection, next selection with and without `--stack`, set, and `--check` exit codes.
9. Run `mise exec -- bun run clutch issues --write` and commit the regenerated TRACKER.md.
10. Update `apps/cli/README.md` with a short "Issues" section.

## Notes

- `bun run format` runs oxfmt over `.clutch/**`. It pads the tables in `TRACKER.md` and turns frontmatter double quotes into single quotes. `clutch issues --write` must write oxfmt's output (or run oxfmt on the file), or `--check` and `format-check` disagree.
