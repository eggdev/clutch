# CL-103: Pin GitHub Actions to commit SHAs and enforce it in check-workflows

## Goal

Every `uses:` pins a full commit SHA, and `check-workflows` keeps it that way.

## Context

There are 15 `uses:` lines in five workflow files: `agent-review.yml`, `ci.yml`, `clutch-doctor.yml`, `gardening.yml` and `release.yml`. `check-workflows` already exists and runs in `checks`. It has no SHA rule yet, so `ci_security_lint` is partial today. The actionlint and zizmor linters are in CL-103b.

## Steps

1. Branch `clutch/cl-103-pin-actions`.
2. Pin each `uses: owner/action@vN` in `.github/workflows/*.yml` to `@<40-hex sha> # vN`. Resolve each SHA with `gh api repos/<owner>/<action>/git/ref/tags/<tag>`. Dereference annotated tags.
3. Extend `tools/check-workflows.ts` with a rule in the pure `findWorkflowErrors`: a `uses:` ref must be a 40-hex SHA unless it is a local `./` path. The fix message names the `gh api` command.
4. Add tests for the rule in a new file, `tools/check-workflows.test.ts`.
5. Update the `check-workflows` row in `docs/contributing/setup/checks.md` to name an unpinned `uses:`. In the CI section, add a bullet for the SHA pins, and change "the other two rules" to "the other three rules".
6. In `clutch.yaml`, replace the `ci_security_lint` waiver with `ci_security_lint: adopted`. Then run `mise exec -- bun run clutch doctor --write-baseline`.

## Acceptance criteria

- `rg -n 'uses: [^.].*@v[0-9]' .github/workflows` prints nothing.
- `check-workflows` passes.
- `clutch doctor --check` passes with `ci_security_lint` adopted.

## Verify

```bash

mise exec -- bun nx run check-workflows
```
