# CL-010: Add the clutch doctor report

## Goal

`clutch doctor` prints each capability's detected status, its declared decision from `clutch.yaml`, and a summary. `--json` gives a stable machine format.

## Steps

1. Branch `clutch/cl-010-doctor`.
2. Add `apps/cli/src/doctor-command.ts`. The usage is `clutch doctor [--root DIR] [--json] [--remote] [--category C] [--phase P]`.
   - `--root` defaults to cwd. The registry comes from the Clutch checkout the CLI runs from (`path.resolve(import.meta.dir, '../../..')`), not from `--root`. Downstream repos then get the registry of their pinned Clutch commit.
3. Text output: one line per capability, grouped by category: `<status icon> <id>  <detected>  <declared>  <evidence or reason>`. Then a summary line with counts of present, partial, missing and unknown, and counts of adopted, waived, n/a and undeclared.
4. JSON output: `{schemaVersion:1, root, templateCommit, registryCommit, results:[{id,name,category,phase,level,detected,declared,reason,issue,evidence}], summary:{...}}`.
5. Exit 0 in report mode (the gate lands in CL-011). Exit 1 on a registry or config error.
6. Register `doctor` in `commands.ts`. Tests use a `gitRepo` fixture with a small `clutch.yaml`.
7. Snapshot the JSON shape in a test, without timestamps.

## Files

- add `apps/cli/src/doctor-command.ts` plus test
- edit `apps/cli/src/commands.ts`, `apps/cli/README.md`

## Acceptance criteria

- `clutch doctor` on the template prints 36 lines and a summary.
- `clutch doctor --json | jq '.results | length'` prints 36.
- Running from a Clutch checkout with `--root ../neighborhood` works without Clutch files in that repo (declared = `undeclared`).
