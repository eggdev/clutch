# CL-469: Restore the built iOS app in CI by its native fingerprint

## Goal

The iOS lane of CI finishes inside its time limit. It builds the native app only when the native fingerprint has no saved build.

## Context

- On PR 251 the lane reached the native build with Xcode 26.3. About 6 minutes of setup came first, and the build did not finish in the 19 minutes that were left of the 25-minute limit.
- A JavaScript-only change keeps the native fingerprint, so it needs no native build. `native:build` holds that rule on a developer's machine, and CI builds each time.
- The step `Make the dev server names resolve` took 63 seconds, because the first `dev --check` waits for names that do not resolve yet.
- The owner chose the cache on 2026-11-12, and said that most builds will be local. See CL-470 for the build service of Expo.

## Steps

1. Branch `clutch/cl-469-ios-build-cache`.
2. Give `native:build` a way to print the fingerprint hash of the checkout.
3. In the job, restore the built app with `actions/cache`, keyed by that hash. On a hit, install the app and skip the build. On a miss, build and save.
4. Measure one cold build on the runner, and put the time in the PR body. When a cold build cannot fit the limit, say so and stop: that is a decision for the owner.
5. Write the hosts entries before the first `dev --check`.

## Files

- `.github/workflows/ci.yml`, `tools/native/build.ts`, `tools/native/native.test.ts`

## Acceptance criteria

- A PR that changes no native input runs the iOS journey in CI with no native build, and passes.
- The cache key changes when a native dependency or a config plugin changes.

## Verify

- `mise exec -- bun test tools/native`
- The `native-ios` job of the PR, twice: one miss and one hit.
