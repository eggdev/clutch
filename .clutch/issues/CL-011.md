# CL-011: Add the clutch doctor --check gate with waivers and a regression baseline

## Goal

`clutch doctor --check` fails when:

- an adopted capability is not present
- a core capability is missing or partial without a waiver or n/a
- a waiver has expired
- a capability that was present in the baseline is no longer present

## Rules

- Adopted plus present passes. Adopted plus partial or missing fails as "adopted but not present".
- Undeclared plus core plus not present fails as an unwaived gap. Undeclared plus extra gives a warning.
- A waiver fails when `until` is in the past or when `issue` has `status: done` in `.clutch/issues/`. The fix is to adopt it or renew the waiver.
- `remote` rules that are `unknown` never fail `--check`. Only `--check --remote` evaluates them.
- Regression: `.clutch/doctor-baseline.json` maps `{id: detected}`. A capability that drops from present to partial or missing, or from partial to missing, fails. `clutch doctor --write-baseline` rewrites it. The baseline file may only move up. `--write-baseline` refuses a downgrade unless `--allow-downgrade` is given, and the PR then needs Brendan (stop condition).
- Exit codes: 0 ok, 1 failure, 2 baseline stale (a capability improved and the baseline was not raised), matching the `--check` convention of the sync command (CL-013).

## Steps

1. Branch `clutch/cl-011-doctor-check`.
2. Add `apps/cli/src/doctor/gate.ts` and `apps/cli/src/doctor/baseline.ts` with unit tests for each rule.
3. Fill the template's `clutch.yaml`:
   - set `adopted` for each capability present today
   - set `waived` for each core gap, with `reason: Lands in CL-NNN.` and `issue: CL-NNN`, using the phase map in Appendix B
   - set `n/a` only with a reason
4. Run `clutch doctor --write-baseline` and commit `.clutch/doctor-baseline.json`.
5. Add the baseline file to `tools/guardrail-files.json` and CODEOWNERS.
6. Each fix message names the command to run and links the capability doc, following the template rule "make failures teach the fix".

## Acceptance criteria

- `clutch doctor --check` exits 0 on the template.
- Deleting `.github/CODEOWNERS` in a scratch copy makes it exit 1 with "regression: codeowners present -> missing".
- Removing a waiver for `codeql_sast` makes it exit 1 with "unwaived gap".
- Setting `CL-102` to done in a scratch copy makes the `codeql_sast` waiver fail.
