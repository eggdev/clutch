# CL-234: Name the project-owned pages whose Clutch copy changed in a sync

## Goal

When `clutch sync` moves a project to a newer release, it lists each seed page (project-owned, never written by sync) whose Clutch copy changed, with a link to see the change. The reviewer of the sync PR then ports what applies.

## Context

- Neighborhood's sync to v0.44.2 (Neighborhood #53) brought Clutch's new agent-review and auto-revert behavior. Three pages that describe it are seed files, so sync left them alone: `docs/contributing/review.md`, `docs/contributing/operations/rollback.md` and `docs/contributing/setup/checks.md`.
- Agent review blocked #53 three times for "docs did not move with behavior". A person ported Clutch's lines by hand each time.

## Steps

1. `apps/cli/src/sync/seed-changes.ts`: diff the seed paths of the target against the lineage release, and keep the files that exist in the project.
2. `runSync` adds `seedChanges` and `seedChangesNote` to the result. The sync shows them in text and `--json`, and the sync PR body in `clutch-sync.yml` gets a section for them.
3. Tests with a fixture, and a read-only dry run against Neighborhood's history.
4. Docs: the sync section of the CLI README.

## Files

- apps/cli/src/sync/seed-changes.ts (new)

- apps/cli/README.md

## Acceptance criteria

- A seed page that Clutch changed between the lineage release and the target is listed, with its path and a link.
- An unchanged seed page, a managed file and a seed page the project deleted are not listed.
- The list never fails the sync and never edits a seed page. A failure to read the lineage release becomes a note.
- Neighborhood's v0.40.0 to v0.44.2 list includes `review.md`, `operations/rollback.md` and `setup/checks.md`.
