# CL-524: Sync the contract engine to each project, and move the fleet onto contracts

## Goal

Each project gets the contract vocabulary through `clutch sync`, and the fleet moves onto contracts, one package at a time.

## Context

A project owns its sync engine after install, and an engine can differ a lot from the one in this template. So sync does not replace `packages/sync`. It ships `packages/sync/contract/` as managed files: the folder imports nothing outside itself, and it runs on any engine. `packages/sync/contract/engine-groups.ts` belongs to the engine, because its prefixes are in each stored event.

Clutch keeps no code for the older form. A project whose packages still have `models/` moves every package in one branch: `check-structure` rejects each `models/` folder, so the branch passes `validate` only at its end. A plain value moves from `models/` to `contract/` as it is, and `check-contract` asks for a contract only where a file declares a part. The steps are in `.agents/skills/move-to-contracts/SKILL.md`.

A dry run on the first project applied the sync, and moved one small package onto a contract. No file of `packages/sync/contract/` changed for it. The engine layer of that project took about 200 lines. The sync stopped at each managed file that the project edited, and each one waits for the owner.

## Steps

1. Release this major version.
2. In the first project, answer each keep-or-take decision that sync lists. An agent never decides one.
3. On one branch: set the prefixes in `engine-groups.ts`, and port the listed parts into each kept config file.
4. Write the engine layer of the project once: the server half, the registered lists, the stamps in the object pool, and the two optional wire keys.
5. Move each package in its own commit, a small one first. Delete the older helpers after the last one.
6. Land the branch as one pull request. Repeat for the next project.

## Files

- `clutch.files.yaml`
- `.agents/skills/move-to-contracts/SKILL.md`
- `tools/check-structure.ts`, `tools/check-contract.ts`

## Acceptance criteria

- One branch brings the contract vocabulary to a project and moves each package, and `validate` passes at its end.
- The first project has no `models/` folder left, and passes `check-contract` with a committed `contract.json`.
