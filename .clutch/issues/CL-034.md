# CL-034: Replace fixed sleeps in tests with waits for the event

## Goal

No test guesses how long something takes. Each one waits for the event it needs.

## Context

From the CL-029 review:

- `packages/sync/service/feed.test.ts:62, 80, 82, 100, 116`: `Effect.sleep('50 millis')`. At line 100, the refusal can pass before the request is handled. The shared `access` object (line 26) is never reset.
- `apps/api/src/server.test.ts:26, 86` and `apps/api/src/jobs.test.ts:28`: `Effect.sleep('100 millis')` for socket readiness. `apps/api/src/spaces.test.ts:72/97` already waits on a `Deferred`.
- `packages/sync/runtime/boot-paint.test.ts:42, 52`: `Bun.sleep(600)` waits out the real `paintWait = 500`.
- `packages/runtime/service/session-queue.test.ts:206, 263`: a 1 ms lease and `Bun.sleep(10)`.
- `apps/api/src/server.test.ts:83`: `Stream.take(1)` cannot prove "no second change".

## Steps

1. feed, server and jobs: await a `Deferred` completed on the first message or the backfill, as `spaces.test.ts` does. Reset `access` in `afterEach`.
2. boot-paint: stub `setTimeout` in `page()` and fire the fallback by hand.
3. session-queue: give `SessionQueue` an injectable `now`.
4. server.test.ts:83: assert exactly one delta, or drop the claim from the name.

## Acceptance criteria

- `grep -rn "sleep(" --include=*.test.ts` finds no wait for readiness.
- validate passes.
