# CL-533: Count the first-run failures of each journey in the flake hunt

## Goal

The owner and the agents know how often each journey fails on its first run, before the clock or the retry changes.

## Context

Exact gives the clock to the agent, so a test has no waits and no timing failures. Clutch journeys differ on purpose, in two ways. `packages/journeys/testing/journey.ts` installs the clock only for a journey with an `advance` step. Any other journey runs on real time, because its network is real and a clock that jumps fires the timers of a retry before the answer comes. `docs/contributing/end-to-end-testing.md` defines one retry: a journey that passes on the retry passes the check, and the runner files a `flake` friction entry. A measured budget gets no retry.

So a change to the clock or to the retry needs evidence first. The flake hunt in `.github/workflows/flake-hunt.yml` runs the tools tests only, and no report shows how often a journey needs its retry.

## Steps

1. Branch `clutch/cl-533-journey-flake-hunt`.
2. Add the journeys to the flake hunt. It runs each journey 20 times with no retry. The blocking journey run keeps its one retry.
3. Print the first-run failures of each journey in the run summary. Do not quarantine a journey, because a journey is proof.
4. When the hunt names a journey, file one issue for it with the cause. File an issue that gives more journeys the clock only when a cause is timing.

## Files

- `.github/workflows/flake-hunt.yml`
- `tools/journeys/playwright.config.ts`
- `docs/contributing/end-to-end-testing.md`

## Acceptance criteria

- The flake hunt runs each journey 20 times with no retry.
- The run summary names each journey that failed a run, and how many times it failed.
- The blocking journey run keeps its one retry.
