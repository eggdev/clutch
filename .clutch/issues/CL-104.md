# CL-104: Add Renovate and a minimum release age for dependencies

## Goal

Updates arrive as small PRs, and no package version younger than 3 days installs.

## Context

`bunfig.toml` already sets `minimumReleaseAge = 259200` (CL-030), and `dep_min_age` is already adopted. This issue adds only the update bot. The digest pins match the SHA pins from CL-103.

## Steps

1. Branch `clutch/cl-104-renovate`.
2. Check the existing `minimumReleaseAge` setting in `bunfig.toml` with `mise exec -- bun install --dry-run`. It must succeed. Do not change the setting. `bunfig.toml` is a guardrail file.
3. Add `renovate.json`:
   - extend `config:recommended`
   - `minimumReleaseAge: "3 days"`
   - `rangeStrategy: pin`
   - group Nx, oxlint and oxfmt packages
   - set `github-actions` digests to pinned
   - a weekly schedule
   - `prConcurrentLimit: 3`
   - labels `dependencies`
4. Add `renovate.json` to `tools/guardrail-files.json`, add a line for it to `.github/CODEOWNERS`, and add a `seed` entry with `capability: dep_automation` for it in `clutch.files.yaml`.
5. In `clutch.yaml`, replace the `dep_automation` waiver with `dep_automation: adopted`. Detection passes on a tracked `renovate.json`. Leave `dep_min_age` as it is.
6. Installing the Renovate GitHub app is a repo setting. It goes on the CL-106 checklist.

## Acceptance criteria

- `bun install --frozen-lockfile` passes.
- `npx --yes --package renovate -- renovate-config-validator` passes.
- `clutch doctor --check` passes with `dep_automation` adopted.

## Verify

```bash
mise exec -- bun install --frozen-lockfile
npx --yes --package renovate -- renovate-config-validator renovate.json
mise exec -- bun run clutch doctor --check
```
