# CL-556: A flaky test is fixed, or deleted with its reason

## Goal

A flaky test is fixed. When the cause is not found in its quarantine, the test is deleted and the reason is written down.

## Context

The owner compared Clutch with the article "How the Claude Code team thinks about verification". The article says that an agent never skips a flaky test, adds sleeps or retries it. Today `docs/contributing/testing.md` says to quarantine a flaky test and never delete it. An entry can get a new date with no end.

## Steps

1. Add a `since` field to each quarantine entry: the first day of the quarantine.
2. Make `check-flaky-tests` fail when `until` is more than 30 days after `since`, when `since` is in the future, and when a PR moves the `since` of an entry on the base branch.
3. Make the flake hunt write `since`.
4. Add a `removed` list for deleted flaky tests, with `file`, `name`, `removed`, `reason` and `issue`.
5. Make the message for an expired entry name the two ways out.
6. Add a lint rule that refuses a fixed sleep or a retry option in a test, if the repository has few cases.
7. Rewrite the "Flaky tests" section of `docs/contributing/testing.md`.

## Files

- `tools/check-flaky-tests.ts` and its test
- `tools/flaky.ts`, `tools/flaky-tests.json`
- `tools/flake-hunt.ts` and its test
- `tools/lint/test-policy.mjs` and its test
- `docs/contributing/testing.md`, `docs/contributing/setup/lint-rules.md`

## Acceptance criteria

- An entry with `until` 31 days after `since` fails the check.
- A removed entry with no reason fails. A removed entry whose test is still in the file fails.
- The flake hunt writes `since`.
- `testing.md` no longer says "never delete it".
- `validate` passes with the empty lists.
