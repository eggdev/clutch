# CL-451: Keep watching main when the Auto-revert net started the rerun

## Goal

`pr merge` keeps watching `main` when the Auto-revert workflow already started the rerun, so a session reports the real result of the second run.

## Context

- `watchMain` in `tools/github/main-watch.ts` sees a red first attempt and calls `runAutoRevert`. The rerun is what it then waits for.
- On `main` at 28a5701, the Auto-revert workflow started the rerun first. `validate` was then `in_progress`, so `runAutoRevert` logged "No required check failed", called no `reran`, and `watchMain` returned 1 at once.
- `pr merge 228` exited 1 while attempt 2 was still running. Attempt 2 failed too, and the session had already stopped watching.

## Steps

1. Treat a required check that is in progress on the failed commit as a rerun under way. `runAutoRevert` reports it, and `watchMain` waits for that attempt.
2. Keep the current result when no required check failed and none is running.
3. Add a test in `tools/github/main-watch.test.ts` for a rerun that another actor started first.

## Files

- `tools/github/auto-revert.ts`, `tools/github/main-watch.ts` and their tests

## Acceptance criteria

- A red first attempt whose required check is already in progress keeps the watch open until that attempt ends.
- A second red attempt starts the revert, once.
- `bun run validate` passes.

## Verify

`mise exec -- bun test tools/github/main-watch.test.ts tools/github/auto-revert.test.ts`.
