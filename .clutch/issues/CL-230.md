# CL-230: Read the review result the way the merge gate does

## Goal

`pr status` and `pr wait` print the review result the way the merge gate reads it.

## Context

- PR #172 merged by the bot. Its agent-review check passed, and its summary said "none blocking" in a form `blockingCount` did not match, so `pr wait` printed "blocking count is unreadable" and "Ready to merge: no".
- PR #170 showed 3 owner findings as 9. Its agent-review check carried 9 "Owner review needed" annotations, all on path `.github`, with log-line numbers as line. The same finding is restated in the structured answer, the head's inline comments, and an earlier head's inline comments, in other wording. Annotations carry no identity to dedupe on.

## Steps

1. Blocking count: a passed agent-review check on the head means 0. The comment gives the count only when the check did not pass, and no comment means the review did not run.
2. Owner count: count the distinct inline owner comments of the head's review, by path, line and first line. Annotations still decide whether an owner finding exists.
3. Tests with the real shapes of #172 and #170.

## Files

- tools/github/status.ts
- tools/github/owner-reviews.ts (new, split from status.ts to stay under the size budget)
- tools/github/status.test.ts (new)

## Acceptance criteria

- `pr status` on a PR with a passed agent-review check and a "none blocking" summary reads 0 blocking.
- `pr status` on #170's head reads 3 owner, not 9.
- The gate (auto-merge.ts, agent-review.yml) is unchanged.
