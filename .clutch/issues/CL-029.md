# CL-029: Review the whole test suite for what it proves and how it behaves

## Goal

One pass over every test in the repository: what each one proves, whether it is reliable, and whether it is worth its time (request by Brendan, 2026-10-30).

## Steps

1. List every test file, its target and its run time from `validate`.
2. For each one, record what behavior it proves, then flag these:
   - **flaky:** fixed sleeps, timing, network;
   - **slow:** over 1 s;
   - **weak:** it asserts nothing user-visible, or only mirrors the implementation;
   - **redundant:** another test covers the same thing;
   - **stub:** it tests a placeholder, such as the database checks Brendan called stubbed.
3. Write the findings in this issue as a table. Propose a fix, delete or keep for each flagged test, and ask Brendan before any delete. `check-test-integrity` blocks silent removal.
4. Open one issue per agreed change.

## Acceptance criteria

- Every test file appears in the table.
- Brendan has signed off on the proposed deletions and fixes.

### Flagged tests

**Flaky**

- `tools/verification/test_verify.py:184` `test_force_loss_is_reconciled_before_another_flow_and_never_replayed`. The note above is right. `spawn_owned` (`tools/verification/processes.py:92-98`) starts the flow with `Popen`, runs a `ps` subprocess for its birth time, and only then writes `command-owner.json` (through `.new` and a rename). The flow writes `flow.pid` as soon as its interpreter starts. `start_waiting_flow` (test lines 162-166) returns on `flow.pid`, so the SIGKILL at line 186 can land before the record exists. `recover()` then finds nothing, and the new flow runs and exits 0, which is the CI failure. Fix: in `start_waiting_flow`, poll until `flow.pid` parses as an int and `tmp/verification/command-owner.json` records that same pid. The same window exists in production: a SIGKILL between `Popen` and `write_json` leaves an untracked flow, and the next run goes ahead. Product fix (a separate issue): write an intent record before `Popen`, or hold the child on a pipe until the record is saved.
- `tools/verification/test_verify.py:163-166`, `start_waiting_flow`, used by the tests at lines 172 and 184. `write_text` creates the file and then writes it, so `int(pid_file.read_text())` can read `''` and raise `ValueError`. The poll in the fix above covers this.
- `tools/verification/test_verify.py:199` `test_timeout_stops_descendant_even_after_group_leader_exits`. `timeoutSeconds: 1` (line 208) must cover two Python startups and the worker writing `child.pid`. On a loaded runner, line 215 raises `FileNotFoundError`. Fix: raise it to 3 s, and fail with "worker never started" when the file is missing.
- `tools/verification/test_verify.py:267` `test_detached_output_writer_has_a_deadline_and_retains_uncertain_ownership`. `timeoutSeconds: .5` (line 273) has the same startup race, and it ends on the plain timeout path (exit 124). Fix: raise it to 2 s.
- `packages/sync/service/feed.test.ts:62, 80, 82, 100, 116`. `Effect.sleep('50 millis')` guesses when the feed has subscribed or handled a Load.
