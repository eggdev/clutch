# CL-552: Fail a package whose contract has no proof of its claims

## Goal

`check-contract` fails a package that has a contract and no test that calls `proveClaims`.

## Context

CL-532 added `proveClaims` in `packages/sync/testing/claims.ts`, and `packages/notes` and `packages/access` call it. Nothing asks a new package for the same proof. The whole change of CL-532 was over the size limit of one pull request, so this issue holds its last two steps. The code exists on the branch `clutch/cl-552-claims-check`, and an independent review read it with CL-532.

## Steps

1. Branch `clutch/cl-552-claims-check`.
2. Add the finding `check-contract/claims-not-proven` to `tools/check-contract.ts`. It reads files on disk and runs no test. Its message prints the call to write.
3. Make the package generator write the proof file of each new package with a contract.
4. List the proof files in `tools/guardrail-files.json`, because the check now depends on them.
5. Describe the claims and their proof in `docs/contributing/architecture/contract.md`.

## Files

- `tools/check-contract.ts`, `tools/check-contract.test.ts`, `tools/contract-claims.ts`, `tools/contract-claims.test.ts`
- `tools/generators/package/`, `tools/generators/generators.test.ts`
- `tools/guardrail-files.json`, `clutch.files.yaml`
- `docs/contributing/architecture/contract.md`

## Acceptance criteria

- A package with a contract and no call of `proveClaims` fails `validate`, and the message prints valid code.
- A package that the generator makes passes `check-contract`.
- No existing finding id changes.

## Verify

```sh
mise exec -- bun run validate
```
