# CL-130: Grade dry-run verdicts in one place

## Goal

The owner grades every auto-merge dry-run verdict in one place, with one comment, and `clutch metrics` counts the grades.

## Context

Brendan merges nothing himself: the lanes merge under his delegation. So he always grades verdicts after the fact, and finding them in PR comments is clumsy. On 2026-10-30 he graded 19 in one go ("agree with all"), and the coordinator added the 👍 reactions for him.

## Steps

1. Branch `clutch/cl-130-grade-verdicts`.
2. Add `clutch metrics --verdicts [--json] [--owner LOGIN]`. It lists each verdict with no owner grade, with the PR, the verdict, its reasons and the link. The owner is `automerge.owner` in `clutch.yaml`, else the CODEOWNERS default.
3. Have the weekly gardening workflow open or update the issue "Auto-merge calibration: week of <date>" with the ungraded verdicts.
4. Add a workflow on `issue_comment`. The owner's `agree with all` or `/agree all` adds a 👍 to each listed verdict, and `/disagree #<pr>` adds a 👎 and keeps the PR listed with a note. The release bot reacts. `clutch metrics` counts the owner's reactions and a bot's.
5. Report the agreement streak. It stands at 19 from the graded verdicts of 2026-10-30.
6. Add both commands to the command index.

## Files

- `apps/cli/src/metrics/`, `apps/cli/src/metrics-command.ts`, `tools/github/grade-verdicts.ts`, `.github/workflows/grade-verdicts.yml`, `.github/workflows/gardening.yml`, `.agents/skills/deliver/references/`.

## Acceptance criteria

- `clutch metrics --verdicts` lists only verdicts without an owner or bot grade, and shows the streak.
- An owner's `agree with all` on the calibration issue grades every listed verdict. A comment from anyone else grades nothing.

## Verify

```bash
mise exec -- bun run clutch metrics --verdicts
```
