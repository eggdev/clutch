# CL-403: Add risk tiers by path

## Goal

Every PR gets a risk tier from the paths it touches.

## Steps

1. Branch `clutch/cl-403-risk-tiers`.
2. Add `.clutch/risk.yaml` (a guardrail file): ordered rules `{tier: low|medium|high|one-way-door, paths: [globs]}`, where the highest tier wins. Add `.clutch/risk.yaml` to `tools/guardrail-files.json` and to `.github/CODEOWNERS`.
   - `one-way-door`: every pattern in `tools/guardrail-files.json`. `clutch risk` reads that list, so the two cannot drift. Also migrations (`apps/*/migrations/**`, `features/*/migrations/**`, `packages/*/migrations/**`, the paths `tools/check-migrations.ts` matches) and auth (`**/auth/**`). No auth code exists in the repo yet, so that glob is a guess until some does.
   - `apps/*/src` code is `medium`.
   - Docs and tests only are `low`.
3. Add `clutch risk [--base <ref>] [--json]` and a CI job that labels `risk/<tier>`. Create the four labels first with `gh label create --force --repo eggdev/clutch`. A label set with `GITHUB_TOKEN` starts no other workflow, so CL-404 computes the tier itself.
4. If Brendan points to a one-way-door file in Neighborhood, read it before you build this. None exists in `~/dev/neighborhood/.github/workflows` today.

## Acceptance criteria

- Tests cover the precedence.
- A docs-only PR gets `risk/low`. A PR that touches `.github/workflows` gets `risk/one-way-door`.

mise exec -- bun run clutch risk --json
