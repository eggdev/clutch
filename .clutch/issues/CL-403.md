# CL-403: Add risk tiers by path

## Goal

Every PR gets a risk tier from the paths it touches.

## Steps

1. Branch `clutch/cl-403-risk-tiers`.
2. Add `.clutch/risk.yaml` (a guardrail file): ordered rules `{tier: low|medium|high|one-way-door, paths: [globs]}`, where the highest tier wins.
   - Guardrail files, workflows, migrations and auth are `one-way-door`.
   - `apps/*/src` code is `medium`.
   - Docs and tests only are `low`.
3. Add `clutch risk [--base <ref>] [--json]` and a CI job that labels `risk/<tier>`.
4. Neighborhood's `one-way-door.yml` is the prior art. Read it before you build this.

## Acceptance criteria

- Tests cover the precedence.
- A docs-only PR gets `risk/low`. A PR that touches `.github/workflows` gets `risk/one-way-door`.

## Verify

```bash
mise exec -- bun run clutch risk --json
```
