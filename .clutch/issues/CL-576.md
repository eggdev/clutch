# CL-576: Keep a deleted record deleted when an older backfill names it

## Goal

A record that the server deleted does not come back on a client when a later backfill holds an older change of it.

## Context

`applyChange` in `packages/sync/runtime/pool.ts` skips a change that is older than the last change of the record. A delete removes the `meta` of the record, which held that sync ID. A council review on 2026-11-20 found this case: a client has loaded group A. Record R moves from group B to A, and is then deleted. Later the client loads group B. The backfill of B holds only the old change of R in B, because the move and the delete name group A. R comes back. CL-530 sends a delete to the group that a record leaves, which closes this case for a move. This issue closes it in the pool for each cause.

## Steps

1. Branch `clutch/cl-576-deleted-stays-deleted`.
2. Write the failing test first, in `packages/sync/runtime/pool-groups.test.ts`.
3. Keep the sync ID of a delete, so `applyChange` skips an older upsert of the same record.
4. Decide when the pool may forget the sync ID of a delete.

## Files

- `packages/sync/runtime/pool.ts`, `packages/sync/types/local-database.ts`
- `packages/sync/runtime/pool-groups.test.ts`

## Acceptance criteria

- A backfill that holds an older upsert of a deleted record does not bring the record back.
- A saved copy keeps this after a reload.
