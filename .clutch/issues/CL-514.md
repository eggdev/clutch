# CL-514: Define the factory tree schema and check it in validate

## Goal

A project's factory is a tree of files, and a check rejects a bad tree. Clutch owns the format from now on. C-Suite's `docs/stack.md` then links to the schema page in Clutch.

## Context

- Layer 00 of the factory stack. Decisions D-018 and D-019 in `eggdev/c-suite` (private). The build plan is `docs/stack.md` on the C-Suite branch `test-week-builds-stack`: `gh api 'repos/eggdev/c-suite/contents/docs/stack.md?ref=test-week-builds-stack' --jq .content | base64 -d`.
- The Warp research (`company/research/warp-factories/README.md` in C-Suite) says: the path is the name, the frontmatter holds the settings, the body holds the prompt, and the schema rejects an unknown key.
- Every other stack issue (CL-515, CL-426, CL-427, CL-312, CL-313, CL-314, CL-516, CL-517) builds on this one. Keep the scope to the format and the check.
- The test week ends on 2026-11-11.

## Design (coordinator defaults, 2026-11-04)

Keep the key names in `docs/stack.md`. Each change below goes in the PR body under "Schema changes versus stack.md", so C-Suite can match it.

- The tree root is `factory/` at the project root. `factory.root` in `clutch.yaml` changes it, and `--root` on the command changes it for one run, so C-Suite can check a tree at `.`. Change versus stack.md: stack.md puts the folders at the root.
- Paths, relative to the tree root:
  - `agents/<name>/agent.md`
  - `automations/<name>/automation.md`
  - `runners/<name>.yaml`
  - `scorers/<name>/scorer.md`
  - `benchmarks/<name>/benchmark.md`. The path only. CL-427 adds its keys. Addition versus stack.md.
  - `skills/<name>/SKILL.md`. In a Clutch project, `.agents/skills/` is the skills folder, so the tree needs no `skills/`. Change versus stack.md.
- `agent.md` keys, as in stack.md: `role` (`foreman`, `triage`, `spec`, `implement`, `review`, `verify` or `custom`), `description`, `harness` (`claude`, `codex` or `qwen`), `model`, `runner`. The body is the prompt and must not be empty.
- `automation.md` keys: `description`, `trigger`, `agent`. `trigger` holds exactly one of `schedule` (a 5-field cron in UTC) or `event` (a GitHub event name, with an optional `filter` map). The body is the starting prompt.
- `runners/<name>.yaml` keys: `description`, `machine`, `t3_environment`, `workspace` (`worktree` or `shared`), `setup` (a list of shell commands). CL-312 adds the check command.
- `scorer.md` keys: `description`, `agents` (a list of agent names), `labels` (1 to 20 items of `{ name, score, description }`, each score from 0 to 1), `pass_mark` (0 to 1), `sample_rate` (0 to 1, default 0.25), `harness`, `model`, `runner`. The body is the judge prompt. stack.md names these settings but not the keys, so these keys are Clutch's.
- References: `agent.runner` and `scorer.runner` name a file in `runners/`. `automation.agent` and each `scorer.agents` item name a folder in `agents/`. A name is lowercase kebab case.
- Keep one source of truth for each schema in code. Use the library that `apps/cli/src/clutch-config/schema.ts` uses. Write a JSON Schema file for each kind from that source, so C-Suite's validate can use the same schema. A test fails when a JSON Schema file is stale.

## Steps

1. Branch `clutch/cl-514-factory-schema`.
2. Add a `factory` module in `apps/cli/src/factory/` that loads the tree and returns each problem with its file, its key and a reason.
3. Add `clutch factory --check [--root DIR] [--json]` to `apps/cli/src/commands.ts`. It exits 1 on a problem. A project with no tree passes with a notice.
4. Run the check in `validate`, so `pre-push` and CI run it.
5. Write the schema page, `docs/contributing/architecture/factory-tree.md`. It names each path and each key, with an example of each file. Link it from the architecture index and from `apps/cli/README.md`.
6. Test with fixture trees: a good tree, an unknown key, a missing runner, a missing agent, a bad enum value, an empty prompt and a bad cron.

## Files

- `apps/cli/src/factory/` (new), with tests and fixtures
- `apps/cli/src/commands.ts`, `apps/cli/README.md`
- The JSON Schema files, in a folder the lane picks
- `tools/validate.ts` or the task that `validate` runs
- `docs/contributing/architecture/factory-tree.md`, `docs/contributing/architecture/index.md`

## Acceptance criteria

- `clutch factory --check` fails on a tree with an unknown key or a missing runner. The output names the file and the key.
- It passes on a good tree, and on a project with no tree.
- `mise exec -- bun run validate` runs it.
- The release binary carries the command.
- The schema page names every path and key. The PR body lists each change versus stack.md.
