# CL-559: A new check starts in observe mode

## Goal

A new check starts in observe mode. It warns first, so its false positives show before it blocks.

## Context

The owner asked on 2026-11-16 for Clutch to meet the practice "Start a new gate in observe mode". Before this change, a new check blocked from its first day. The merge gate already has the modes `off`, `dry-run` and `on`.

## Steps

1. Add `observedTargets` to `tools/validate.ts`. `validate` runs each one after the blocking targets and prints a failure as a warning.
2. An observed check never changes the exit code, also when it crashes.
3. `check-scope` fails a PR that adds a target to a blocking list when the base has it in no list. A rename or split passes one for one.
4. State the rule in `checks.md`, `tools/AGENTS.md` and `harness-engineering.md`.

## Files

- `tools/validate.ts`, `tools/validate.test.ts`
- `tools/check-scope.ts`, `tools/check-scope.test.ts`
- `tools/AGENTS.md`
- `docs/contributing/setup/checks.md`
- `docs/contributing/harness-engineering.md`

## Acceptance criteria

- An observed check with a finding prints a warning, and `validate` still passes.
- A new blocking target fails `check-scope` unless the base observes it.
- With the empty observed list, `validate` prints and takes the same as before.
- `tools/AGENTS.md` and `checks.md` state the same rule.

## Verify

```sh
mise exec -- bun test tools/validate.test.ts tools/check-scope.test.ts
mise exec -- bun run validate
```
