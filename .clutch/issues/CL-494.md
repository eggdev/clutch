# CL-494: Hold a guardrail change in the merge judge, and remove the ask hook

## Goal

The merge judge holds an agent pull request that changes a check, a lint rule, a budget or a hook when its issue does not name that file. No hook asks a person in the session.

## Context

- The council review of 2026-11-13 found this gap at head `8563977b`. The owner approved the fix on 2026-11-14, and he knows that it changes decision record 0005.
- Today `tools/agent-hooks/guard-guardrails.ts` asks a person before an agent edits a file of `tools/guardrail-files.json`. The hook does not see a shell write, it is off while `KICKOFF.md` exists, and a session with no person cannot answer it.
- After the edit, nothing holds the change. `tools/check-*.ts` and the lint config are in the tier `medium`, which merges with no person.
- So an agent that cannot pass a check can change the check, and the pull request merges.
- The hold must not bring the owner back for common work. Decision record 0005 says he was asked for 34 of 100 pull requests.
- This issue replaces CL-466.

## Steps

1. Branch `clutch/cl-494-guardrail-hold`.
2. Find out first: of the last 100 merged agent pull requests, how many changed a file of `tools/guardrail-files.json`, and how many of those had an issue that names the file. Write both counts in this issue.
3. Choose the set of files that the hold covers. It must cover the check scripts, the lint rules and their config, the budgets, the agent hooks and the guardrail list. Leave out a pattern that common work changes, such as `package.json`, when the counts show that the hold would stop more than 1 in 10 pull requests.
4. Add the rule to the merge judge: an agent pull request that changes a file of the set is held, unless the issue of its branch names that file in its `## Files` section. Read the issue from the default branch, not from the pull request, so a pull request cannot allow itself.
5. The reason tells the agent what to do: take the change out, or deliver an issue that names the file first. The owner's approval lifts the hold, as it lifts the other holds.
6. Remove the guardrail ask hook from `.claude/settings.json` and `.codex/hooks.json`, with `guard-guardrails.ts` and its tests.
7. Update the description in `tools/guardrail-files.json`, `docs/contributing/harness-engineering.md`, `docs/principles/proof-gates-code.md` and decision record 0005. The record gets a dated note that the owner changed it on 2026-11-14.
8. Set CL-466 to `done` with a note that this issue replaced it.

## Acceptance criteria

- A judge test: an agent pull request that changes `tools/check-scope.ts`, with an issue that does not name it, gets a reason that names the file and the two ways out.
- A judge test: the same change with an issue on the default branch that names the file gets no reason.
- A judge test: an issue file that only the pull request changes does not lift the hold.
- A judge test: the owner's approval lifts the hold.
- No hook asks a person before an edit to a guardrail file.

## Notes

Step 2, measured on 2026-11-14 over the last 100 merged PRs. A person opened one of them. No release, sync, Renovate or revert PR was among them. So 99 are agent PRs.

- The full list: 74 of the 99 agent PRs changed a guardrail file. Only 1 of those had an issue on the default branch that named each such file.
- Of the 73 that would hold, 64 had no issue on the default branch. The branch named no issue, or the PR filed its own issue.
- The chosen set, `held`: 22 of the 99 changed one of its files. 2 had an issue that named each file, so the hold would have stopped 20.
- Of those 20, 17 had no issue on the default branch. If each issue had been there first, 10 would still hold.
- The counts leave out a new file, a test file and a change that only makes the list stronger. The hold leaves them out too.
- `tools/check-*.ts` alone would have stopped 13 of the 99. The issue requires it, so it stays in `held`.
- Left out of `held`: `.github/workflows/**` (27), `tools/github/**` (23), `tools/journeys/**` (12), `docs/contributing/review.md` (10), `.clutch/risk.yaml` (9), `clutch.yaml` (7) and `package.json` (6). Each is common work, and the journey files and budgets have their own hold.
- The hold asks no person. The agent takes the change out, or names the file in its issue on the default branch first.
