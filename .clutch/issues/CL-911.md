# CL-911: Dry-run migrations against the base branch's seed

## Goal

A PR's migrations are applied to the base branch's seeded database, and the check fails on an error, lost or changed data, or a slow step.

## Context

From CL-605. Neighborhood's `tools/migration-dry-run.ts` builds the base branch's database with its seed, applies the branch's migrations, and compares the data. It runs as a CI job on D1. Clutch's `check-migrations` checks the files only, and `migrations.md` has a kickoff slot for a dry-run command. Clutch's packages use PGlite, so the port can run in CI with no service.

## Steps

1. Port the dry run to PGlite: seed at the base, migrate to the head, and diff each table.
2. Run it in `validate`, or as a CI job, when a migration changed.

## Acceptance criteria

- A migration that drops a seeded column fails with the table and column named.
