# CL-549: Review each blocking check with the owner, and remove a check that stops no real mistake

## Goal

The owner knows what each blocking check stops and what it costs, and no check stays only for coverage.

## Context

Decision record 0006 keeps the blocking checks with no cap. The owner gave the condition on 2026-11-13: a check stays only when it stops a mistake that an agent makes for real. He wants to go through each rule and see its effect before he decides.

On 2026-11-13, `validate` blocked on 45 targets: 7 in `tools/validate.ts` and 38 under `checks` in `package.json`. The table in `docs/contributing/setup/checks.md` says what each target rejects. It does not say which mistake the check stops, and it does not say whether the check ever failed on a pull request.

The owner decides each check, so this issue waits for him. An agent prepares the evidence first.

## Steps

1. Branch `clutch/cl-549-check-review`.
2. An agent collects the evidence for each blocking target: the rule in one sentence, the mistake that it stops, the issue that added it, how often it failed on a pull request in the last 60 days, and its seconds in `validate`.
3. The agent marks each check that states no reason, and each check that did not fail in that time.
4. The owner goes through the checks in a session, one at a time. He says keep, change or remove for each.
5. Remove each check that the owner removes, and file one issue for each check that he changes.
6. State the mistake that each kept check stops in the table of `checks.md`.

## Files

- `docs/contributing/setup/checks.md`
- `package.json`, `tools/validate.ts`, and the script and the test of each removed check
- `tools/guardrail-files.json`

## Acceptance criteria

- The owner said keep, change or remove for each blocking target.
- Each kept check states the mistake that it stops in `checks.md`.
- Each removed check is gone from `validate`, with its script and its test.

mise exec -- bun run validate
