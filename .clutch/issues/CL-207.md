# CL-207: Revert a red auto-merge and watch the revert rate

## Goal

Auto-merge can take most PRs (Brendan, 2026-11-02: start at 80% and tighten
on evidence). So a bad merge comes out fast, each revert proposes a tighter
path, and the numbers that say "tighten" show each week.

## Context

The Revert workflow (CL-110) opens a revert PR when a person adds the `revert`
label. `clutch metrics` already counts reverts and main-red minutes, and the
weekly digest prints the metrics of each repository.

## Steps

1. Add the Auto-revert workflow and `tools/github/auto-revert.ts`. When CI on
   the default branch fails after a green run, it reruns the failed jobs once.
   When the rerun fails too, and auto-merge merged the PR, it labels the PR
   `revert` and starts the Revert workflow.
2. When the Revert workflow reverts an auto-merged PR, file a `risk-tighten`
   issue with the PR's files and their tiers.
3. Add a Watch row to `clutch metrics`: no-human share under 80%, revert rate
   over 2%, main-red minutes and the open `risk-tighten` issues.

## Files

- `.github/workflows/auto-revert.yml`, `tools/github/auto-revert.ts` and its test
- `.github/workflows/revert.yml`, `tools/github/revert.ts` and its test
- `apps/cli/src/metrics/collect.ts`, `report.ts` and `report.test.ts`
- `docs/contributing/operations/rollback.md`,
  `docs/contributing/capabilities/factory-observability.md`

## Acceptance criteria

- A second red CI run on main after a green one, at an auto-merged PR's merge
  or its release commit, labels that PR `revert` and starts the Revert
  workflow. A first red run only reruns. A PR that a person merged is left.
- A revert of an auto-merged PR files a `risk-tighten` issue.
- `clutch metrics` prints a Watch row, and the weekly digest shows it.

## Verify

`mise exec -- bun run validate`. The workflows run only on main, so the live
path is checked after merge, on the first red run.
