# CL-141: Report autonomy, cycle time and reverts with Warp's definitions

## Goal

One command prints a project's autonomy, cycle time and revert rate, with the definitions in C-Suite's `docs/stack.md` layer 04. C-Suite's weekly metrics brief reads the JSON. Layer 04 "Done when": C-Suite reads the Neighborhood numbers with one command.

## Context

- The definitions, from stack.md:
  - **Autonomy:** the share of merged PRs with no human code push before the merge. Opening the PR counts as a push. Reviews, comments and the merge do not.
  - **Cycle time:** the median from the start of a lane to the PR, the first review and the merge.
  - **Reverts:** the share of merged PRs that a later PR reverts. The brake is 2% (D-004).
- `clutch metrics` already reports `noHumanAction`, the open-to-merge hours and the revert rate (`docs/contributing/capabilities/factory-observability.md`). `noHumanAction` counts reviews and comments as human action, so it is a different number. Keep it, and add autonomy next to it.
- An agent PR is opened with the operator's token, so the author of the PR does not tell a person from an agent. The `Co-authored-by` trailers and the `pr.branchPrefix` branch already tell them apart in `agents`.
- CL-207 is `in_progress` and names `apps/cli/src/metrics/collect.ts` and `report.ts`. It has no live lane on 2026-11-04. Rebase on `main` before each push.

## Design (coordinator defaults, 2026-11-04)

- A human code push is a commit on the PR's head that has no agent trailer and is not from a bot. A PR that a person opens, with no agent trailer on its first commit and no agent branch prefix, counts as a push too.
- The lane starts at the earliest of: the first commit on the branch (author date), or the commit that set the issue to `in_progress`. Report p50 and p90 for lane start to PR open, to the first review, and to the merge. A first review is the first submitted review or agent review check, from any reviewer. Write down in the docs which one the code takes.
- Reverts: keep the current rate, and add the merged PRs that a later merged PR in the window or after it reverts, matched by the `This reverts commit` body or the `Revert "<title>"` title.
- Put the 3 numbers in a `factory` object at the top level of `--json`, with a `definitions` version string, so C-Suite can pin the meaning. Print them first in the text report.

## Steps

1. Branch `clutch/cl-141-warp-metrics`.
2. Collect the PR commits and reviews that the 3 numbers need, with `gh api` GET requests only.
3. Compute autonomy, cycle time and reverts, with tests on fixture PRs: an agent-only PR, a PR with a human fixup push, a PR a person opened, a revert, and a PR with no review.
4. Add the `factory` object to `--json` and to the text report.
5. Update `factory-observability.md` with each definition.
6. Run it on `eggdev/neighborhood` and on `eggdev/clutch` for 14 days, and put the numbers in the PR body.
