# CL-427: Compare 2 models for implement on a suite of 3 pinned tasks

## Goal

A benchmark suite of 3 tasks, each pinned to a commit, runs the `implement` agent with 2 models and records which model passes more tasks, in what time. Layer 04 "Done when": the suite has 1 result.

## Context

- Layer 04 of the factory stack. Read the Design section of CL-514. CL-514 reserves the path `benchmarks/<name>/benchmark.md` in the tree.
- Warp's benchmarks compare up to 6 configurations of model, harness or router on fixed tasks pinned to a commit.
- Claude and Codex run on the Spark with their own CLIs (`claude -p`, `codex exec`) on Brendan's plans. A run must not use an API key that bills per token. That would spend money, and needs Brendan first.

## Design (coordinator defaults, 2026-11-04)

- `benchmarks/<name>/benchmark.md` keys: `description`, `agent` (a folder in `agents/`), `configs` (2 to 6 items of `{ name, model }`; `model` is an id in `models.yaml`, which gives the harness), `tasks` (1 to 20 items of `{ name, commit, issue, check }`). `commit` is a full SHA. `issue` is the path of the issue file at that commit, and its text is the task's prompt. `check` is the command that grades the result: exit 0 passes. The body says what the suite measures. Addition versus stack.md.
- Pick 3 tasks from Clutch's own history: small, merged issues whose PR added a test, and whose test calls code that exists at the pin. Pin each one to the commit before the PR's first code commit. The check copies the test files from the PR head and runs them on the agent's result, so the agent never sees them.
- `clutch bench <name> [--config NAME] [--task NAME] [--json]` clones the commit alone into a scratch folder for each task and config, runs the runner's setup, runs the agent's prompt with the issue, runs the check, and removes the clone, also after a failure. The clone has no remote and no later history. It records pass or fail, wall time, changed lines, turns and the exit reason.
- Each agent run stops after 20 minutes or 80 turns.
- A run of the whole suite writes `factory/benchmarks/<name>/results/<date>-<short sha>.json`. Commit it. A result is small and rare, so it does not churn.
- Compare `claude-opus-5-5` with `claude-sonnet-5-5` on `claude --print`. Codex and Qwen configs come later.

## Steps

1. Branch `clutch/cl-427-implement-benchmark`.
2. Add the `benchmark.md` keys to the CL-514 schema, with tests.
3. Pick the 3 tasks and write `factory/benchmarks/implement-models/benchmark.md`. Prove that each check fails at the pinned commit and passes at the merge commit.
4. Add `clutch bench`, with tests that use a fake agent command.
5. Run the full suite once and commit the result.
6. Document the command in `apps/cli/README.md` and in the schema page.

- One result file is on `main`.
- Each clone that a run makes is gone after the run, also after a failure.
- `mise exec -- bun run validate` passes.
