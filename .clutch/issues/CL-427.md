# CL-427: Compare 2 models for implement on a suite of 3 pinned tasks

## Goal

A benchmark suite of 3 tasks, each pinned to a commit, runs the `implement` agent with 2 models and records which model passes more tasks, in what time. Layer 04 "Done when": the suite has 1 result.

## Context

- Layer 04 of the factory stack. Read the Design section of CL-514. CL-514 reserves the path `benchmarks/<name>/benchmark.md` in the tree.
- Warp's benchmarks compare up to 6 configurations of model, harness or router on fixed tasks pinned to a commit.
- Claude and Codex run on the Spark with their own CLIs (`claude -p`, `codex exec`) on Brendan's plans. A run must not use an API key that bills per token. That would spend money, and needs Brendan first.

## Design (coordinator defaults, 2026-11-04)

- `benchmarks/<name>/benchmark.md` keys: `description`, `agent` (an agent in the tree), `configs` (2 to 6 items of `{ name, harness, model }`), `tasks` (a list of `{ name, repo, commit, issue, check }`). `commit` is a full SHA. `issue` is the path of the issue file that is the task's prompt. `check` is the command that grades the result: exit 0 passes. The body says what the suite measures. Addition versus stack.md.
- Pick 3 tasks from Clutch's own history: small, merged issues whose PR added a test. Pin each one to the parent of its first commit. The check runs the test files from the merged PR on the agent's result, so the agent never sees them.
- `clutch bench <name> [--config NAME] [--task NAME] [--json]` makes a disposable worktree at the commit for each task and config, runs the agent's prompt with the issue, runs the check, and removes the worktree. It records pass or fail, wall time, changed lines and the exit reason.
- Write each result to `factory/benchmarks/<name>/results/<date>-<short sha>.json` and commit it. A result is small and rare, so it does not churn.
- Compare `claude-opus-5-5` with `claude-sonnet-5-5` on `claude -p`. Add a Codex config when its CLI runs headless in the worktree without a prompt.

## Steps

1. Branch `clutch/cl-427-implement-benchmark`.
2. Add the `benchmark.md` keys to the CL-514 schema, with tests.
3. Pick the 3 tasks and write `factory/benchmarks/implement-models/benchmark.md`. Prove that each check fails at the pinned commit and passes at the merge commit.
4. Add `clutch bench`, with tests that use a fake agent command.
5. Run the full suite once and commit the result.
6. Document the command in `apps/cli/README.md` and in the schema page.

## Acceptance criteria

- `clutch bench implement-models` runs 3 tasks with 2 models and prints a table of pass, time and lines for each pair.
- One result file is on `main`.
- Each worktree that a run makes is gone after the run, also after a failure.
- `mise exec -- bun run validate` passes.
