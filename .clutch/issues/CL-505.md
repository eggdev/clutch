# CL-505: Add accessibility checks to journeys

## Goal

Journeys fail on serious accessibility violations.

## Steps

1. Branch `clutch/cl-505-a11y`.
2. Run axe on the notes journey (`features/notes/journeys/notes-sync.pw.ts`) first, and triage each violation. Fix each real defect. Record any rule you exclude, with a reason, in the journey file.
3. Add `@axe-core/playwright` (pinned). The journeys import `test` from `@playwright/test`, so add a shared fixture in `tools/journeys/` (a guardrail file). It runs axe after each step that renders a page, and it fails on `serious` and `critical` violations. Journeys import `test` from the fixture instead. Check that the import path resolves from `features/`.
4. Add the `a11y_checks` capability to `docs/contributing/capabilities/registry.yaml` as an extra level. Its detect rule greps `features/*/journeys/*.pw.ts` for the fixture import.
5. Add `docs/contributing/capabilities/a11y-checks.md`, and a row for it in `docs/contributing/capabilities/index.md`.
6. Change the capability count from 36 to 37 in `apps/cli/src/doctor-command.test.ts` (lines 48 and 77), `apps/cli/src/doctor/seed.test.ts` (line 52) and `tools/release/binaries.test.ts` (line 113). Skip this if CL-310 lands first and makes them registry-driven.
7. Set `a11y_checks` to `adopted` in `clutch.yaml`, and run `mise exec -- bun run clutch doctor --write-baseline`.

## Acceptance criteria

- `mise exec -- bun run journey --all` passes.
- An injected unlabeled button fails a journey.

## Verify

```bash
mise exec -- bun run journey --all
```
