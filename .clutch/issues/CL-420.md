# CL-420: Babysit every agent PR from a workflow until it merges

## Goal

An agent stays with each agent PR from open to merge, with no session that has to remember it. It keeps the PR in sync with its base, answers every comment and review thread, fixes what needs a fix, resolves each answered thread, and leaves a full trace. The ruleset makes it required: a PR with an unresolved thread cannot merge.

## Context

Brendan, 2026-11-04: he wants "a required, repeatable PR babysitter" that stays with every PR, keeps it in sync with `main` and with its comments, reviews every comment, decides what needs a change, fixes it, resolves the threads, and leaves a full trace.

Before this, `babysit-pr` was a skill that ran only when a session called it. It stopped after 3 rounds and answered only agent review findings. CL-419 found 75 approvals asked of Brendan in the last 60 Clutch PRs and 54 Neighborhood PRs. 16 of them repeated an approval that a push dismissed by changing the diff. A babysitter that finishes every fix before it asks the owner, and pushes only a merge sync or a blocking fix after the approval, removes those.

Research, from the software-factory dataset (`catalog/practices.csv`) and the source files:

- kibana `.agents/skills/pr-babysit`: sync by merge, never rebase or force-push. Reply before the push. Fix the rule, not the line, in every file the PR touches. Stop when the same finding comes back after a fix. Leave a disagreement for a person after two replies. It leaves human comments out of scope. Clutch takes them in, as Brendan asked.
- openclaw ClawSweeper: one bot and one app. Each write capability sits behind a repository variable. A dispatch job skips the bot's own comments and debounces events, and serializes rounds per PR. Workers propose. Deterministic steps own the comments, labels and merges.
- pydantic-ai `review-context.md`: the reviewer reads the thread states, and does not raise a finding again on a thread that a reply resolved.

## Steps

1. `tools/github/babysit.ts`: read a PR in one GraphQL call plus one compare call. Plan the work: `conflict`, `behind` (20 or more commits), `red-check`, `open-thread`, `new-comment` and `owner-approved`. Apply the caps: 2 rounds per head for the same triggers, and 8 rounds per PR per UTC day. `sweep` dispatches up to 10 PRs.
2. `tools/github/babysit-log.ts`: the living `## Babysit log` comment, with its state in hidden JSON. Also the `## Review disposition` that `pr findings` reads.
3. `tools/github/babysit-apply.ts`: reply in each thread and resolve it with `resolveReviewThread`. Answer the other comments in one comment, rerun a flaky check once, write the log and the stuck label, and write the JSON artifact.
4. `tools/github/babysit-owner.ts`: ask for the owner's review only when nothing else is left, and withdraw the request while work is left.
5. `.github/workflows/babysit.yml`: `sweep` on reviews, comments, finished CI and agent review runs, pushes to `main` and every half hour. `babysit` runs per PR from the default branch in the `release` environment. Triage runs on `claude-haiku-5-5`. The fix runs on `claude-sonnet-5-5`, only when an item needs one. The models edit files and return decisions. The bot token is minted after every step that runs the PR's code.
6. `.github/rulesets/main.json`: `required_review_thread_resolution: true`. `dismiss_stale_reviews_on_push` stays `true`.
7. Agent review reads the answered threads, and does not raise a resolved finding again.
8. `pr failures` prints a check run's annotations when its job log is missing. Without them, a job that never started, for example on a billing block, gives no reason.
9. The Labels workflow creates `babysit:stuck` and `babysit:off`. Brendan's daily brief (`/home/clydeedgar/dev/briefing`, local) lists each stuck PR, so the babysitter never pings him on a PR.

## Acceptance criteria

- A review comment on an agent PR gets a reply, a fix or a reason, and a resolved thread, with no session running.
- A PR with an unresolved thread cannot merge.
- Each round is in the PR's `## Babysit log` and in a `babysit-<pr>-<run>` artifact.
- The owner's review request comes only when the checks pass and nothing else is left.
