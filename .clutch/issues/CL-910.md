# CL-910: Retry a journey once only when its server fails to start

## Goal

A journey that fails because its web server did not start gets one retry, and an assertion failure gets none.

## Context

From CL-605. Neighborhood runs browser tests through `tools/retry-infrastructure.ts`, which retries only on a server-start failure. Clutch's journeys run with `retries: 0` (`tools/journeys/playwright.config.ts`), so an infrastructure hiccup fails the required `journeys` check. That is part of the flake cost that CL-903 and CL-304 track.

## Steps

1. Port the wrapper, and run `bun run journey --all` through it in `ci.yml`.
2. Keep `retries: 0` in Playwright, so an assertion never retries.

## Acceptance criteria

- A test that kills the dev server once passes on the retry. A failed assertion fails at once.
