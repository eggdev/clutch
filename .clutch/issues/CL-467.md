# CL-467: Derive the gate list from the gate file of each feature

## Goal

The gate of a feature is declared once, in the feature. The lint config holds no list of gates.

## Context

- The feature generator writes each gate into the `gates` option of `oxlint.config.ts` (`tools/generators/shared/gates.ts`).
- `clutch.files.yaml` lists `oxlint.config.ts` as a managed file. A sync that takes the template's copy drops the gates of the project, and a route with no entry reports nothing.
- No check ties a feature with a screen to a gate.

## Steps

1. Branch `clutch/cl-467-derive-gates`.
2. Write the failing tests first, in `tools/lint/gate-policy.test.ts` and `tools/generators/generators.test.ts`.
3. Declare the route and the route file of a gate in `features/<name>/gate.ts`, and have `repo-gates/one-gate` read each feature's declaration.
4. Delete the `gates` option and `addGate`.
5. Fail a feature that ships a screen and declares no gate.

## Files

- `tools/lint/gate-policy.mjs`, `oxlint.config.ts`, `tools/generators/shared/gates.ts`, `tools/generators/feature/`
- `features/notes/gate.ts`, `docs/principles/one-gate-per-feature.md`

## Acceptance criteria

- `oxlint.config.ts` names no product route.
- A new feature from the generator has its gate enforced with no edit to a managed file.
- A feature with a screen and no gate fails a check.

## Verify

- `mise exec -- bun test tools/lint tools/generators`
- `mise exec -- bun run validate`
