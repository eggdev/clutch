# CL-542: Add a check that each server-rendered route states its reason

## Goal

A route that renders on the server names its reason, or the check fails.

## Context

Single-page app says the browser renders each route. A server render is an exception for one route, and the PR says which of two reasons applies. No check holds the principle, so only review stops a new server render (CL-531).

## Steps

1. Branch `clutch/cl-542-server-render-reasons`.
2. Keep a list of server-rendered routes with the reason of each, in one file.
3. Extend `check-structure` to fail a route file with a server render mode that the list does not name.
4. In `docs/principles/index.md`, replace `Review only` with the new rule's name, and delete the rule from `docs/contributing/review.md` in the same PR.

## Files

- `tools/check-structure.ts`, `tools/check-structure.test.ts`
- `docs/principles/index.md`, `docs/contributing/review.md`

## Acceptance criteria

- A new server-rendered route with no listed reason fails `validate`, and the message names the route.
- The principle's `Held by` cell names the new rule.

## Verify

```sh
mise exec -- bun run validate
```
