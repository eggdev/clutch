# CL-519: Run a sync's new manifest rules with the target release's binary

## Goal

One sync to a release applies every rule of that release's `clutch.files.yaml`, even a rule that the project's current binary does not know.

## Context

- A project runs the Clutch binary that `mise.toml` pins. Sync moves the pin, but the run that moves it is still the old binary.
- Neighborhood's sync from v0.53.6 to v0.55.0 on 2026-11-05 added no `factory/` files. The v0.53.6 binary ignores `add_on_sync` (CL-515). A second run with the v0.55.0 binary added them. After the first run the lineage says v0.55.0, so `clutch-sync.yml` reports "Up to date" and never runs the second pass.
- Each new manifest rule hits the same gap.

## Steps

1. Branch `clutch/cl-519-sync-target-binary`.
2. When the target release is newer than the running binary, sync fetches the target's binary (as `mise install` would) and runs the rest of the sync with it. Or the sync workflow runs `mise install` and a second pass after the first.
3. Add a test with a fake older binary and a manifest rule it does not know.
4. Document the behavior in `apps/cli/README.md#sync`.

## Files

- `apps/cli/src/sync/` and its tests, or `.github/workflows/clutch-sync.yml`
- `apps/cli/README.md`

## Acceptance criteria

- A sync from a binary that predates `add_on_sync` to a release that uses it adds the `add_on_sync` files in one run.
- `mise exec -- bun run validate` passes.

## Verify

```bash
mise exec -- bun run validate
```
