# CL-026: Make package.json clashes a decision when sync merges into a mature project

## Goal

`clutch sync` never replaces a project's own `package.json` values without a person's answer.

## Context

- A `sync --check` on Bar Savvy `epic/refactor` (`9637103d9`, 2026-10-29) found 13 `package.json` clashes where Clutch's value would win the merge. They include `scripts.validate`, `scripts.dev`, `workspaces`, two `nx.targets` commands, and the versions of `nx`, `oxlint` and `ultracite`.
- The merge rule comes from install, where Clutch winning is right for a new project. For an established project, those values are its own.

## Steps

1. During sync, list each clash as a decision: keep the project value or take Clutch's. Keep the install behavior unless Brendan says otherwise.
2. Reuse the keep-or-take flow from CL-013b, and remember the answer per key in `.clutch/lineage.json`.
3. Test with a fixture whose `validate` script differs.

## Acceptance criteria

- `sync --check` on a project with its own `validate` script lists it as a decision. A sync without an answer keeps the project value.
- validate passes.
