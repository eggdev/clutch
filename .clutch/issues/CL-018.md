# CL-018: Write capability docs part 1: index and the first 18 pages

## Goal

Each capability gets one page in `docs/contributing/capabilities/` that says what it is, why Clutch adopts it, how doctor detects it, how to adopt it and how to waive it.

## Context

These docs are inside `docs/`, so every doc check applies:

- `check-sentences`: 25 words per sentence at most.
- `check-terms`: none of `via`, `e.g.`, `i.e.`, `etc.`, `utilize`, `in order to`, `mutation`, `hydrate`, or the em dash.
- `check-docs-temporal`: no changelog phrases such as "now", "new", "no longer" or "was added".
- `check-docs-claims`: any claim that a check enforces something must name an existing check.
- `check-docs-file-refs`: every linked file must exist.
- `documentation.md`: docs hold no status or plans. Work that is not done lives in the tracker. So a page never says "missing" or "planned". doctor reports status.

## Page template

```markdown
# <Name>

<One sentence: what the capability is.>

## Why

<Two to four sentences. Cite the research rank and leaders in plain words.>

## Detection

`clutch doctor` reports this capability as present when <rules in words>. See the `<id>` entry in [the registry](./registry.yaml).

## Adopt

1. <Concrete steps in this repository, with paths.>

## Waive

Set `<id>` to `waived` in `clutch.yaml` with a reason. <When a waiver is reasonable.>
```

## Steps

1. Branch `clutch/cl-018-capability-docs-1`.
2. Add `docs/contributing/capabilities/index.md`: what a capability is, the three decisions (adopted, waived, n/a), and how to read `clutch doctor`. Add a table of all 36 capabilities with links. Pages from part 2 can be plain names until CL-019, because `check-docs-file-refs` rejects links to missing files.
3. Write the pages for the first 18 capabilities in Appendix B order.
4. Link the index from `docs/contributing/index.md`.
5. Add the terms "Capability", "Waiver", "Lineage" and "Clutch" to `docs/contributing/glossary.md`. It is a guardrail file, so the PR needs Brendan's review.
6. `mise exec -- bun nx run-many -t check-sentences check-terms check-docs-temporal check-docs-claims check-docs-file-refs` until it is clean.
