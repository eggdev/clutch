# CL-571: Give a managed page a notes block that sync never touches

## Goal

A project can add facts about itself at the end of a managed Markdown page. Sync keeps them, and the project keeps no copy of the whole page.

## Context

- `clutch.files.yaml` makes each page under `docs/principles/` a managed file. A project edit to one of them is a decision on each sync that changes the page.
- `docs/principles/index.md` says that a principle page never states a fact about one product. It links to the project page that owns the fact.
- Neighborhood needed one sentence in `docs/principles/fast-first-load.md`: the boot script also sets a color theme. The only way was a kept copy of the whole page.
- No marked region exists in a managed file today.

A **notes block** is a marked block at the end of a managed Markdown page. It holds facts of this project. The exact form:

```markdown
<!-- clutch:project-notes -->

## In this project

The boot script also sets the color theme before the first paint.

<!-- /clutch:project-notes -->
```

The markers follow the form of a kickoff slot, which `tools/check-kickoff-slots.ts` reads as `<!-- kickoff: ... -->`. Only blank lines may follow the end marker. A page holds one block at most.

With CL-569 in place, a notes block is a project edit that sync carries. So this issue is a convention and support in the checks. It needs no new decision logic in `apps/cli/src/sync/`, with one small exception.

The exception: Clutch may add text at the end of a page. A plain three-way merge then sees two additions at the same place, and reports a conflict. So the merge of CL-569 lifts the block out of the project's copy before it merges, and adds it back at the end after.

## Steps

1. Branch `clutch/cl-571-project-notes`.
2. In the merge step of CL-569, take the notes block out of the project's copy, merge the rest, and append the block. A page whose only edit is the block merges with no conflict and asks nothing.
3. A notes block needs no `differences:` entry, because the markers record it. `clutch doctor` lists each managed page that holds a block.
4. Make the docs checks accept the block. `check-sentences`, `check-terms`, `check-docs-file-refs` and `check-docs-claims` check its text as any other text. `check-kickoff-slots` matches only `kickoff:` comments, so it ignores the markers already. Keep it so.
5. In Clutch, a managed page holds no notes block. `check-managed-links` fails a managed page in Clutch that holds one.
6. Say where a project's fact goes:
   - `docs/principles/index.md`: a fact of one product goes in the notes block of the page, or in the project page that the principle page links to.
   - The placement table of `docs/principles/lean-agent-context.md` gets the same row.
   - `docs/contributing/documentation.md` gives the marker form.
7. Extend the tests:
   - `apps/cli/src/sync/decide.test.ts`: a page with only a notes block asks nothing. A page where Clutch adds text at the end keeps the block after the new text.
   - The test of each changed check: a page with a block passes, and a long sentence in the block fails `check-sentences`.

## Files

- `apps/cli/src/sync/run.ts`, or the module of the CL-569 merge
- `apps/cli/src/sync/decide.test.ts`
- `tools/check-managed-links.ts` and `tools/check-managed-links.test.ts`
- `tools/check-sentences.ts`, `tools/check-terms.ts`, `tools/check-docs-file-refs.ts` and `tools/check-docs-claims.ts`, when one of them rejects the markers
- `docs/principles/index.md`, `docs/principles/lean-agent-context.md`
- `docs/contributing/documentation.md`
- `apps/cli/README.md`

## Acceptance criteria

- A project adds a notes block to `docs/principles/fast-first-load.md`. A sync that changes the page keeps the block, writes Clutch's change, and asks nothing.
- A sync where Clutch adds a paragraph at the end of the page keeps the block at the end, after that paragraph.
- `clutch doctor` lists each page with a notes block.
- The docs checks pass on a page with a valid block, and check the text inside it.
- `check-managed-links` fails a managed page in Clutch that holds a block.
- `docs/principles/index.md` names the notes block as a home for a fact of one product.
- `mise exec -- bun run validate` passes.
