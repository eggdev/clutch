# CL-428: Make the implement-models checks grade behavior, so the suite tells models apart

## Goal

The `implement-models` suite gives a different pass count to models that differ in skill. Its first result gave 0 of 3 to Opus and 0 of 3 to Sonnet.

## Context

- The first result is `factory/benchmarks/implement-models/results/2026-11-04-7649c9d.json` (CL-427).
- Each check runs the PR's own test files. Those tests also check wording and formats that the issue does not name:
  - `cl-504-fleet-key`: both models built the `fleet` key and its rules. Both wrote problem paths as `fleet.0.repo`, and the test wants `fleet[0].repo`. Each other test passed (11 of 12).
  - `cl-103-pin-actions`: the test wants the exact text `` `actions/checkout@<sha> # v7` `` and a rule for Docker digests. The issue names neither.
  - `cl-116-release-changeset`: both models missed one rule that the issue names: a range that only touches release outputs, with no changeset deleted, is not a release. This failure is fair.
- A pass or fail for each task hides how close a run came.

## Steps

1. Branch `clutch/cl-428-fair-checks`.
2. For each task, keep the test cases that grade what the issue asks. Run only those with `bun test -t <pattern>`, or swap the task for a cleaner one.
3. Decide with Brendan whether a result also records the passed and total test counts of the check.
4. Prove each check again: it fails at the pin and passes at the PR head.
5. Run the suite again and commit the result.

## Files

- `factory/benchmarks/implement-models/benchmark.md` and `results/`
- `apps/cli/src/bench/` when a result records test counts

## Acceptance criteria

- Each check fails at its pin and passes at its PR head.
- A check fails only for a rule that the issue names.

## Verify

```bash
mise exec -- bun run clutch bench implement-models
```
