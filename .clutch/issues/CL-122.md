# CL-122: Keep pr sync and pr wait right after a hand-finished rebase or a push

## Goal

`pr sync` and `pr wait` act on the commit the checkout has, after a rebase finished by hand and right after a push.

## Context

Two gaps showed up while lane B delivered CL-204 and CL-303 on 2026-10-31:

- `pr sync 104` stopped on a real conflict in `seed.test.ts`. I finished the rebase by hand, so the recorded fork point stayed at the old base. The next `pr sync` rebased `--onto` from that stale point and replayed 19 commits, `main`'s among them.
- `pr ready 103` pushed the done commit, and `pr wait 103` read the PR at once. GitHub still showed the old head with its green checks, so `wait` said "Ready to merge: yes" for a commit that was no longer the head.

## Steps

1. Branch `clutch/cl-122-pr-sync-wait`.
2. In `pr sync`, drop a recorded fork point that the branch no longer contains, and rebase as before.
3. In `pr wait`, when the checkout is on the PR's branch, treat a PR head that differs from the local `HEAD` as pending.

## Files

- `tools/github/branch.ts`, `tools/github/status.ts`, `tools/github/pr.ts`
- `tools/github/lifecycle.test.ts`, `tools/github/project.test.ts`

## Acceptance criteria

- After a hand-finished rebase, `pr sync` replays only the branch's own commits.
- Right after a push, `pr wait` waits for GitHub to show the pushed head.
